## Introducción

Una **proposición** es la unidad mínima de ejecución en el lenguaje. Desde el punto de vista sintáctico, una proposición simple y un bloque (proposición compleja) son completamente equivalentes para el compilador.

Una *proposición simple* es cualquier expresión válida seguida de un punto y coma `;`, lo que indica una acción concreta a realizar.
```c
x = 5;               // Proposición Simple (Asignación válida)
a = b * 3;           // Proposición Simple (Operación matemática)
printf("Hola\n");    // Proposición Simple (Invocación a función)
```

Las *proposiciones inválidas* son sentencias que rompen las reglas sintácticas del lenguaje. Directamente no compilan.
```c
num /+ 4;            // Proposición Inválida (Sintaxis rota)
```

Una *proposición simple inútil* es código que es sintácticamente correcto pero que no genera ningún efecto o cambio de estado en el programa (desperdicio de ciclos).
```c
b + 3;              // Proposición Simple Inútil
```

Una *proposición compleja (Bloque)* es un conjunto de declaraciones y proposiciones agrupadas de manera lógica entre llaves {}. Se comporta ante el compilador como si fuera una única proposición grande.
```c
{
    int x = 4;
    a++;
    putchar(x);
}                       // Proposición Compleja
```

## Estructura de Control

Una **estructura de control** `if` permite bifurcar el flujo de ejecución evaluando una condición lógica. Consta de una línea de control y un cuerpo de ejecución. La sintaxis es la siguiente:
```c
if ( condición ) // Línea de control
    proposición  // Cuerpo
```

Algunas reglas para la estructura del cuerpo son:
- Si el cuerpo tiene una sola línea (proposición simple) se pueden omitir las llaves.
- Si el cuerpo requiere más de una línea es obligatorio agruparlas dentro de un bloque usando llaves `{}`.

Entonces, los siguientes casos son válidos:
```c
int a = ...;
if (a % 2 == 0)
    printf("El número %d es par\n", a);
    
if (a < 0) {
    printf("El número %d es negativo\n", a);
    a = 0;
}
```

>[!TIP] Recomendación de Buenas Prácticas
>Fuera de lo que permita la sintaxis, siempre se recomienda utilizar llaves `{}`, incluso si el cuerpo del `if` contiene una sola línea de código. Esto evita errores lógicos graves al agregar líneas en el futuro.

Una **estructura de control** `else` complementa al if para ejecutar una acción alternativa en caso de que la condición lógica evaluada resulte falsa. Su sintaxis es:
```c
if ( condición )
    proposición1
else
    proposición2
```

Podemos verlo en el siguiente ejemplo, que busca evaluar la paridad:
```c
int num = 35;
if (num % 2 == 0)
    printf("El número %d es par", num);
else
    printf("El número %d es impar", num);
```

Notemos que para limpiar la redundancia, podemos usar el operador condicional ternario `?:` dentro de un único `printf`, variando dinámicamente solo el texto que cambia:
```c
printf("El número %d es %s", num, (num % 2 == 0) ? "par" : "impar");
```

## Anidamientos

Las proposiciones `if` / `if-else` se pueden anidar logrando decisiones múltiples. Cuando metemos un condicional dentro de otro, el flujo del programa evalúa las condiciones en cascada de manera sucesiva.
```c
int cant = 35, suma = 10, x;
if (cant > 0)
    if (suma < 100)
        x = suma / cant;
    else
        puts("Suma incorrecta");
```

Para que se imprima "Suma incorrecta", se tiene que dar la combinación de que `cant > 0` sea verdadero, pero que `suma < 100` sea falso, lo que significa que la suma debe terminar siendo mayor o igual a 100 para que el flujo caiga en esa rama alternativa.

En C, no se utiliza la identación para corresponder los `else` con los `if`. El compilador no mira el espaciado ni los espacios en blanco, por lo que el `else` siempre se va a corresponder con el segundo `if` (el más cercano que tenga arriba en el mismo nivel de bloque). Esto puede generar errores visuales si el código está mal alineado.
```c
if (a % 2 == 0)
    if (b * 2 > a)
        num = a;
else
    num = b;
```

Si queremos cambiar este comportamiento por defecto para que el camino alternativo corresponda al primero, hay que usar llaves de forma obligatoria para aislar el condicional interno y forzar al compilador a emparejar el bloque correctamente:
```c
if (a % 2 == 0) {
    if (b * 2 > a)
        num = a;
} else
    num = b;
```

Para encadenar múltiples condiciones de forma limpia se utiliza la estructura `else if`.
```c
if (num > 0)
    puts("Número positivo");
else if (num < 0)
    puts("Número negativo");
else
    puts("Es cero !!!");
```

>[!INFO] Criterio de Uso
>Ahora que conocemos tanto el `if` como el `?`, tenemos que saber decidir cuándo usar cada uno:
>- Usamos el `?` si queremos devolver uno u otro valor directamente en una expresión.
>- Usamos el `if` cuando queremos ejecutar acciones o bloques de código.

Para imprimir un valor en un `printf` podemos usar el operador ternario de la siguiente forma:
```c
printf("Hay %d libro%s en stock\n", cant, (cant == 1) ? "" : "s");
```

>[!WARNING] ¡Cuidado!
>Recordar que luego del `if()` no se pone punto y coma, sino que se abre la llave del bloque. Si lo hacemos, el compilador NO te va a tirar error de sintaxis (compila igual), pero el `if` se cierra en esa misma línea y el bloque de abajo se ejecuta siempre (un error lógico grave).

Podemos ver esto en el siguiente caso:
```c
if (a > b) { c = 0; }; 
// ERROR: Sobra el punto y coma después de la llave de cierre.

if (a > b); { c = 0; } 
// ERROR: Ese punto y coma después del paréntesis rompe la lógica del if.
```

## Proposición `switch`

La proposición `switch` evalúa una expresión entera y va a ver cuál `case` coincide. Si por ejemplo la expresión coincide con `exp_cte2`, el programa empieza a ejecutar desde ahí para abajo de forma secuencial. Esto es un comportamiento del lenguaje que me puede servir o no dependiendo de lo que busque hacer. Si yo quiero que la ejecución corte en un determinado punto y no siga de largo por los siguientes casos, tengo que usar la instrucción `break`.
```c
switch ( expresión_entera )
{
    case exp_cte1: proposicion1
    case exp_cte2: proposicion2
    case exp_cte3: proposicion3
    case exp_cteN: proposicionN
    default: proposicionX
}
```

Para entenderlo mejor, si tenemos un tipo enumerado para los días de la semana y evaluamos la variable condicional, podemos notar que el siguiente caso no funciona bien porque faltan los `break`. Si la variable `dia` valiera `MAR`, el programa imprimiría "Martes", pero al no encontrar un corte, seguiría ejecutando los comandos de abajo imprimiendo también "Miércoles", "Jueves", hasta llegar al "Inválido" del `default`.
```c
enum tipoDia {LUN, MAR, MIE, JUE, VIE, SAB, DOM};
enum tipoDia dia;

switch(dia)
{
    case LUN: puts("Lunes");
    case MAR: puts("Martes");
    case MIE: puts("Miércoles");
    case JUE: puts("Jueves");
    case VIE: puts("Viernes");
    case SAB: puts("Sábado");
    case DOM: puts("Domingo");
    default:  puts("Inválido");
}
```

Sin embargo, esta propiedad de ejecutar hacia abajo nos puede jugar a favor cuando queremos asociar múltiples casos a una misma acción. Si buscamos imprimir la cantidad de días de un cierto mes numerado, podemos agrupar los meses compartiendo la misma proposición. En este caso, no todos los `case` tienen `break` porque intencionalmente dejamos que los meses de 31 días caigan en cascada hasta el `case 12:` para ejecutar un único `puts`, repitiendo la misma lógica para los meses de 30 días. El `default` al final sirve para atrapar cualquier número de mes que quede por fuera del rango válido de un año.
```c
switch(mes)
{
    case 1: case 3: case 5: case 7:
    case 8:
    case 10:
    case 12:
        puts("31 dias"); break;
    case 4:
    case 6:
    case 9:
    case 11:
        puts("30 dias"); break;
    case 2:
        puts("28 o 29 dias"); break;
    default:
        puts("Numero de mes invalido");
}
```

En otros contextos, el `switch` puede servir para mapear ciertos valores especiales de un conjunto. El siguiente código para un juego de naipes asume que el número de la carta está entre 1 y 13, imprimiendo el nombre correspondiente para el as, el jack, la reina o el rey, y mostrando el valor numérico en el caso `default` para cualquier otra carta intermedia. Si queremos que devuelva que el número es inválido cuando el `int` no está en ese rango de naipes tradicionales, podemos agregar un `if` que contenga al `switch` para validar los límites de la variable antes de evaluarla.
```c
int naipe;
// ...
switch(naipe)
{
    case 1:
        puts("As"); break;
    case 11:
        puts("Jack"); break;
    case 12:
        puts("Reina"); break;
    case 13:
        puts("Rey"); break;
    default:
        printf("%d\n", naipe); break;
}
```

>[!TIP] Regla Sobre Proposiciones de Decisión
>Cuando se opera con números reales hay que utilizar un rango de tolerancia para analizar igualdad o desigualdad. La forma correcta es calcular la diferencia absoluta entre el valor obtenido y el esperado, verificando que sea menor a un margen de error mínimo aceptable. Hay que definir un `epsilon` siempre para estas operaciones. 

Debido a la forma en que las computadoras representan internamente los tipos de datos como `float` o `double`, valores que parecen exactos en base decimal (como hacer `15.1 + 0.2`) sufren de sutiles imprecisiones de redondeo binario al guardarse en memoria, haciendo que una comparación directa de igualdad estricta como `suma == 15.3` devuelva falso.
```c
// Forma incorrecta y propensa a fallos por redondeo:
float suma; // Supongamos que suma termina valiendo 15.1 + 0.2
if (suma == 15.3) // Falso. El literal 15.3 se evalúa además como double aumentándola

//  Forma correcta usando un rango de tolerancia:
#define EPSILON      1E-12

if ( (suma - 15.3) < EPSILON && (15.3 - suma) < EPSILON )
    // El programa interpreta correctamente la igualdad dentro de la tolerancia
```

## Ciclos

El ciclo `while` consta de una línea de control (donde se evalúa la expresión entre paréntesis) y un cuerpo compuesto por la proposición a repetir. Su comportamiento es simple: evalúa la condición y, si es verdadera, ejecuta el cuerpo para luego volver a chequear la línea de control en bucle. Un uso típico es la validación de datos; si una entrada por ejemplo es inválida, la sigue pidiendo repetidamente en el cuerpo hasta que se ingrese un valor válido que rompa la condición.
```c
while ( expresión )
    proposicion // Cuerpo del ciclo
```

Dependiendo de cuándo la condición pase a ser falsa, un ciclo `while` puede ejecutarse nunca (si la condición da falso de entrada), un número finito de veces, o infinitamente. Por ahora, no nos sirve que corra el ciclo infinitamente, ya lo vamos a ver más adelante (próximos años). Asimismo, para mantener un flujo estructurado y limpio, no conviene acostumbrarse a usar `break` para forzar la salida de los ciclos de forma artificial.

Un ejemplo práctico es este programa que lee caracteres de la entrada estándar y los procesa uno a uno hasta alcanzar el final del archivo. El bucle evalúa la asignación en su línea de control y, si el carácter es una letra minúscula, le resta el `DELTA` numérico correspondiente para convertirla y pasar la letra a mayúscula antes de imprimirla con `putchar()`.
```c
#include <stdio.h>
#define DELTA ('a' - 'A')

int main(void)
{
    int c;

    while ( (c=getchar()) != EOF)
    {
        if (c >= 'a' && c <= 'z')
            c -= DELTA;
        putchar(c);
    }
    return 0;
}
```

Otro caso de aplicación directa es el conteo de ocurrencias durante la lectura de datos. El siguiente código utiliza la misma estructura de control para evaluar la entrada carácter por carácter y, mediante una condición interna, incrementa un contador cada vez que detecta un espacio en blanco, imprimiendo el total acumulado al finalizar el ciclo.
```c
#include <stdio.h>
#define SPACE ' '

int main(void)
{
    int c, space = 0;

    while ( (c=getchar()) != EOF)
        if (c == SPACE)
            space++;

    printf("Blancos: %d\n", space);
    return 0;
}
```

El ciclo `for` no es igual al `while`, ya que cuenta con tres expresiones dentro de su línea de control que están separadas por puntos y comas.
- `expresion1`: se evalúa una sola vez al inicio de todo el ciclo. 
- `expresion2`: condición que se evalúa en cada iteración y marca el final del ciclo si da falso.
- `expresion3`: se evalúa al final de cada iteración, justo después de ejecutar el cuerpo del ciclo.
```c
for ( expresion1; expresion2; expresion3)
    proposicion
```

En general, `expresion1` funciona como una asignación inicial, `expresion2` es una expresión relacional y `expresion3` se encarga de la actualización de alguna variable contadora. Por ejemplo, para imprimir la tabla del 3 usamos esta estructura de forma muy limpia. Como dijimos que las expresiones son opcionales, omitirlas genera casos que siguen siendo válidos para el compilador. Si dejamos vacía la del medio, el programa lo interpreta de manera equivalente a poner un 1 (verdadero), generando un bucle infinito que en esta materia no tiene tanto sentido.
```c
int a;
for ( a = 0 ; a < 10; a++)
    printf("3 * %d = %d\n", a, a * 3);
```

>[!INFO] Equivalencia
>Muchas veces, usar `for` o `while` son equivalentes en funcionalidad. Cualquier ciclo `for` estándar puede reescribirse dejando la inicialización afuera, la condición en el paréntesis del `while` y la actualización al final de las proposiciones del cuerpo.

La diferencia principal entre el ciclo `for` vs el ciclo `while` es conceptual: en el `for`, toda la información para saber cuántas veces se ejecuta el cuerpo está concentrada en la propia línea de control, lo que hace el código mucho más legible. Además, el contador que creamos al principio como `for (int a = 0; ...)` es un contador interno cuyo alcance se limita al ciclo; si luego intentamos llamarlo por fuera, no nos trae nada y arroja un error de compilación.

Es muy importante cuidar las buenas prácticas de diseño al programar estos bucles. El siguiente caso representa un pésimo estilo de programación que debe evitarse: alterar manualmente la variable de control del ciclo (como hacer `i = i - 1;`) dentro del cuerpo para forzar un comportamiento altera la lógica natural del `for` y vuelve el flujo ilegible y propenso a errores.
```c
// PÉSIMO ESTILO: Modificar el contador adentro del cuerpo
for (i = 0; i < n; i++)
{
    num = getint("");
    if (num < 0)
        i = i - 1; // Nunca alterar el índice manualmente acá
}
```

El ciclo `do-while` invierte el orden tradicional de los bucles: primero ejecuta el cuerpo de la proposición y recién después pasa por la línea de control para evaluar la expresión condicional. A diferencia del `while` común, primero ejecuta en vez de preguntar si se cumple mi expresión. Esto garantiza que el bloque de código de adentro se va a correr por lo menos una vez, sin importar si la condición es verdadera o falsa desde el principio.
```c
do
    proposicion // Cuerpo del ciclo
while ( expresión );
```

Esta particularidad sirve para ahorrar código en situaciones comunes como la interacción con el usuario o menús interactivos, donde siempre se necesita mostrar el mensaje inicial antes de poder evaluar la respuesta. 
```c
do
    puts("Pulse S para salir del ciclo.");
while ( (c=getchar()) != EOF && c != 'S' && c != 's' );
```

Ahora, podemos resumir un criterio claro de cuándo elegir cada una según lo que demande nuestro problema: 
- `for`: para una cantidad exacta $n$ de ciclos (cuando conocemos de antemano el número de iteraciones).
- `while`: para una cantidad de $0$ o más ciclos (cuando la condición puede ser falsa de entrada y no queremos ejecutar nada).
- `do-while`: para una cantidad de $1$ o más ciclos, asegurando esa primera iteración obligatoria.

La sentencia `continue` interrumpe la iteración actual y lleva el flujo directamente al final del ciclo para evaluar la siguiente. Su comportamiento exacto varía según la estructura que estemos usando: en un ciclo `for`, salta de inmediato a la evaluación de la expresión de actualización (`exp3`); en un ciclo `while`, salta directo a la línea de control para reevaluar la condición; y en un ciclo `do-while`, se dirige directamente a la evaluación de la expresión condicional al pie del bloque.

Para que tenga sentido lógico y no rompa el programa interrumpiendo todas las iteraciones de manera incondicional, la sentencia `continue` debería estar dentro de un `if`. De este modo, el salto solo se produce si se cumple una condición específica. De todas formas, en línea con las buenas prácticas de la cátedra para mantener un flujo estructurado y limpio, no lo vamos a usar por ahora.

## Ingreso con Centinela

El **ingreso con centinela** es un patrón donde se piden valores continuamente hasta recibir un dato específico (el centinela) que marca el final de la lectura. Una primera aproximación usa un bucle infinito `while (1)` que pide datos y sale mediante un `break` apenas detecta el cero. Sin embargo, para no tomar el vicio de usar el `break`, podemos estructurarlo con un `do-while`. De esta forma, el programa solicita el dato en el cuerpo, procesa el valor únicamente si es válido (distinto de cero) y evalúa la condición de permanencia al final.
```c
// Alternativa estructurada sin vicios de break
do
{
    value = getint("Ingrese un dato (0 = fin)");
    if (value != 0)
        processData(value);
}
while (value != 0);
```

Podemos ver otro ejemplo de procesamiento de caracteres:
```c
int a, digit;
while ((a=getchar()) != EOF)
    digit = ( a >= '0' && a <= '9' );

printf("%s dígito\n", digit ? "Hubo" : "No hubo");
```

## Salto `goto`

El **salto `goto`** es una estructura de control que rompe el flujo secuencial del programa saltando de una función a otra o moviéndose hacia una etiqueta específica dentro de la función. Su sintaxis básica requiere declarar un punto de destino mediante un identificador seguido de dos puntos:
```c
goto rótulo;
...
...
rótulo: proposicion;
```

>A nivel de diseño de software y buenas prácticas, se usa SÓLO para manejar casos de excepciones y manejo de errores de forma muy puntual. Siguiendo el criterio metodológico adoptado en esta materia para garantizar un código estructurado y claro, no lo vamos a necesitar.

## Características Deseables del Software 

Las **características deseables del software** definen los atributos esenciales para que un desarrollo se considere de calidad:
- **Que funcione correctamente**: El programa debe cumplir con su objetivo principal y resolver de manera precisa el problema para el cual fue diseñado.
- **Que utilice algoritmos eficientes**: Debe optimizar el uso de los recursos del sistema (como tiempo de procesamiento y memoria) al ejecutar sus tareas.
- **Que sea portable**: Esto significa que el código posee la propiedad de poder ser ejecutado en distintos entornos o sistemas operativos sin requerir modificaciones estructurales complejas.
- **Que se pueda adaptar a distintas necesidades**: Debe ofrecer la flexibilidad suficiente para amoldarse a nuevos requerimientos, cambios en el entorno de aplicación o necesidades específicas del usuario.
