## Algoritmo

Un **algoritmo** es una secuencia finita de pasos diseñada para resolver un problema determinado. En el ámbito de las ciencias de la computación, se le imponen condiciones adicionales para asegurar que sea apto para ser ejecutado por una computadora.

Para cumplir con su propósito, un algoritmo debe ser:
- **Simple y no ambiguo**
- **Efectivo**
- **Finito**

Al momento de elegir o evaluar un algoritmo, entran en juego tres criterios fundamentales:
- **Correctitud**
- **Claridad**
- **Eficiencia**

De estos factores, la **claridad** y la **eficiencia** se posicionan como los más importantes, siendo aspectos críticos y determinantes a la hora de corregir los exámenes.

## Funciones

Una **función** es un conjunto de proposiciones identificadas por un nombre que cumplen un objetivo común.
```c
tipoDeRetorno nombreFuncion (tipoPar par1, ..., tipoPar parN) {
    /* Proposiciones */
}
```

Donde:
- **Tipo de retorno:** Indica el tipo del valor que devuelve la función. Si no se especifica nada explícitamente, C lo asume por defecto como `int`.
- **Parámetros formales:** Son las variables declaradas en la cabecera de la función que reciben los valores cuando esta es invocada.

Al invocar una función (`nombreFuncion(par1, ...);` o `nombreFuncion();`), los parámetros actuales deben coincidir en tipo, cantidad y orden con los formales. Si no coinciden exactamente, el lenguaje realiza una conversión automática o promoción implícita:
```c
int max(double x, double y) {
    return x > y ? x : y; // El valor double se convierte implícitamente a int
}
```

Al invocar una función, se utiliza el **stack de memoria** para almacenar variables locales, parámetros, datos temporales y la dirección de retorno; esta estructura permite realizar llamadas anidadas sin sobrescribir información. Para concluir, la sentencia `return` realiza un salto incondicional que libera el _frame_ del _stack_ y devuelve el control al módulo llamante. Si una función especifica un tipo de retorno pero omite el valor devuelto (o ejecuta un `return;` vacío), la variable receptora tomará un valor basura indeterminado (por ejemplo, `p = -1075190380`).

Tomemos el siguiente caso, donde se recibe un número entero no negativo y calcula la suma de sus dígitos con `% 10` y `/= 10`:
```c
unsigned sumDigits(unsigned number) {
    unsigned sum = 0;

    while (number) {
        sum += number % 10;
        number /= 10;
    }

    return sum;
}
```

## Pasaje de Parámetros

En lenguaje C, el **pasaje de parámetros** se realiza siempre estrictamente por valor. Esto significa que, al llamar a una función y pasarle argumentos, la función receptora recibe copias de los datos originales y no las variables en sí.
```c
int nro = 5;
func(nro); // 'num' en la función recibe una copia con el valor 5
```

Por este motivo, las modificaciones que se hagan sobre los parámetros dentro del cuerpo de la función afectan únicamente a sus copias locales. Las variables enviadas desde el contexto llamante permanecen inalteradas, ya que están guardadas en posiciones de memoria completamente distintas.
```c
void sample(int a, int b) {
    a *= 2; // Modifica únicamente la copia local de 'a'
    b++;    // Modifica únicamente la copia local de 'b'
    return;
}

int main(void) {
    int a = 2, b = 4;
    sample(a, b); // Los valores de 'a' y 'b' en main siguen siendo 2 y 4
    return 0;
}
```

La **declaración de prototipos** le permite al compilador conocer la firma de una función antes de su invocación. La sintaxis general consiste en especificar el tipo de retorno, el nombre de la función y la lista de parámetros formales entre paréntesis.
```c
tipoRetorno nombreFuncion(listaDeParametros);

float discountCalc(float price, int qty);

int main(void) {
    float discount;
    discount = discountCalc(12.5F, 10); // 12.5F y 10 son argumentos / parámetros actuales
    return 0;
}
```

En la lista de parámetros formales del prototipo podríamos incluir únicamente el tipo de dato, dado que al compilador solo le interesa verificar la cantidad y el tipo de los argumentos recibidos. No obstante, se suele agregar también el nombre de las variables para mejorar la legibilidad del código.

>[!INFO] ANSI C
>Según la norma ANSI C, es necesario prototipar todas las funciones que se vayan a utilizar. En el desarrollo de bibliotecas de funciones, la estructura se divide en un archivo de encabezado (.h) para los prototipos y un archivo fuente (.c) para la implementación concreta.

```c
/* Archivo math.c */
long double square(long double nbr) {
    return nbr * nbr;
}

/* Archivo prog.c */
int main(void) {
    int value = 5;
    value = square(value);
    printf("Cuadrado = %d\n", value);
    return 0;
}
```

Para compilar múltiples archivos que forman parte del mismo programa, se pueden pasar juntos al compilador. Por ejemplo, ejecutando `gcc -o prueba prog.c math.c` se genera un único ejecutable enlazando el programa principal con el módulo implementado.

El calificador `static` aplicado a una función limita su alcance al propio archivo de código donde fue definida. Al utilizarlo, el símbolo de la función no se exporta ni se le entrega al enlazador (o _linkeditor_), lo que la vuelve completamente invisible e inaccesible para los demás módulos del programa.
```c
static tipoDeRetorno nombreFuncion(tipoPar par1, ..., tipoPar parN) {
    /* Proposiciones */
}
```

Esta característica resulta ideal para el diseño de bibliotecas, ya que permite encapsular funciones auxiliares u ocultar detalles de implementación interna sin riesgo de generar conflictos de nombres con otros archivos fuente.

## Reglas sobre Funcions

Cada función debe realizar una única tarea bien definida, lo que permite que su nombre sea significativo y surja de manera natural. Si resulta difícil nombrar una función, suele ser un síntoma de que o bien no está haciendo nada relevante, o bien intenta abarcar demasiadas responsabilidades a la vez.

Asimismo, todo prototipo debe ir precedido por un prólogo o comentario que detalle con claridad qué hace la función y cómo debe utilizarse. Es fundamental prestar atención a los algoritmos ya existentes creados por expertos y no quedarse únicamente con la primera solución propuesta, evaluando siempre distintas alternativas antes de implementar.
```c
/*
** discountCalc: calcula el monto final aplicando un descuento sobre el precio.
** Recibe el precio base y la cantidad de unidades.
** Retorna el valor total abonar.
*/
float discountCalc(float price, int qty);
```

Por otro lado, es clave aplicar principios de programación defensiva sin asumir jamás que un escenario de error nunca va a ocurrir (siguiendo la Ley de Murphy). Finalmente, resulta imprescindible realizar exhaustivas pruebas de código sobre el programa, utilizando más adelante criterios sistemáticos para validarlo.

## Modularización

La **modularización** consiste en diseñar un programa dividiéndolo en funciones bajo criterios bien definidos para evitar la repetición de código, en lugar de acumular toda la lógica dentro de la función `main`. Este proceso de diseño debe realizarse antes de empezar a programar, ya que estructurar todo en el `main` y luego extraer bloques a funciones no se considera una verdadera modularización.

Tampoco es recomendable postergar las pruebas hasta tener el programa completamente terminado. Es mejor ir testeando cada módulo a medida que se desarrolla. Para abordar este proceso existen dos enfoques principales: la metodología _Top-Down_ (programar de arriba hacia abajo, definiendo primero la lógica principal) y la metodología _Bottom-Up_ (programar de abajo hacia arriba, construyendo primero los componentes individuales).

La elección de la estrategia depende del criterio del desarrollador. El enfoque _Bottom-Up_ resulta muy conveniente para probar piezas de código de forma aislada a medida que se crean, además de ser útil cuando no se tiene del todo claro cuántos parámetros va a necesitar una función. Sin embargo, su desventaja es que, al avanzar en la integración, es posible tener que modificar los módulos de menor nivel previamente creados.

## Macros

Una **macro de sustitución simple** o **definición de constante simbólica** le permite al preprocesador hacer una sustitución directa de texto en el código fuente antes de la compilación, descartando espacios en blanco al inicio y al final. Esto facilita enormemente el mantenimiento del código a lo largo del tiempo, ya que actualizar un valor centralizado repercute en todas sus referencias.
```c
#define IDENTIFICADOR texto_de_Reemplazo

#define SEGS_X_HORA 3600
#define DIR_DATOS   "c:\\personal\\"
#define FOR_EVER    for ( ; ; )

// Durante el preprocesado, PI se reemplaza textualmente por 3.14
#define PI 3.14
printf("El valor de PI es %g\n", PI);
```

C ofrece además constantes simbólicas predefinidas que proveen información del contexto de compilación. Entre ellas destacan `__LINE__` para el número de línea actual, `__FILE__` para el nombre del archivo fuente, `__DATE__` y `__TIME__` para la fecha y hora de compilación, y `__func__` para obtener el nombre de la función actual.
```c
printf("Compilado el %s en la línea %d\n", __DATE__, __LINE__);
```

También es posible definir **macros con parámetros** que reciben argumentos y realizan un reemplazo literal en el código. Sin embargo, al ser una sustitución textual sin evaluación previa, es indispensable encerrar tanto cada parámetro como la expresión completa entre paréntesis; de lo contrario, la precedencia de operadores puede alterar el resultado algebraico u operaciones matemáticas posteriores.
```c
// Incorrecto: al invocar AREA_CIRC(radioIni + delta) se expande sin prioridad
#define AREA_CIRC(r) PI * r * r

// Correcto: paréntesis en cada argumento y en el conjunto de la expresión
#define AREA_CIRC(r) (PI * (r) * (r))

int main(void) {
    int radio = 3;
    double area = 1.0 / AREA_CIRC(radio);
    return 0;
}
```

>[!WARNING] Efectos Secundarios
>Es importante tener cuidado con los efectos secundarios al usar operadores de incremento o decremento como argumentos en macros. Si una macro evalúa más de una vez a su parámetro, provocará múltiples ejecuciones no deseadas sobre esa misma variable en lugar de una sola.

```c
#define MAYOR(n1, n2) (((n1) > (n2)) ? (n1) : (n2))

int main(void) {
    int a = 9, b = 8, mayor;
    // CUIDADO: '++a' se evalúa dos veces al expandirse la macro
    mayor = MAYOR(++a, b); 
    return 0;
}
```

Si en lugar de devolver una expresión se busca almacenar el resultado en un tercer parámetro pasado a la macro, no se requiere retornar un valor de forma explícita. En este escenario sí resulta válido emplear estructuras de control como `if` para asignar directamente el resultado según la condición evaluada.
```c
// Asignación directa mediante operador ternario
#define MAYOR(n1, n2, r) (r = (n1) > (n2) ? (n1) : (n2))

// O bien utilizando una estructura condicional
#define MAYOR(n1, n2, r) if ((n1) > (n2)) r = n1; else r = n2;
```

Existen operadores específicos para el trabajo con macros que no suelen ser de uso frecuente. El operador `#` (_stringification_) permite transformar el parámetro recibido en una cadena de texto (_string_), resultando muy útil para formatear o imprimir literales directamente.
```c
#define Saludo(nombre) printf("Hola " #nombre)

Saludo(Ana);  // Imprime "Hola Ana"
Saludo(Juan); // Imprime "Hola Juan"
```

Por otro lado, para eliminar la definición de una macro se utiliza la directiva `#undef`. A partir del punto en que se incluye esta instrucción, el preprocesador deja de reemplazar las apariciones de ese identificador en el código fuente.
```c
#undef IDENTIFICADOR
```

Las macros también pueden aceptar una cantidad variable de argumentos utilizando puntos suspensivos (`...`) en su definición. En el cuerpo de la macro, estos parámetros adicionales se capturan y reemplazan mediante el identificador especial `__VA_ARGS__`, lo cual resulta de gran utilidad para implementar sistemas o funciones personalizadas de manejo de errores.
```c
#define name(fixed_args, ...)

// Ejemplo para simplificar llamadas a printf o manejo de errores
#define imprimir(fmt, ...) printf(fmt, __VA_ARGS__)
```

Para garantizarlas buenas prácticas y evitar errores comunes al trabajar con macros en C, se deben seguir reglas fundamentales de diseño. 
- Los nombres de las macros deben escribirse siempre en mayúsculas para diferenciarlas a simple vista de las funciones comunes.
- Envolver entre paréntesis cada una de las ocurrencias de los argumentos dentro de la definición de la macro. 
- Cuando la macro incluya operaciones matemáticas o expresiones compuestas, se debe encerrar la totalidad del texto reemplazado entre paréntesis para preservar la precedencia de operadores.

## Compilación Condicional

La **compilación condicional** le permite al preprocesador incluir o descartar bloques de código antes de la etapa de compilación, según si un identificador está definido o no. Su sintaxis básica utiliza `#ifdef`, `#else` y `#endif`.

```c
#ifdef IDENTIFICADOR
    /* Código si está definido */
#else
    /* Código si no está definido */
#endif
```

Un caso de uso práctico es la ejecución de comandos del sistema operativo, como la limpieza de pantalla. Como ANSI C no provee una función nativa para esto, se puede definir la llamada adecuada según la plataforma.
```c
#ifdef WIN32
    #define CLR_SCRN system("cls");
#else
    #define CLR_SCRN system("clear");
#endif
```

También resulta muy útil para habilitar o deshabilitar impresiones de _debugging_. Para evitar modificar el código fuente constantemente agregando o quitando `#define DEBUG`, es posible definir constantes simbólicas directamente desde la consola al compilar con la opción `-D` de `gcc`.
```c
#include <stdio.h>

int main(void) {
#ifdef DEBUG
    printf("Debug mode\n");
#else
    printf("Release mode\n");
#endif
    return 0;
}
```

```bash
# Definición de banderas desde la terminal
gcc pgm.c -DDEBUG -o debug
gcc pgm.c -o release
```

Es importante recordar que estas condiciones no se evalúan en tiempo de ejecución, sino en tiempo de preprocesado. Otro uso fundamental de la compilación condicional es la prevención de la doble inclusión de archivos de cabecera (`.h`).

Si un archivo `f1.h` incluye a `f2.h`, y luego `main.c` incluye a ambos, el contenido de `f2.h` se duplicaría provocando errores de compilación por redefinición de símbolos.
```c
/* Sin guardas: f2.h se procesa dos veces en main.c */
/* f1.h */
#include "f2.h"

/* main.c */
#include "f1.h"
#include "f2.h" // Provoca declaraciones duplicadas
```

Este problema se soluciona rodeando el contenido de los archivos `.h` con guardas de inclusión (_include guards_) usando `#ifndef`. Así, la primera vez que se procesa el archivo se define la constante simbólica y las inclusiones posteriores son ignoradas.
```c
/* Con guardas en f2.h */
#ifndef _F2_H_
#define _F2_H_

int f2(void);
int var_global;

#endif
```

## Biblioteca Estándar

La biblioteca estándar de C reúne funciones altamente testeadas e implementadas de forma muy eficiente. Siempre que un ejercicio no prohíba explícitamente su uso, se deben aprovechar en lugar de reinventar la rueda.

Dentro de `<stdio.h>` encontramos funciones fundamentales para la entrada y salida de datos:
- `getchar()` y `putchar(c)`: Leen y escriben un caracter individual.
- `ungetc(c, stream)`: Devuelve un caracter al buffer de entrada para que vuelva a ser leído en la siguiente operación.
- `feof(stream)` y `ferror(stream)`: Retornan un valor distinto de 0 (verdadero) si se alcanzó el fin de archivo o si ocurrió un error de lectura, respectivamente.
- `clearerr(stream)` y `perror(s)`: Permiten limpiar los indicadores de error o imprimir un mensaje descriptivo del fallo detectado.

```c
// Ejemplo de uso de ungetc
int c = getchar(); // Lee 'h'
int d = getchar(); // Lee 'o'
ungetc('x', stdin); // Devuelve 'x' al buffer de entrada

c = getchar(); // Ahora lee 'x'
d = getchar(); // Lee 'l'
```

Por otro lado, la cabecera `<stdbool.h>` incorpora el tipo booleano `bool` junto con sus valores de verdad `true` y `false`, los cuales internamente se definen mediante enumeraciones o macros (`#define`).

```c
bool b = true;
if (b) {
    /* Lógica condicional */
}
```

En la biblioteca `<stdlib.h>` se incluyen funciones de utilidad general como `abs()` y `labs()` para obtener el valor absoluto de enteros y enteros largos. Para la generación de números pseudoaleatorios en el rango `[0, RAND_MAX]` se utiliza `rand()`, mientras que `srand()` permite fijar la semilla inicial. Funciones como `abort()` y `exit()` se descartan por el momento, destacando que `exit()` finaliza la ejecución del programa actuando como un salto directo al `return` del `main`.

Por su parte, `<ctype.h>` ofrece funciones de clasificación de caracteres que evalúan una condición y devuelven `0` si es falsa o un valor distinto de `0` si es verdadera:
- `islower(c)` e `isupper(c)`: Evalúan si el caracter es minúscula o mayúscula.
- `isalpha(c)` y `isdigit(c)`: Verifican si es una letra alfabética o un dígito numérico (entre `'0'` y `'9'`).
- `isxdigit(c)` e `isalnum(c)`: Comprueban si es un dígito hexadecimal o un caracter alfanumérico.
- `isprint(c)`, `ispunct(c)` e `iscntrl(c)`: Determinan si es imprimible, signo de puntuación o un caracter de control.
- `isspace(c)`: Evalúa si es un espacio en blanco (`' '`, `'\n'`, `'\t'`, etc.).

Para la transformación de caracteres, la misma biblioteca incluye `toupper(c)` y `tolower(c)`, las cuales retornan el caracter convertido a mayúscula o minúscula según corresponda.
```c
int c = 'A';
c = tolower(c); // Convierte 'A' a 'a'
putchar(c);     // Imprime 'a'
```

>[!INFO] Asignación
>Invocaciones sencillas como las previas no modifican la variable original pasándole una copia, sino que devuelven un nuevo valor. Por eso, es obligatorio asignar el resultado de vuelta (`c = tolower(c)`), ya que de lo contrario se terminaría imprimiendo el valor previo de `c`.

Para procesar caracteres individualmente desde un flujo de texto, conviene utilizar variables de tipo `int` en lugar de `char`. Esto se debe a que `EOF` es un valor entero negativo (usualmente `-1`) que un `unsigned char` no puede representar adecuadamente, aunque para variables aisladas que no interactúan con `EOF` ambos tipos funcionan de manera equivalente.

```c
#include <stdio.h>
#include <ctype.h>

int main(void) {
    int c;
    
    // Lee hasta llegar al final del archivo o entrada
    while ((c = getchar()) != EOF) {
        if (!isspace(c)) {
            putchar(toupper(c));
        }
    }
    return 0;
}
```

Para funciones matemáticas avanzadas como las de `<math.h>`, es necesario compilar incluyendo la bandera `-lm` (`gcc pgm.c -lm`). Cuando estas funciones reciben argumentos fuera de su dominio o generan resultados fuera del rango representable (como `sqrt(-9)` o `pow()` con exponente muy alto), recurren a la biblioteca `<errno.h>`.

La variable global externa `errno` se utiliza para registrar estos fallos matemáticos. Cuando ocurre un problema, la función actualiza `errno` fijando un valor distinto de cero, dejando definidos códigos específicos como `EDOM` (error de dominio) y `ERANGE` (error de rango).

Para validar correctamente la ocurrencia de un error, es indispensable reiniciar manualmente `errno = 0` antes de ejecutar la operación, ya que de lo contrario conservará el estado de un fallo previo durante las siguientes iteraciones.
```c
#include <stdio.h>
#include <math.h>
#include <errno.h>

int main(void) {
    double resp;
    
    errno = 0; // Se resetea el indicador antes de la operación
    resp = pow(-2, 0.5);
    
    if (errno == 0) {
        printf("resp vale %f\n", resp);
    } else {
        perror("Potencia:"); // Imprime el mensaje estándar de error en inglés
    }
    return 0;
}
```

Al utilizar la función `perror("mensaje")`, el sistema imprime la cadena enviada por parámetro junto con la descripción estándar del error en inglés asociada al valor actual de `errno`.

## Assert

La macro `assert`, definida en la cabecera `<assert.h>`, sirve para verificar suposiciones o condiciones lógicas durante la etapa de desarrollo. Recibe como argumento una expresión entera y evalúa si su resultado es verdadero o falso.
```c
#include <assert.h>

void assert(int expresion);
```

Si la expresión evaluada resulta ser falsa (`0`), la macro imprime un mensaje de error detallado a través del flujo de salida de errores estándar (`stderr`) indicando la condición fallida, el nombre del archivo fuente y el número de línea. Inmediatamente después, aborta de formaabrupta la ejecución del programa.
```c
// Si 'a' vale -3, la expresión (a > 0) es falsa y el programa aborta
int a = -3;
assert(a > 0); 
// Imprime en stderr: Assertion failed: a > 0, file main.c, line 12
```

Por esta razón, `assert` debe utilizarse de manera exclusiva durante la fase de _debugging_ o prueba de funciones para validar invariantes y pruebas unitarias. Jamás debe incluirse en la versión final de producción, ya que interrumpiría la ejecución normal frente a entradas inesperadas del usuario.
```c
#include <stdio.h>
#include <assert.h>

int main(void) {
    int a = 1, b = 3;

    // Pruebas de validación de lógica
    assert(min(a, b) == a);
    assert(max(a, b) == b);
    assert(equals(a, b) == 0);
    assert(compare(a, b) < 0);
    assert(equals(a, a) == 1);
    assert(compare(b, a) > 0);
    assert(compare(a, a) == 0);

    puts("No se encontraron errores");
    return 0;
}
```

## Características de las Variables

Las variables en C poseen diferentes características según su tipo de almacenamiento y alcance (_scope_):
- **Variables automáticas:** Se crean dinámicamente en la pila (_stack_) al momento de ser necesitadas (por ejemplo, dentro de una función) y se destruyen al finalizar su bloque.
- **Variables estáticas (`static`):** No se guardan en el _stack_, sino que se asignan en memoria al inicio de la ejecución y se inicializan automáticamente en cero.
- **Variables externas (`extern`):** Permiten acceder a una variable global que está definida en otro archivo fuente o en otro punto del programa.

```c
#include <stdio.h>
#define MULT 3

int main(void) {
    // 'top' y 'num' son variables automáticas creadas en el stack de main
    int top, num; 
    
    top = getint("Ingrese el tope:") / MULT;
    for (num = 1; num <= top; num++) {
        printf("%d\n", num * MULT);
    }
    return 0;
}
```

El comportamiento de la palabra clave `static` varía según el contexto donde se declare la variable. Si se define fuera de cualquier función, la variable es visible dentro de todo ese archivo `.c`, pero permanece oculta para los demás módulos.

```c
static int a; // Variable estática global: visible solo en este archivo .c
```

En cambio, si `static` se declara dentro de una función, la variable mantiene su estado y conserva su valor entre sucesivas invocaciones a lo largo de toda la ejecución del programa.

```c
int funcion(int valor) {
    // Se inicializa en 0 al arrancar el programa y conserva su estado
    static int acum = 0; 
    acum += valor; // Si se llama con 5 la 1° vez da 5, y la 2° vez acumulando otro 5 dará 10
    return acum;
}
```

Por su parte, la palabra clave `extern` le avisa al compilador que la variable global ya existe y está definida en otra parte (como en otro archivo `.c`). Si se declara `extern` por fuera de las funciones, quedará disponible globalmente en ese archivo; si se declara dentro de una función, solo esa función concreta podrá acceder a ella.
```c
/* Archivo 1 */
int gl; // Definición de la variable global
static int c; // Variable privada de este archivo

void f1(void) {
    printf("%d %d\n", gl, c);
    c++;
}

/* Archivo 2 */
#include <stdio.h>
void f2(void);

int main(void) {
    extern int gl; // Declaración: le avisa a main que 'gl' está definida en otro archivo
    gl = 10;       // Funciona correctamente sin error
    f1();
    return 0;
}

void f2(void) {
    int count;
    // Da error de compilación si 'gl' no fue declarada extern dentro de f2 o fuera de las funciones
    printf("%d %d\n", gl, count); 
}
```

Un ejemplo muy claro del uso de `static` fuera de las funciones es la preservación de estado interno para un conjunto de algoritmos, como la generación de números pseudoaleatorios. Al declarar la variable compartida como privada del módulo, las funciones pueden modificarla sin exponerla al resto del sistema.
```c
// Variable privada del módulo para conservar el estado
static int lastValue; 

void srand(int seed) {
    lastValue = seed;
}

int rand(void) {
    /* Calcula el nuevo valor en base al anterior */
    lastValue = (lastValue * 1103515245 + 12345) & 0x7fffffff;
    return lastValue;
}
```

## Construcción de una Biblioteca

Una biblioteca es un conjunto de funciones con un propósito definido y coherente. Su diseño exige mantener criterios unificados, por ejemplo, utilizando un mismo idioma para nombrar todas sus funciones y variables.

Al diseñarla se busca cumplir con los siguientes criterios clave:
- **Unificada:** Mantiene consistencia en nombres, parámetros y estilo de codificación.
- **Simple y suficiente:** Ofrece una interfaz concisa pero completa para cubrir las necesidades del usuario.
- **General y estable:** Se adapta a múltiples casos de uso sin requiring cambiar la interfaz ante modificaciones internas.

La interfaz (el contrato o API) se define en el archivo de cabecera `.h`. Si cambia la implementación en el archivo `.c`, solo se requiere volver a relinkeditación (_re-linkedit_) el programa. En cambio, alterar el archivo `.h` fuerza al usuario a re-codificar su programa fuente para mantener la compatibilidad. Los únicos cambios admisibles en un `.h` sin romper el código existente consisten en agregar nuevas funciones.
```c
// random.h - Interfaz de la biblioteca de aleatorios
#ifndef RANDOM_H
#define RANDOM_H

void randomize(void);
double randNormalize(void);
int randInt(int left, int right);
double randReal(double left, double right);

#endif
```

Para implementar estas funciones, es común que unas se apoyen en otras dentro del mismo módulo. Por ejemplo, `randNormalize()` genera un punto flotante en el intervalo $[0, 1)$ dividiendo por `RAND_MAX + 1` para excluir el extremo superior.

```c
// random.c - Implementación
#include "random.h"
#include <stdlib.h>
#include <time.h>

// Inicializa la semilla utilizando la hora actual
void randomize(void) {
    srand((unsigned int) time(NULL));
}

// Retorna un número real pseudoaleatorio en el intervalo [0, 1)
double randNormalize(void) {
    return rand() / ((double) RAND_MAX + 1);
}

// Retorna un entero en el intervalo [left, right]
int randInt(int left, int right) {
    // Aunque rand() % (right - left + 1) + left es matemáticamente correcto,
    // usar randNormalize() ofrece una mejor distribución estadística.
    return (int)(randNormalize() * (right - left + 1) + left);
}

// Retorna un número real en el intervalo [left, right)
double randReal(double left, double right) {
    return randNormalize() * (right - left) + left;
}
```

Antes de distribuir una biblioteca, es fundamental verificarla con un programa de prueba e incluir dicho programa como parte de la documentación oficial. Usar `assert` ayuda a validar invariantes y límites esperados durante la fase de testing.
```c
#include <stdio.h>
#include <assert.h>
#include "random.h"

int main(void) {
    randomize();

    // Verificación de rango para randInt
    for (int i = -10, j = -10; j < 100; j++) {
        int n = randInt(i, j);
        assert(n >= i && n <= j);

        n = randInt(j, i);
        assert(n >= i && n <= j);
    }

    puts("Pruebas básicas finalizadas con éxito");
    return 0;
}
```

## Separación de Backend y Frontend

El principio de diseño de software exige una clara separación de responsabilidades entre el **frontend** y el **backend**. Mientras que el frontend (cliente) se encarga exclusivamente de la interfaz y la presentación visual para interactuar con la persona, el backend (servidor/bibliotecas) procesa la lógica de negocio y los cálculos, respondiendo únicamente a llamadas de otras funciones sin interactuar jamás directamente con el usuario final.

Esta arquitectura desacoplada permite que la conexión entre ambas capas pueda darse en el mismo ejecutable o incluso a distancia a través de la red. En la práctica, la distinción radica en sus destinatarios: para el frontend, el usuario es una persona; para el backend, el usuario es otra función.
- Responsabilidades de frontend:
    - Menú de opciones y ventanas desplegables.
    - Pedir la jugada o entrada de datos al usuario.
    - Mostrar el tablero, gráficos o resultados procesados.
- Responsabilidades de backend:
    - Validar las jugadas o la regla de negocio.
    - Almacenar o restaurar el estado del juego.
    - Calcular el puntaje o procesar algoritmos.
    - Obtener la jugada automática de la computadora.

Un desacoplamiento deficiente donde el _backend_ imprima textos en pantalla o solicite datos directamente rompe el contrato de modularidad y es un error grave de diseño.
```c
// backend.h - Interfaz pura sin interacción de usuario
typedef struct {
    int board[8][8];
    int score[2];
} ReversiGame;

int validateMove(const ReversiGame *game, int row, int col, int player);
void computeNextComputerMove(const ReversiGame *game, int *outRow, int *outCol);

// frontend.c - Interfaz de usuario que consume el backend
#include <stdio.h>
#include "backend.h"

void promptAndMakeMove(ReversiGame *game, int player) {
    int r, c;
    printf("Ingrese fila y columna: ");
    scanf("%d %d", &r, &c);
    
    if (validateMove(game, r, c, player)) {
        // Ejecutar movimiento
    } else {
        puts("Jugada inválida, reintente.");
    }
}
```
