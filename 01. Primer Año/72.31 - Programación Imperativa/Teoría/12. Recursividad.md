## Introducción

Para introducir la recursividad, imaginemos a un pintor que tiene la tarea de pintar una ruta completa. Si intenta hacerlo todo él solo de principio a fin, el trabajo se vuelve ineficiente e inmanejable por la enorme escala del problema. Para resolverlo, la clave está en cómo gestiona la carga de trabajo: en lugar de encarar toda la tarea junta, decide dividir la ruta en tramos más pequeños y delegarlos en otros pintores que aplicarán exactamente el mismo método de trabajo, repitiendo este proceso de subdivisión hasta que el tramo asignado a cada uno sea tan corto que cualquiera pueda pintarlo directamente sin necesidad de pedir ayuda.

Supongamos que el pintor conoce de eficiencia y decide llevarse el balde para pintar un tramo de 200 km. Una estrategia posible es contratar a otros 5 pintores para que cada uno asuma 40 km. El problema de fondo sigue siendo exactamente el mismo para todos (pintar una cantidad determinada de kilómetros); lo único que varía es el espacio de trabajo asignado a cada uno. El pintor original debe esperar a que los demás terminen.

Dado que 40 km puede seguir siendo un tramo extenso, cada pintor puede a su vez subcontratar a otros pintores, manteniendo la misma lógica del problema. De esta forma, la tarea se continúa subdividiendo sucesivamente hasta que cada pintor reciba un tramo razonable (por ejemplo, 2 km o menos), punto en el cual se corta la recursividad.

Expresado conceptualmente en pseudocódigo para este caso:
```
pintarTramo de N(km)
    si (N <= 2km)                             // Caso Base
        pintar dicho tramo;
    sino
        encontrar 5 pintores más
        pedirle a cada pintor:
            pintarTramo de N(km)              // Paso Recursivo
        medir el tramo de los 5 pintores
```

Si lo abstraemos a una estructura de código genérica en C:
```c
tipo funcionRecursiva( listaParámetros ) {
    if ( se cumple caso base ) {
        return solución_simple;
    } else {
        // dividir el problema en subproblemas de igual formato
        // resolver cada llamada recursiva de funcionRecursiva(...)
        return combinación_de_las_soluciones_parciales;
    }
}
```

Este esquema corresponde a una **recursión directa**, la cual consiste en la repetición por autorreferencia: una función que se invoca a sí misma en su propia definición. Existen múltiples tipos de problemas en programación que pueden resolverse tanto de forma recursiva como iterativa (sin recursividad).

Algunos errores comunes al implementar recursividad son:
- Omitir el caso base.
- No converger hacia el caso base, generando una recursividad infinita (y provocando un _stack overflow_).

## Factorial

Uno de los casos más conocidos de recursividad es el cálculo del **factorial**. Habitualmente lo veníamos resolviendo con un ciclo (planteo iterativo), pero existe también el planteo recursivo, que va a ser, en este caso, menos eficiente porque equivale a invocar a otra función varias veces. Por este motivo, el enfoque recursivo se plantea solamente para casos en los que se necesite estrictamente la recursividad (aunque en la práctica docente se suelen pedir ejercicios que serían más eficientes con un planteo iterativo para ejercitar el pensamiento recursivo).

Recordemos la definición matemática de factorial:
$$n! = n \times (n-1) \times (n-2) \times \dots \times 1$$
Veamos que:
$$n! = n \times (n-1)!$$

Por lo tanto podemos usar recursividad. Nuestro caso base será $0! = 1$.
```c
unsigned int factorial(unsigned int n) {
    if (n == 0)
        return 1;
    return n * factorial(n - 1);
}
```

Otra forma de escribir la misma lógica:
```c
unsigned int factorial(unsigned int n) {
    if (n > 0)
        return n * factorial(n - 1);
    return 1;
}
```

Notemos que todas las variaciones siguen la estructura genérica planteada anteriormente. Es muy importante definir correctamente el caso base, intentando tener un **único** caso base por función.

Empieza acumulando llamadas en la pila y "volviendo" a $n-1$, quedando a la espera de lo que retorne la función invocada. Una vez que alcanza el caso base ($n = 0$), comienza a retornar el valor hacia atrás a la función previa que estaba esperando, hasta desapilar por completo. El _stack_ primero se va llenando y luego, en la "vuelta", se va liberando.

Otro ejemplo podría ser calcular la potencia entera de un número $i^n$. Notemos que $i^n = i \times i^{n-1}$ y que nuestro caso base va a ser $i^0 = 1$.
```c
// Mal planteo: la recursividad NO valida en cada llamada
int potencia(int base, int exponente) {
    if (base == 0) // Este if valida, ver aclaración
        return 0;
    if (exponente == 0)
        return 1;
    return base * potencia(base, exponente - 1);
}
```

>[!INFO] Importante
>La recursividad no debe encargarse de las validaciones de entrada en cada llamada. En el ejemplo anterior, no tiene sentido preguntar en cada paso recursivo si la base es 0, porque la base nunca se modifica a lo largo del árbol de llamadas. A la función recursiva la debemos llamar con los parámetros ya validados. El segundo `if` (`exponente == 0`) sí corresponde porque es el **caso base**, y el exponente efectivamente se reduce en cada paso.

Si necesitamos validar parámetros de entrada (como verificar si la base es 0), armamos una función envolvente o **_wrapper_**:
```c
// Función Wrapper que realiza validaciones iniciales
int potencia(int base, int exponente) {
    if (base == 0 && exponente == 0)
        return ERROR;
    if (base == 0)
        return 0;
    return potenciaRec(base, exponente);
}

// Función puramente recursiva
int potenciaRec(int base, int exponente) {
    if (exponente == 0)
        return 1;
    return base * potenciaRec(base, exponente - 1);
}
```

Donde `potenciaRec()` es la función recursiva propiamente dicha que solo se encarga del cálculo y de la convergencia hacia el caso base.

## Series de Fibonacci

La **Sucesión de Fibonacci** se define matemáticamente de la siguiente manera:
$$T_n = \begin{cases} n & \text{si } n = 0 \text{ ó } n = 1 \\ T_{n-1} + T_{n-2} & \text{si } n > 1 \end{cases}$$

Implementación directa en C aplicando esta definición recursiva:
```c
long fibonacci(long n) {
    if (n == 0 || n == 1)
        return n;
    return fibonacci(n - 1) + fibonacci(n - 2);
}
```

## Torres de Hanoi

En el problema de las **Torres de Hanoi**, el objetivo es trasladar una torre de $n$ discos desde una varilla origen (**A**) hasta una varilla destino (**C**), utilizando una varilla auxiliar (**B**), respetando las reglas del juego (no se puede colocar un disco más grande sobre uno más pequeño y solo se puede mover un disco a la vez).
![[Pasted image 20260729214117.png|391]]

Para resolver el problema de manera recursiva, denominemos $n$ al disco más grande (ubicado en la base) y $n-1$ al bloque formado por el resto de los discos superiores. La estrategia consiste en:
1. Mover el bloque de $n-1$ discos desde el origen (**A**) hacia la varilla auxiliar (**B**), utilizando el destino (**C**) como soporte temporal.
2. Mover el disco restante $n$ directamente desde el origen (**A**) hacia el destino (**C**).
3. Mover el bloque de $n-1$ discos que quedó en la varilla auxiliar (**B**) hacia el destino (**C**), utilizando el origen (**A**) como soporte temporal.

El caso base conceptual ocurre cuando tenemos **un solo disco** ($n = 1$), en cuyo caso el movimiento es directo de **A** a **C** sin necesidad de apoyarse en la varilla auxiliar.
![[Pasted image 20260729214209.png|center|486]]
![[Pasted image 20260729214227.png|center|488]]
![[Pasted image 20260729214247.png|center|488]]

Traduciendo esta lógica a código C con caso base explícito en $n = 1$:
```c
void hanoi(int n, char orig, char aux, char dest) {
    // Caso base: un solo disco se mueve directamente
    if (n == 1) {
        printf("%c -> %c\n", orig, dest);
        return;
    } else {
        // 1. Mover los n-1 discos superiores al auxiliar
        hanoi(n - 1, orig, dest, aux);

        // 2. Mover el disco base n al destino
        printf("%c -> %c\n", orig, dest);

        // 3. Mover los n-1 discos del auxiliar al destino
        hanoi(n - 1, aux, orig, dest);
    }
}
```

Si quisiéramos simplificar la estructura del código, podríamos considerar como caso base implícito $n = 0$ (donde no se realiza ningún movimiento):
```c
void hanoi(int n, char orig, char aux, char dest) {
    if (n > 0) {
        hanoi(n - 1, orig, dest, aux);
        printf("%c -> %c\n", orig, dest);
        hanoi(n - 1, aux, orig, dest);
    }
}
```

Esta segunda alternativa simplifica la sintaxis al eliminar el `return` explícito, aunque genera llamadas recursivas adicionales en los niveles de las hojas de árbol cuando $n = 0$.

## Consideraciones Importantes

Como consideración fundamental, las funciones recursivas **no deben validar sus parámetros** dentro de su propio cuerpo. Esa responsabilidad debe recaer siempre sobre la función invocadora o envoltura (_wrapper_), evitando así ejecutar chequeos redundantes en cada nivel del árbol de llamadas.

Asimismo, la propiedad de recursividad depende estrictamente de que una función se llame a sí misma de forma directa o indirecta: si una función A invoca a una función B, y únicamente B se llama a sí misma, **solo la función B es recursiva**, mientras que A es simplemente una función convencional que llama a una función recursiva.

Por último, **se debe evitar el uso de variables `static`** dentro de funciones recursivas. Dado que las variables estáticas conservan su valor en memoria entre distintas ejecuciones, rompen la independencia de los marcos de llamada en la pila (_stack_), provocando que cada nivel modifique el mismo espacio de memoria y generando efectos secundarios indeseados o resultados incorrectos en cómputos posteriores.
