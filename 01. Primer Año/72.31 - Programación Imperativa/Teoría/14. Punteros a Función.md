Tomemos los casos de punteros que ya estudiamos, como ser `int *p`, `double *s`, etc. Todos ocupan 4 u 8 bytes según la arquitectura. Si ahora declaramos una función, ¿dónde se guarda todo el código de esa función? Se guarda en memoria, por lo que tiene una dirección asociada. Entonces podríamos pensar en declarar un puntero a una función.

Recordemos que lo que caracteriza a una función es su valor de retorno y sus parámetros. Para declarar un puntero a función no podemos escribir `double * fp(double);`, ya que esto declararía una función `fp` que devuelve un puntero a `double`. Para evitar este problema de precedencia con los operadores, debemos utilizar paréntesis agrupando el asterisco y el identificador:
```c
double (*fp)(double);
```

Cualquier función que acepte un parámetro de tipo `double` y retorne un `double` puede ser apuntada mediante este prototipo. El puntero `fp` almacenará la dirección de memoria de la primera instrucción ejecutable de la función. Si realizamos la asignación:
```c
fp = sqrt;
```

A partir de este momento resulta indistinto invocar a la función directamente mediante `sqrt` o a través de nuestro puntero `fp`. Podemos realizar la llamada utilizando la notación explícita con asterisco o la notación simplificada:
```c
double sqrt(double x);
double (*funp)(double x);
funp = sqrt;

double result;
// Invocación explícita mediante desreferenciación:
result = (*funp)(16.0);           // Equivalente a result = sqrt(16.0);
result = (*funp)((*funp)(16.0));   // Equivalente a result = sqrt(sqrt(16.0));
```

O bien prescindiendo del asterisco:
```c
double sqrt(double x);
double (*funp)(double x);
funp = sqrt;

double result;
// Invocación implícita o directa:
result = funp(16.0);              // Equivalente a result = sqrt(16.0);
result = funp(funp(16.0));        // Equivalente a result = sqrt(sqrt(16.0));
```

Los punteros a función nos ofrecen una gran flexibilidad en C, permitiéndonos:
- Pasarlos como argumentos a otras funciones.
- Retornarlos desde una función.
- Asignarlos a otro puntero a función compatible.
- Almacenarlos dentro de arreglos o vectores.
- Compararlos mediante los operadores de igualdad (`==`) y desigualdad (`!=`).

>[!INFO] Limitaciones
>Sin embargo, presentan ciertas limitaciones clave respecto de los punteros a datos: no es posible realizar operaciones de incremento o decremento sobre ellos, ni tampoco restar punteros a función entre sí, dado que no aplica la aritmética de punteros convencional.

Un uso habitual de los punteros a función como parámetro se observa en la función `atexit()` de la biblioteca estándar de C:
```c
#include <stdio.h>
#include <stdlib.h>

static void goodbye(void) {
    puts("Graciasss, vuelva prontosss");
}

int main(void) {
    atexit(goodbye); // Se pasa el puntero a la función goodbye
    // ...
    return 0;
}
```

Otro caso clásico se presenta cuando diseñamos un programa que ofrece un menú de opciones al usuario para aplicar distintas funciones matemáticas sobre un número real. Inicialmente podríamos implementarlo con una estructura condicional:
```c
int opcion;
double x, fx;
opcion = menu();

switch (opcion) {
    case 1: 
        fx = sqrt(x);
        printf("Raíz cuadrada de %g: %g\n", x, fx);
        break;
    case 2: 
        fx = sin(x);
        printf("Seno de %g: %g\n", x, fx);
        break;
    case 3: 
        // ...
        break;
}
```

Sin embargo, podemos optimizar significativamente la modularidad y escalabilidad del código mediante un **vector de punteros a funciones**. 
```c
(double)(*vFun[])(double) = {sin, cos, ex, log};
```

Para construir la declaración de este vector, analizamos la expresión desde el identificador `vFun` aplicando la regla de lectura de dentro hacia afuera y respetando precedencias:
1. `vFun`: Es un vector $\rightarrow$ `vFun[]`
2. `*vFun[]`: Es un vector de punteros.
3. `(*vFun[])(double)`: Es un vector de punteros a funciones que reciben un `double`.
4. `double (*vFun[])(double)`: Es un vector de punteros a funciones que reciben un `double` y devuelven un `double`.

De este modo, declaramos e inicializamos el vector asociándole las funciones deseadas de `<math.h>`:
```c
double (*vFun[])(double) = {sin, cos, exp, log10};
```

Dentro del ciclo principal de nuestro programa, la ejecución de la función seleccionada se simplifica a indexar el vector según la opción elegida:
```c
int main(void) {
    char option;
    double number;
    double ans;
    double (*vFun[])(double) = {sin, cos, exp, log10};

    do {
        if ((option = menu()) != EXIT) {
            number = getDouble("");
            errno = 0;
            ans = vFun[option - 1](number);
            if (errno != 0)
                printf("Problemas en el calculo\n");
            else
                printf("%s(%g)=%g\n", "FUNCION", number, ans);
        }
    } while (option != EXIT);

    return 0;
}
```

En la implementación anterior, imprimir la cadena literal `"FUNCION"` no resulta adecuado si deseamos mostrar el nombre específico de la función ejecutada. Tampoco es recomendable mantener un segundo arreglo paralelo con los nombres en texto, puesto que esto acopla el código de forma frágil.

La solución más limpia y profesional consiste en definir un tipo de estructura (`struct`) que encapsule tanto el nombre descriptivo de la función como su respectivo puntero a función:
```c
typedef struct {
    char *name;
    double (*pFun)(double);
} functionType;

functionType v[] = {
    {"seno", sin},
    {"coseno", cos},
    {"exp", exp},
    {"log10", log10}
};
```

De esta manera, la llamada a la función elegida y el acceso a su nombre representativo se resuelven de forma elegante y centralizada accediendo a los campos de la estructura:
```c
ans = v[option - 1].pFun(number);
printf("%s(%g) = %g\n", v[option - 1].name, number, ans);
```

Supongamos otro ejemplo: necesitamos implementar una función que reciba un vector de enteros y devuelva un nuevo arreglo reservado dinámicamente con aquellos números que sean pares:
```c
int * pares(const int * conj, size_t dim, size_t * nuevaDim) {
    int * res = NULL;
    int cont = 0;

    for (int i = 0; i < dim; i++) {
        if (conj[i] % 2 == 0) {
            if (cont % BLOQ == 0) {
                res = realloc(res, (cont + BLOQ) * sizeof(*res));
            }
            res[cont++] = conj[i];
        }
    }

    *nuevaDim = cont;
    // Reajustamos la memoria reservada para que quede exactamente con el tamaño final del vector
    res = realloc(res, cont * sizeof(*res));

    return res;
}
````

Si quisiéramos adaptar esta misma función para filtrar números impares, únicamente tendríamos que modificar la condición de evaluación dentro del ciclo: `if (conj[i] % 2 == 0)` $\rightarrow$ `if (conj[i] % 2 != 0)`

Del mismo modo, si quisiéramos filtrar únicamente los números primos, la lógica cambiaría a: `if (conj[i] % 2 == 0)` $\rightarrow$ `if (esPrimo(conj[i]))`

Como la estructura de la función es idéntica en todos los casos, existe una alternativa mucho más práctica: parametrizar la condición. Para lograr esto, la función principal pasa a recibir un puntero a una función de "criterio", permitiendo que quien la invoque decida qué prueba lógica se evaluará dentro del `if`:
```c
int * tipoNumero(const int * conj, size_t dim, size_t * nuevaDim, int (*criterio)(int)) {
    int * res = NULL;
    int cont = 0;

    for (int i = 0; i < dim; i++) {
        if (criterio(conj[i])) {
            if (cont % BLOQ == 0) {
                res = realloc(res, (cont + BLOQ) * sizeof(*res));
            }
            res[cont++] = conj[i];
        }
    }

    *nuevaDim = cont;
    // Reajustamos la memoria al tamaño exacto de elementos encontrados
    res = realloc(res, cont * sizeof(*res));

    return res;
}
```

Con este enfoque, la responsabilidad del programador consiste simplemente en definir las funciones auxiliares de verificación (`esPar`, `esImpar`, `esPrimo`) y pasárselas como argumento a `tipoNumero`:
```c
int esPar(int n) {
    return (n % 2 == 0);
}

int esImpar(int n) {
    return (n % 2 != 0);
}

int esPrimo(int n) {
    // ...
    return 0;
}
```
