## Introducción

En el diseño de datos en C es fundamental distinguir entre colecciones homogéneas y heterogéneas:
- **Arreglo (`array`):** Colección de datos caracterizada por su homogeneidad (todos sus elementos deben ser estrictamente del mismo tipo) y su orden. Sus elementos se identifican individualmente mediante índices.
- **Uniones (`union`):** Permiten compartir un mismo espacio de memoria entre distintos campos. Las estudiamos conceptualmente para comprender en detalle la disposición de memoria de los `structs`, pero no se utilizan activamente en el desarrollo regular.
- **Estructuras (`struct`):** Permiten definir tipos de datos compuestos que agrupan variables de distintos tipos (heterogéneas) bajo un mismo identificador.

¿Qué sucede si queremos representar y almacenar los datos pertenecientes a una entidad compleja, como por ejemplo un libro? Nos encontramos con características de diversa naturaleza:
- Título: Cadena de caracteres (`char[]` o `char *`)
- Autor: Cadena de caracteres (`char[]` o `char *`)
- Páginas: Entero (`int`)
- Precio: Coma flotante (`float` o `double`)
- ISBN: Entero (`int` o `long`)

Para evitar manejar múltiples arreglos independientes y desvinculados para cada atributo, C proporciona las estructuras (`struct`), las cuales permiten agrupar todos estos miembros heterogéneos en una sola unidad lógica.

---
## Definición

Un registro o **struct** es una colección de datos heterogéneos y sin orden, cuyos elementos no se identifican con índices numéricos sino con nombres de campos.

La sintaxis general para declarar una `struct` es:
```c
struct nombreRegistro {
    tipo1 nombreCampo1;
    tipo2 nombreCampo2;
    ...
    tipoN nombreCampoN;
};
```

Aplicando esta sintaxis al ejemplo del libro, la declaración queda:
```c
struct tipoLibro {
    char titulo[30];
    char autor[30];
    char ISBN[11];
    float precio;
};
```

>[!INFO] Importante
>Es muy importante notar que `struct tipoLibro` define únicamente un **nuevo tipo de dato**, NO una variable en memoria.

Para poder utilizarlo y declarar variables de este tipo, se usa la siguiente forma:
```c
struct nombreRegistro nombreVariable;
```

Donde el bloque `struct nombreRegistro` actúa en su conjunto como el tipo de dato, y `nombreVariable` es el identificador de la variable concreta que almacenará la información.

---
Al anidar estructuras se establecen jerarquías. Dos campos dentro de la misma jerarquía (mismo nivel de definición) deben tener obligatoriamente nombres diferentes para evitar ambigüedades. En cambio, dos campos pertenecientes a diferentes jerarquías o a estructuras distintas sí pueden coincidir en sus nombres.

Un ejemplo de lo que **NO** se debe hacer por colisión de nombres en el mismo nivel:
```c
// INCORRECTO: genera error por identificador duplicado
struct tipo1 {
    char nombre[30];
    char nombre[30]; // Error: nombre repetido dentro de la misma estructura
    float dato;
};
```

Por el contrario, al anidar o definir estructuras compuestas, los nombres pueden repetirse en distintos niveles:
```c
// CORRECTO:
struct tipo1 {
    int codigo;
    char nombre[30];
};

struct tipo2 {
    int codigo; // Válido: pertenece a tipo2
    struct tipo1 dato; // Anidamiento de struct tipo1 dentro de tipo2
};
```

## Uso de `typedef`

Podemos usar `typedef` para abreviar la sintaxis al declarar tipos de datos estructurados. La sintaxis de declaración de un registro o `struct` con `typedef` es la siguiente:
```c
typedef struct nombreOptativo {
    tipo1 nombreCampo1;
    tipo2 nombreCampo2;
    ...
    tipoN nombreCampoN;
} nombreTipo;

struct nombreOptativo unaVariable;
nombreTipo otraVariable;
```

Para la inicialización de una variable de tipo estructura, la sintaxis general asigna los valores entre llaves respetando la definición del registro:
```c
struct nombreRegistro {
    tipo1 nombreCampo1;
    tipo2 nombreCampo2;
    ...
    tipoN nombreCampoN;
};

struct nombreRegistro nombreVariable = {dato1, dato2, ..., datoN};
```

Por ejemplo, dada la estructura para una fecha:
```c
struct tipoFecha {
    int dia, mes, anio;
};

struct tipoFecha cita = {10, 11, 2020};
```

En este caso, hay que recordar que importa el orden según cómo guardamos los datos (en este ejemplo, 10 para `dia`, 11 para `mes` y 2020 para `anio`).

A partir del estándar C99, se permite la inicialización referenciando explícitamente los campos mediante sus nombres:
```c
struct tipoFecha {
    int dia, mes, anio;
};

// A partir de C99 se permite inicializar referenciando los campos:
struct tipoFecha cita = {.anio=2022, .dia=12}; // mes es cero
```

En este segundo caso, los campos que no rellenamos explícitamente se rellenan automáticamente con cero.

Un ejemplo integrando `typedef` e inicialización:
```c
typedef struct {
    char aerolinea[30];
    int vuelo;
    char fecha[10];
    char hora[6];
} tipoPasaje;

tipoPasaje pasaje = {"Flybondi", 905, "20240619", "20:30"};
```

## Acceso a un Campo

Para acceder a un campo de una estructura lo hacemos con el operador punto `.`:
```c
tipoPasaje pasaje;

pasaje = (tipoPasaje) {
    .aerolinea = "Flybondi",
    .fecha = "20240619",
    .vuelo = 905,
    .hora = "20:30"
};
```

Si quisiéramos imprimir la hora:
```c
printf("%s", pasaje.hora);
```

Si quisiéramos cambiar el número de vuelo:
```c
pasaje.vuelo = 908;
```

Si quisiéramos cambiar la aerolínea, estaría **MAL** hacer esto:
```c
pasaje.aerolinea = "Emirates";
```
porque no es un _l-value_. En cambio, deberíamos hacer:
```c
strcpy(pasaje.aerolinea, "Emirates");
```

Dada la siguiente definición de estructura y uso de variables:
```c
struct bookType {
    char title[30];
    char *author;
    float price;
    unsigned int pages;
};

struct bookType book;
book.pages = 150.5;
book.price = book.price * 1.5;
book.title = "Ficciones";
strcpy(book.author, "Jorge Luis Borges");
```

Hacemos un análisis de la validez de las expresiones:
1. `book.pages = 150.5;` $\rightarrow$ Está bien sintácticamente porque va a castear el 150.5 a 150, pero no está bien en cuanto a estilo de programación.
2. `book.price = book.price * 1.5;` $\rightarrow$ Está mal, porque nunca inicializamos la variable `price` con un valor previo antes de leerla.
3. `book.title = "Ficciones";` $\rightarrow$ Está mal por lo que vimos antes, `book.title` es un arreglo estático y no es un _l-value_ asignable. Deberíamos hacer `strcpy()`.
4. `strcpy(book.author, "Jorge Luis Borges");` $\rightarrow$ Está mal, porque al ser `author` un puntero (`char *`), no le reservamos espacio para guardar el string antes de copiarlo. Deberíamos asignarle una cadena literal con `book.author = "..."` si es algo que no vamos a modificar, o asignarle memoria con `book.author = malloc(...)` y luego guardar el nombre.

## Estructura Como Parámetro

Al pasar una estructura como parámetro a una función, se envía al _stack_ una copia de la misma. Como se envía una copia, si la función modifica un campo, la variable original (el parámetro actual) no se ve alterada.
```c
enum meses{ENE=1,FEB,MAR,ABR,MAY,JUN,JUL,AGO,SET,OCT,NOV,DEC};

typedef struct {
    int dia;
    enum meses mes;
    int anio;
} fechaTipo;

void imprime( fechaTipo fecha) {
    printf("%02d/%02d/%04d\n",fecha.dia,fecha.mes,
            fecha.anio);
    fecha.dia = 0;
    return;
}

int main(void) {
    fechaTipo fecha1 = {19, FEB, 1970};
    imprime( fecha1 );
    return 0;
}
```

Si lo corremos una vez, imprime `"19/02/1970"`. Si lo corremos por segunda vez, se podría pensar que debería imprimir `"00/02/1970"`, pero imprime lo mismo que antes. Esto es porque la función **recibe una COPIA**. Por lo tanto, no modifica el valor original.

Analizando otro ejemplo:
```c
typedef struct {
    int code;
    char description[30];
} itemType;

void change( itemType art){
    art.code = 2;
    strcpy(art.description, "Zapatilla");
    return;
}

int main(void){
    itemType art = {1, "Zapato"};
    change( art );
    printf("%d - %s \n", art.code, art.description);
    return 0;
}
```

En este caso, la función `change` "no hace nada" sobre la variable del `main`, pues cuando imprimimos nos da `"1 - Zapato"`. Sigue el mismo razonamiento de antes: `change` recibe una copia, entonces guarda el $2$ en la copia y `"Zapatilla"` también en la copia.

Veamos este caso con un puntero dentro de la estructura:
```c
typedef struct {
    int code;
    char * description;
} itemType;

void change( itemType art) {
    art.code = 2;
    strcpy(art.description, "Zapatilla");
    return;
}

int main(void) {
    itemType art = {1, "Zapato"};
    change( art );
    printf("%d - %s \n", art.code, art.description);
    return 0;
}
```

Este código va a compilar pero arrojará un error en tiempo de ejecución (_Runtime error_). El error ocurre porque `"Zapato"` está almacenado en una zona de memoria constante, por lo que `change` recibe la copia de la estructura con un puntero apuntando a esa zona constante e intenta escribir sobre ella con `strcpy`.

Si adaptamos el código apuntando a un arreglo modificable:
```c
typedef struct {
    int code;
    char * description;
} itemType;

void change( itemType art) {
    art.code = 2;
    strcpy(art.description, "Zapatilla");
    return;
}

int main(void) {
    char greet[30] = "Hola mundo";
    itemType art;
    art.code = 1;
    art.description = greet;
    change( art );
    printf("%d - %s \n", art.code, art.description);
    return 0;
}
```

Ahora sí vamos a poder imprimir `"1 - Zapatilla"`. El valor de `art.code` sigue valiendo $1$ sin modificarse porque se cambió en la copia, pero el contenido del _string_ apuntado sí pudo modificarse.

Para modificar el código o retornar una estructura completa de forma segura, podemos hacer que la función la devuelva explícitamente:
```c
typedef struct {
    int code;
    char * description;
} itemType;

itemType newItem(int code, char * description) {
    itemType aux;
    aux.code = code;
    aux.description = malloc(strlen(description)+1);
    strcpy(aux.description, description);
    return aux;
}

int main(void) {
    itemType art;
    art = newItem(1, "Zapatilla");
    printf("%d - %s \n", art.code, art.description);
    free(art.description);
    return 0;
}
```

En este caso sigue imprimiendo $1$ porque a `aux` le pasamos `code` que es $1$ (si fuera $2$, lo imprime bien). Lo que sucede aquí es que el _string_ se recorre 2 veces: una para calcular el largo (`strlen`) y otra para el `strcpy`. Esto lo podemos hacer solo para strings cortos, de lo contrario tendríamos que trabajar directamente con bloques de memoria.

Resumiendo las operaciones permitidas, las estructuras pueden ser:
- **Inicializadas:**
    ```c
    typedef struct {
        char nombre[30];
        int legajo;
    } tipoAlumno;
    
    tipoAlumno alu = {"Juan Perez", 39205};
    ```
- **Asignadas:**
    ```c
    tipoAlumno alu1 = {"Juan P.", 39205}, alu2;
    ...
    alu1 = alu2;
    ```
- **Pasadas como parámetro:**
    ```c
    respuesta = procesarAlumno(alu);
    ```
- **Retornadas en el nombre de la función:**
    ```c
    alu = leerAlumno();
    ```

Por otro lado, las estructuras NO pueden ser comparadas directamente:
```c
    typedef struct {
        char nombre[30];
        int legajo;
    } tipoAlumno;
    
    tipoAlumno alu1 = {"Juan Perez", 39205};
    tipoAlumno alu2 = {"Jose Garcia", 38205};
    ...
    if (alu1 == alu2) // ERROR DE COMPILACIÓN
    ...
```

Como se envía una copia de la estructura, si la función modifica un campo, la variable original (el parámetro actual) no se ve alterada. Para modificar directamente la variable original, debemos pasar un puntero a la estructura. En ese caso deberíamos usar `(*p).code`, pero para simplificar esta sintaxis se creó el operador `->`.

Ejemplo utilizando desreferenciación explícita `(*p)`:
```c
typedef struct {
    int code;
    char description[30];
} itemType;

void change( itemType * item) {
    (*item).code = 2;
    strcpy((*item).description, "Zapatilla");
    return;
}

int main(void) {
    itemType it = {1, "Zapato"};
    change( &it );
    printf("%d - %s \n", it.code, it.description);
    return 0;
}
```

Si quisiéramos usar el operador `->`:
```c
typedef struct {
    int code;
    char description[30];
} itemType;

void change( itemType * item) {
    item->code = 2;
    strcpy(item->description, "Zapatilla");
    return;
}

int main(void) {
    itemType it = {1, "Zapato"};
    change( &it );
    printf("%d - %s \n", it.code, it.description);
    return 0;
}
```

## Almacenamiento de una Estructura en Memoria

Los campos de una estructura se almacenan en forma contigua siguiendo el orden de la declaración, pero pueden quedar espacios vacíos entre ellos debido al alineamiento. Los campos se alinean a palabra, es decir que cada campo comienza en una posición de memoria múltiplo de la palabra.

Tomemos la siguiente estructura:
```c
struct tipoAlumno {
    char nombre[25]; // 25 + 3 bytes de relleno
    int legajo;      // 4 bytes
    int anio;        // 4 bytes
    char curso;      // 1 + 3 bytes de relleno
};                   // Total = 40 bytes
```

En memoria:
![[Pasted image 20260729204616.png|center|588]]

En este caso, para el campo `nombre[25]` se ocupan 25 bytes más 3 bytes de _padding_ o relleno para completar el límite del múltiplo de la palabra (4 bytes). El campo `legajo` ocupa 4 bytes, `anio` ocupa 4 bytes, y `curso` ocupa 1 byte más 3 bytes de relleno al final para alinear el tamaño total de la estructura a un múltiplo de palabra, dando un total de 40 bytes.

Si por ejemplo `nombre` fuera de 24 elementos, no rellenaría en ese campo (asumiendo que el tamaño de palabra es de 4 bytes, como en el caso anterior), ya que 24 es directamente un múltiplo de 4.

## Optimización de Memoria

Para optimizar la memoria en una estructura, el orden de los campos importa debido al alineamiento y al _padding_. Agrupar los campos por tipos de dato de igual tamaño reduce el espacio desperdiciado por relleno:
```c
typedef struct one {
    int i1;
    char c1;
    int i2;
    char c2;
    int i3;
    char c3;
} one;

typedef struct two {
    int i1, i2, i3;
    char c1, c2, c3;
} two;

int main(void) {
    printf("%ld\n", sizeof(one)); // Imprime 24
    printf("%ld\n", sizeof(two)); // Imprime 16
    return 0;
}
```

Para obtener las propiedades de tamaño y posición de los campos en memoria:
- Para conocer el tamaño de una estructura $\rightarrow$ `sizeof()`.
- Para conocer la posición relativa de un campo $\rightarrow$ `offsetof(tipo, campo)` (requiere incluir `<stddef.h>`).

Si quisiéramos indicar cuántos bits ocupa cada campo, usamos _bit fields_:
```c
typedef struct {
    unsigned int size:6;        // 6 bits (0 a 63)
    unsigned int bold:1;        // 1 bit (0 ó 1)
    unsigned int italic:1;
    unsigned int underline:1;
    unsigned int strikethrough:1;
    unsigned int superscript:1;
    unsigned int subscript:1;
} format;
```

Dadas las siguientes definiciones:
```c
typedef struct {
    int code;
    char descr[10];
} itemType1;

typedef struct {
    int code;
    char * descr;
} itemType2;
```

Y la secuencia de operaciones:
```c
???? item = {98, "Lapicera"}, item2;

item2 = item;
strcpy(item.descr, "Tijera");
strcpy(item.descr, "Papel glase");
item.code = 9;
item.descr = "Hola";
item.descr[0] = 'A';
```

Análisis del tipo de variable para `item`:
1. `{98, "Lapicera"}` $\rightarrow$ Cualquiera guarda el _string_, pero lo guarda en una zona constante si usamos `itemType2`.
2. `item2 = item;` $\rightarrow$ Cualquiera, pero tienen que coincidir en el tipo (si uno es `itemType1`, el otro debe ser del mismo tipo).
3. `strcpy(item.descr, "Tijera");` $\rightarrow$ `itemType1`, porque si fuera `itemType2` tiraría error de ejecución (salvo que tuviéramos un `malloc` previo).
4. `strcpy(item.descr, "Papel glase");` $\rightarrow$ Ninguno, porque no hay espacio para guardar todo el _string_ (supera los 10 bytes). Podríamos decir `itemType1` pensando que en realidad reserva 12 bytes por alineamiento, dado que 10 no es múltiplo de 4.
5. `item.code = 9;` $\rightarrow$ Cualquiera.
6. `item.descr = "Hola";` $\rightarrow$ Debe ser obligatoriamente `itemType2`. En `itemType1` no se puede hacer porque `descr` es un arreglo estático y no un _l-value_ asignable (es una dirección constante), lo que tira error de compilación. En `itemType2` cambia el puntero para apuntar a la zona constante de `"Hola"`.
7. `item.descr[0] = 'A';` $\rightarrow$ Debe ser `itemType1`, porque en `itemType2` se estaría intentando modificar un caracter dentro de una zona de memoria constante.

## Estructuras de Datos Complejas

Los tipos de datos _built-in_ (`char`, `int`, `float`, etc.), los arreglos y las estructuras se pueden combinar y anidar para generar estructuras de datos complejas. Supongamos el caso en que queremos modelar una biblioteca. Si intentamos definir una única estructura declarando individualmente los campos para cada libro:
```c
struct tipoBiblioteca {
    char titulo1[30];
    char autor1[30];
    char ISBN1[11];
    float precio1;
    ...
    char tituloN[30];
    char autorN[30];
    char ISBNN[11];
    float precioN;
};
```

Esto representa una pésima idea; por ejemplo, no nos permite ordenar los elementos según el título de forma genérica o iterar sobre ellos. Otra alternativa podría ser utilizar arreglos paralelos:
```c
char titulos[N][30];
char autores[N][30];
char ISBNs[N][11];
float precios[N];
```

Esta propuesta también resulta una mala idea: no hay coherencia semántica y no vamos a poder mantener fácilmente la relación de posición entre los datos asociados a cada libro si realizamos ordenamientos o modificaciones.

La solución adecuada es utilizar un **vector de structs** (o arreglo de estructuras), los cuales pueden ser tanto estáticos como dinámicos:
```c
struct tipoLibro {
    char titulo[30];
    char autor[30];
    char ISBN[11];
    float precio;
};

// Declaración directa de un arreglo de estructuras:
struct tipoLibro biblioteca1[N];

// O bien definiendo el tipo de arreglo mediante typedef:
typedef struct tipoLibro tipoBiblioteca[N];
tipoBiblioteca biblioteca2;
```

> [!WARNING] ¡Cuidado!
> No podemos escribir sintaxis del tipo `bib[index].&precio`, porque inmediatamente después del operador punto (`.`) debe ir únicamente el nombre de un campo de la estructura. La forma correcta de obtener la dirección de un campo es `&bib[index].precio`.

En cuanto al rendimiento, al trabajar con funciones siempre es más eficiente pasar un puntero a la estructura que pasar la estructura completa por valor, ya que evita copiar todos sus campos en el _stack_.

## Encapsulamiento

Cuando se utilizan arreglos para almacenar elementos sin orden (desde el punto de vista semántico), ocurre que en cierto instante hay una cantidad de componentes ocupadas menor a la disponible, por lo que resulta necesario almacenar en una variable la cantidad de componentes en uso:
```c
typedef struct {
    int values[30];
    unsigned int dim;
} Array;

Array v;
```

Si a este caso le queremos aplicar una función de `mezcla()` que reciba `Array v`, no va a funcionar, porque recordemos que recibe una **COPIA**. Por más que sea un vector (`values`), al estar contenido dentro de la estructura, la función no lo modifica.

Podemos usar el mismo criterio de encapsulamiento para vectores dinámicos:
- `values`: los elementos (puntero al bloque asignado dinámicamente)
- `size`: espacios reservados en memoria
- `dim`: componentes efectivamente almacenadas

```c
typedef struct {
    int * values;
    unsigned int size;
    unsigned int dim;
} Array;

Array v;
```

## Uniones

Las **uniones** son una colección de datos heterogéneos y sin orden cuyos elementos se identifican con nombres, con la particularidad de que **NO pueden coexistir** al mismo tiempo. En C, `union` es una palabra reservada del lenguaje (motivo por el cual no se puede nombrar a una función así). Se utilizaban más antiguamente cuando el manejo de memoria era crítico; por ejemplo, para almacenar un `int` **O** un `long` **O** un `double` compartiendo el mismo espacio físico.

>[!TIP] Almacenamiento
>Todos sus campos se guardan comenzando en la misma dirección de memoria, y el tamaño total reservado por el compilador equivale siempre a la cantidad que requiera el campo de mayor tamaño. De esta forma, solo se puede utilizar uno de los campos a la vez.

La sintaxis general de declaración de una unión es:
```c
union nombreUnion {
    tipo1 nombreCampo1;
    tipo2 nombreCampo2;
    ...
    tipoN nombreCampoN;
};
```

Por ejemplo:
```c
union tipoNro {
    int entero;
    long enteroLargo;
    float realSimple;
    double realDoble;
};
```

Para declarar una variable de tipo unión, existen dos opciones principales:
```c
// Alternativa 1: declarar la variable junto con la definición
union nombreUnion {
    tipo1 nombreCampo1;
    tipo2 nombreCampo2;
    ...
    tipoN nombreCampoN;
} nombreVariable;

// Alternativa 2: definir el tipo y declarar la variable por separado
union nombreUnion {
    tipo1 nombreCampo1;
    tipo2 nombreCampo2;
    ...
    tipoN nombreCampoN;
};

union nombreUnion nombreVariable;
```

Para reconocer cuál de los campos de la unión está "activo" en un momento determinado, se suele utilizar una marca o _"tag"_. Para mantener la coherencia semántica, se encapsula la unión junto con el _tag_ dentro de una estructura (`struct`):
```c
typedef union {
    int entero;
    long enteroLargo;
    float realSimple;
    double realDoble;
} unionNro;

typedef struct {
    char tag;
    unionNro valor;
} tipoNro;
```

Luego se suele utilizar una sentencia `switch` evaluando la etiqueta para procesar el campo correspondiente:
```c
switch(miNum.tag) {
    case 'I': printf("%d", miNum.valor.entero); break;
    case 'F': printf("%f", miNum.valor.realSimple); break;
    ...
}
```
