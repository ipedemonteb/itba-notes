## Definición de Programas

Un **programa en C** consiste en un conjunto de una o más funciones que siguen una estructura determinada:
```c
tipo nombreFuncion (parametros) {
	//...
	return ???
}
```
- `tipo`: Indica el tipo del valor de retorno de la función
- `nombreFuncion`: Nombre que la identifica
- `(parametros)`: Lista de parámetros de la función
- `//...`: Cuerpo de la función, indica cómo lograr su objetivo
- `return ???`: retorna un valor del tipo de la función

El nombre de la función no puede empezar con un número, es *case-sensitive* (sqr $\neq$ SQR $\neq$ Sqr). y no puede ser una palabra reservada (ej. `if`, `return`, `int`). Toda función debe declarar explícitamente su tipo de retorno, que define el tipo de dato que devolverá al finalizar su ejecución. Si la función no debe retornar ningún valor, se utiliza `void`. No especificar el tipo de retorno es una mala práctica, aunque el compilador asuma por defecto que es un `int`.

El cuerpo de la función, donde se declaran las variables locales y se escribe el código de lógica y ciclos, debe ir delimitado por llaves `{}`, incluso si es únicamente una sola línea de código. Asimismo, siempre se deben incluir los paréntesis para los parámetros que representan los datos necesarios para el cálculo; si la función no los requiere, los paréntesis simplemente se dejan vacíos `()`.

Algunos ejemplos de funciones simples son:
```c
double mult(double x, double y) {
	return x*y;
}
```

```c
void menu() {
	printf("1...");
	printf("2...");
}
```

Donde `double` es un tipo de valor numérico.

## Función Main

Para que un programa pueda ejecutarse, requiere obligatoriamente de una función `main()`. Aunque inicialmente la utilicemos sin argumentos (como `void`), es de tipo `int` porque debe retornar un código de salida (o _exit code_) al sistema operativo: 
- Si retorna 0 significa que la ejecución fue exitosa
- Cualquier otro valor indica un error 

Si el programa es corto se puede resolver todo dentro del propio `main()`; de lo contrario, lo correcto es modularizarlo creando otras funciones y llamándolas desde allí.
![[01. Funciones en C-1781279461474.webp|center|397]]

Para el desarrollo podemos elegir el editor que prefiramos, como *VSCode*, pero en las clases todo se manejará a través de la línea de comandos. El compilador estándar que utilizaremos es *GCC*. Dado que algunos compiladores se comportan de manera diferente, lo más conveniente es compilar en un entorno *Linux*, evitando el *GCC* por defecto de *Mac*, ya que no es el verdadero de *GNU* y puede traer discrepancias. Para enviarle el código al compilador, realizamos el siguiente procedimiento:
```c
double mult(double x, double y) {
	return x*y;
}

int main(void) {
	double z = mult(1.5, 3.0);
	return 0;
}
```

```bash
gcc ej1.c -pedantic -std=c99
```

Para invocar al compilador utilizamos el comando `gcc`, pasándole como argumento el archivo del programa, por ejemplo, `ej1.c`. También se suelen incluir flags como `-pedantic` y `-std=c99` (los vamos a ver más adelante). 

Si el proceso de compilación es exitoso y no se produce ningún error, la terminal no arrojará ningún mensaje de salida. En su lugar, el compilador generará directamente el archivo ejecutable, que por defecto se nombrará `a.out` si es que no le asignamos un nombre específico.

> [!Warning] ¡Cuidado!
> El compilador hace una sola pasada, por lo que es importante que el main esté siempre al final.

Tomemos el siguiente caso:
```c
int main(void) {
	double z = mult(1.5, 3.0);
	return 0;
}

double mult(double x, double y) {
	return x*y;
}
```

El compilador realiza la lectura del código en una sola pasada. Cuando encuentra la llamada a `mult`, como todavía no sabe qué es, asume por defecto que es una función que devuelve un `int` y que recibe parámetros también de tipo `int`. Esto genera un _warning_ en la terminal al que hay que prestarle atención. El problema real ocurre cuando el compilador finalmente llega a la definición de la función y ve que en realidad necesita recibir `double` para ejecutarse. Como antes asumió que eran enteros, se produce un conflicto de tipos, arroja un error y el programa no compila.

Esta restricción con el orden se puede complicar todavía más cuando empezamos a llamar funciones dentro de otras funciones. Para solucionar este problema, podemos declarar las funciones al principio del archivo especificando sus parámetros, y postergar su desarrollo para más adelante. A este primer paso lo conocemos como "declaración" o "prototipo" de la función, mientras que al desarrollo posterior de su código lo llamamos "definición".
```c
double mult(double x, double y);

int main(void) {
	double z = mult(1.5, 3.0);
	return 0;
}

double mult(double x, double y) {
	return x*y;
}
```

## Traductor de Programas

Es el software necesario para transformar un programa en código fuente a lenguaje máquina. Existen dos tipos principales:
- **Compiladores (C, Pascal, Java, C++):** Son aquellos que toman el programa completo y generan el código de máquina o un código intermedio. Se caracterizan por ser tipados, ya que el compilador necesita conocer los tipos de datos para saber exactamente qué código máquina o intermedio debe generar.
- **Intérpretes (Smalltalk, PHP, Lisp, Ruby):** A diferencia de los anteriores, toman el código línea por línea y lo van traduciendo y ejecutando en código máquina en tiempo real.

El proceso del compilador es el siguiente:
![[01. Funciones en C-1781366318227.webp|center|418]]
El **compilador** recibe nuestro programa fuente y se encarga puramente de traducirlo a código objeto. Luego, el **linkeditor** (o enlazador) entra en juego para generar el archivo ejecutable final, encargándose de acoplar otras funciones o bibliotecas externas que hayamos invocado, como sucede con `#include <stdio.h>`. Para organizarse y saber por dónde arrancar la ejecución, el sistema busca la función `main`; por lo tanto, sin un `main` es imposible generar el ejecutable. Cabe destacar que el compilador en sí no detecta la falta de esta función, ya que su única tarea es traducir el código que tiene disponible; el error saltará recién en la etapa de enlazado.

Los **intérpretes** no generan un programa ejecutable, sino que pueden generar un código intermedio que será interpretado en tiempo de ejecución en una máquina virtual. Permiten lenguajes no tipados. Tienen una importante desventaja, que es que son más lentos, pero a su vez, son más portables.

> [!INFO] Flag `-c`
> Si hacemos un código y queremos que solamente compile y NO linkedite, debemos agregar `-c` luego del nombre del programa. Si no lo ponemos, nos va a arrojar el error de que en main, la función mult no existe, porque no compiló el segundo archivo todavía.
> ```bash
> # Compilar sin linkeditar
> gcc main.c -c -pedantic -std=c99
> # Para linkeditar:
> gcc main.o
> ```

Un programa es **portable** si se adapta fácilmente a nuevos entornos sin tener que reescribirlo. Debe ser multiplataforma, para lo que debemos usar una versión Estándar. Nosotros usamos la *ANSI C (ISO C-9L)*. Usando `-pedantic -std=c99` nos aseguramos que corra en cualquier plataforma. También podemos agregar delante `-Wall` para que analice el código con más detenimiento para detectar posibles fallas.

## Biblioteca Estándar

La **biblioteca estándar de C** es un conjunto de funciones y herramientas predefinidas que ya vienen listas para usar y que cubren las necesidades más frecuentes, como manejar entradas y salidas, manipular archivos o gestionar memoria. En lugar de escribir cada proceso desde cero, simplemente incluimos el encabezado correspondiente al inicio de nuestro código y aprovechamos estas funcionalidades, que además de ahorrarnos tiempo, garantizan que nuestro programa sea mucho más eficiente y portable.

Es importante sabe que no podemos usar las palabras reservadas de c o de estas bibliotecas: `auto`, `break`, `case`, `char`, `const`, `continue`, `default`, `do`, `double`, `else`, `enum`, `extern`, `float`, `for`, `goto`, `if`, `int`, `long`, `register`, `return`, `short`, `signed`, `sizeof`, `static`, `struct`, `switch`, `typedef`, `union`, `unsigned`, `void`, `volatile`, `while`, `inline`, `restrict`, `_BooL`, `_Complex`, `_Imaginary`.

## Valor de Retorno

En C, absolutamente toda función tiene la capacidad de retornar un valor a quien la invoca. En el caso específico de la función `main()`, quien la llama es el intérprete de comandos del sistema operativo o un script de comandos (_command script_). El valor de retorno del `main` es un entero representado en complemento a la base; un cero indica que el programa se ejecutó correctamente, mientras que un valor distinto de cero señala un error, cuyo significado dependerá del código devuelto. 

Este mecanismo de retorno con `return` es muy útil, por ejemplo, al manejar la apertura de archivos, ya que este proceso puede fallar y necesitamos reportarlo. Por último, para mostrar información en pantalla vamos a utilizar la función `printf`, la cual veremos en detalle durante el taller del viernes.

Podemos ver el siguiente caso, donde se retorna indicando que hubo un error:
```c
int main(void) {
	// ...
	myFile = fopen(...);
	if(myFile == NULL)
		return 1;
	// ...
}
```

## Comentarios

Los **comentarios** sirven para clarificar la semántica y la lógica del código. Para escribirlos, una de las formas es usar la estructura de apertura `/*` y cierre `*/`. Todo lo que se encuentre entre estos símbolos será ignorado por el compilador, sin importar cuántas líneas de texto haya en el medio. 
```c
int main(void) {
	/* Todo esto
	es un comentario */
	return 0;
}
```

Una regla fundamental es que estos comentarios no pueden estar anidados; por ejemplo, si escribimos `/* No pueden */ estar */ anidados */`, el compilador interpretará que el comentario termina en el primer cierre, dejando el resto del texto suelto y generando un error de sintaxis. Otra manera de comentar es utilizando doble barra `//`, con la salvedad de que este estilo solo se extiende desde su aparición hasta el final de esa misma línea.
```c
int main(void) {
	// Esto es un comentario
	/* Esto también es un comentario */
	return 0;
}
```
