## Puntero a `void`

Al diseñar funciones modularizadas (como una función para la unión de vectores), una mejor práctica de diseño es hacer que la propia función reserve e instancie dinámicamente el vector de respuesta mediante asignación de memoria (por ejemplo, con `malloc`), retornando el puntero a dicho vector en lugar de requerir que el llamante le pase una estructura con un tamaño prefijado desde afuera.

El puntero a `void` (`void *`) es un puntero genérico que representa la dirección de memoria de un dato sin especificar su tipo. Se utiliza cuando necesitamos escribir funciones abstractas o polimórficas que puedan operar con direcciones de cualquier tipo de dato.

A un puntero genérico se le puede asignar directamente la dirección o el valor de cualquier otro tipo de puntero sin necesidad de casteos explícitos, y viceversa:
```c
int num = 6;
double valor = 8.4;
int * pint = &num;
float * pfloat;
void * p;

// Asignaciones válidas a un puntero genérico:
p = &num;
p = &valor;
p = pint;

// Asignaciones válidas desde un puntero genérico:
pint = p;
pfloat = p;
```

Sin embargo, no es posible desreferenciar directamente un puntero a `void` ni realizar aritmética de punteros sobre él, ya que el compilador desconoce el tamaño en bytes del tipo subyacente.
```c
int num1 = 6, num2;
int * pint;
void * p;

pint = &num1;
num2 = *pint;  // CORRECTO: 'pint' es de tipo int*

p = &num1;     // CORRECTO: asignación implícita a void*
num2 = *p;     // ERROR de compilación: no se puede desreferenciar un void*
```

Para poder acceder al valor o aplicar aritmética sobre `p`, es obligatorio castearlo explícitamente al tipo concreto correspondiente:
```c
num2 = *((int *)p);  // CORRECTO: casteado a int* antes de desreferenciar
```

Consideremos una función genérica concebida para colocar `cant` bytes en cero a partir de una dirección determinada de memoria:
```c
// Intento incorrecto:
void asignaCeros(void * dir, int cant) {
    for (int i = 0; i < cant; i++) {
        *(dir + i) = 0; // ERROR de compilación: aritmética y desreferenciación sobre void*
    }
}
```

El error se produce por intentar realizar aritmética (`dir + i`) y desreferenciar (`*`) sobre el tipo `void *`. La forma correcta es castear el puntero a `char *` (o `uint8_t *`), ya que al ser un tipo de dato de tamaño exacto 1 byte, la aritmética avanza byte a byte secuencialmente:
```c
void asignaCeros(void * dir, int cant) {
    for (int i = 0; i < cant; i++) {
        *(((char *)dir) + i) = 0; // CORRECTO: casteo a char* para operar a nivel de bytes
    }
}
```

Aunque en la práctica habitualmente utilicemos funciones de la biblioteca estándar para este fin (como `memset` de `<string.h>`), comprender el comportamiento interno del puntero a `void` es fundamental para el manejo de interfaces genéricas en C.

>[!INFO] Aritmética de Punteros
>Cuando sumamos `1` a un puntero de tipo `int *` (`p + 1`), el compilador no avanza un único byte, sino el tamaño en memoria que ocupa dicho tipo (típicamente `sizeof(int)`, es decir, 4 bytes). Por esta razón, si se desea avanzar byte a byte de forma unitaria en la memoria (por ejemplo, para procesar un número determinado de bytes contiguos), es indispensable castear la dirección a un puntero a carácter (`char *`).

## Heap

El **Heap** forma parte del espacio de memoria asignado a un proceso (programa en ejecución) por el sistema operativo. Se fracciona en forma dinámica en bloques de distintos tamaños cada vez que el programa solicita un bloque mediante la invocación a `malloc`.
![[Pasted image 20260726222514.png|center|472]]

A continuación se presenta un ejemplo de uso completo con verificación de memoria y liberación:
```c
#include <stdlib.h>
#include <errno.h>
#include <stdio.h>

int * arrDin;

/* Crea dinámicamente un arreglo de 10 enteros */
errno = 0;
arrDin = malloc(10 * sizeof(int));

if (arrDin != NULL) { /* O también validando errno != ENOMEM */
    /* Almacena el valor 12 en la 2da. posición */
    arrDin[1] = 12;
    
    /* Almacena el valor 18 en la 3ra. posición */
    *(arrDin + 2) = 18;
    
    /* Imprime el valor de la 3ra. posición */
    printf("El 3er. valor es %d\n", arrDin[2]);
    
    /* Libera el arreglo cuando deja de usarlo */
    free(arrDin);
}
```

En este caso, una vez asignado, la forma de indexar y operar sobre los elementos es análoga a la de un arreglo estático `arrDin[10]`. La diferencia fundamental radica en que, al haber reservado esos 10 "lugares" en el Heap, es responsabilidad del programador liberarlos con `free()` al finalizar su uso.

Resumiendo las diferencias de declaración e implementación:
- **Estático:** `int v[SIZE];` (asignado en el Stack o segmento de datos, con tamaño fijo en tiempo de compilación).
- **Dinámico:** `int * v;` operado mediante `malloc`, `calloc`, `realloc` y `free` (asignado en el Heap en tiempo de ejecución).

Si conocemos de antemano la cantidad máxima fija de elementos que vamos a utilizar, conviene usar un arreglo **estático** por simplicidad y rendimiento. Si, en cambio, trabajamos con datos de tamaño variable o estructuras cuya dimensión se define en tiempo de ejecución (por ejemplo, cuando nos pasan una secuencia que finaliza con una marca como `-1`), resulta necesario utilizar asignación **dinámica**.

## Función `malloc`

La función `malloc` (declarada en `<stdlib.h>`) retorna la dirección de inicio de una zona de memoria de `size` bytes reservada en forma dinámica en el **heap**. Si no hay memoria libre suficiente, la asignación falla, la función retorna `NULL` y setea la variable global `errno` en `ENOMEM`.

Por su parte, la función `free` libera el bloque de memoria previamente asignado dinámicamente que comienza en la dirección `p`.

Sus firmas son:
```c
typedef unsigned int size_t; // Tipo sin signo utilizado para tamaños de bloques de memoria

void * malloc(size_t size);
void free(void * p);
```

Lo que hace `malloc()` es básicamente buscar espacio en el Heap y devolver un puntero de tipo `void *` apuntando al inicio del bloque de memoria reservado. A diferencia del Stack, la memoria asignada en el heap **NO** se libera automáticamente al terminar el ámbito de una función. Si realizamos constantes reservas con `malloc()` sin liberar la memoria que ya no se utiliza, nos terminaremos quedando sin espacio disponible (un problema conocido como fugas de memoria o _memory leaks_).

Por este motivo, cuando dejamos de necesitar un vector o estructura dinámica, debemos liberar ese espacio invocando a `free()`, pasándole como argumento la dirección exacta del comienzo del bloque. No es posible pasarle a `free()` un puntero desplazado que apunte al "medio" de una asignación; si lo hacemos, el programa abortará la ejecución por un error de gestión de memoria (_invalid free_ / _segmentation fault_).

Una forma de realizar la verificación es evaluando si el valor de retorno es `NULL` (o bien chequeando `errno`):
```c
int * vec = malloc(100 * sizeof(int));

if (vec == NULL) {
    // Manejo del error en caso de falta de memoria (por ejemplo, abortar o retornar un código de falla)
}
```

O comprobando directamente la variable de entorno de errores:
```c
if (errno == ENOMEM) {
    // Acciones a realizar si no hay memoria disponible
}
```

## Función `calloc`

La función `calloc` (declarada en `<stdlib.h>`) retorna la dirección de una zona de memoria de `size * nobj` bytes reservada en forma dinámica e inicializada en cero.

Hace lo mismo que `malloc`, pero además recorre el bloque asignado y lo llena con ceros. El parámetro `size_t nobj` indica la cantidad de elementos que se van a reservar, mientras que `size_t size` es el tamaño en bytes de cada elemento.
```c
void * calloc(size_t nobj, size_t size);
void * realloc(void * p, size_t size);
```

La función `realloc` modifica el tamaño de una zona de memoria previamente reservada que comienza en la dirección `p`. Si el puntero `p` es `NULL`, se comporta exactamente igual que un `malloc(size)`.

Es obligatorio pasarle como argumento la dirección exacta del comienzo de un bloque. Al redimensionar hacia arriba (por ejemplo, si tenemos un bloque de 40 bytes y queremos llevarlo a 60 bytes en total):
- Si hay suficiente espacio contiguo a continuación del bloque original, extiende la memoria directamente en esa misma posición.
- Si no hay espacio contiguo porque hay otro bloque ocupado a menor distancia, busca un nuevo bloque de 60 bytes en otra ubicación del heap, copia automáticamente el contenido del bloque viejo al nuevo y libera la dirección previa de `p`.

Es fundamental tener en cuenta que a `realloc` NO le pasamos la cantidad de bytes a agrandar/sumar, sino el tamaño total nuevo deseado.

Si invocamos `realloc()` pero no queda memoria libre suficiente en el Heap, la función devuelve `NULL` y deja el bloque original `p` intacto sin modificar ni liberar. Por esta razón, nunca debemos asignar el retorno de `realloc` directamente sobre el mismo puntero original (`p = realloc(p, new_size)`), ya que si falla perderíamos la referencia al bloque original provocando un _memory leak_. Lo correcto es utilizar un puntero auxiliar:
```c
void * aux = realloc(p, nuevo_tamaño);
if (aux != NULL) {
    p = aux;
} else {
    // Manejo de error: p sigue apuntando a la memoria original
}
```

Si utilizamos `realloc` para achicar el tamaño de un bloque, la operación no fallará. Nos sirve pues representa la única manera de liberar el espacio sobrante que no estamos utilizando al final de un arreglo dinámico, ya que a `free()` únicamente se le puede pasar el inicio de un bloque.

Si queremos hacer que el usuario ingrese nombres de distintas longitudes y guardarlos eficientemente en memoria dinámica, una estrategia habitual consiste en declarar un vector estático temporal para recibir la entrada y luego reservar la memoria justa:
```c
#define LENGTH 100

char buffer[LENGTH + 1]; // +1 para alojar el delimitador nulo '\0'
printf("Ingrese un nombre: ");
scanf("%100s", buffer);

// Reservamos exactamente la cantidad de bytes necesarios para el string
char * nombre = malloc(strlen(buffer) + 1);
if (nombre != NULL) {
    strcpy(nombre, buffer);
}
```

Esta técnica presenta una pequeña desventaja de rendimiento al recorrer dos veces la cadena (una para escribirla en el búfer y otra para copiarla con `strcpy`), pero nos permite alocar la cantidad exacta de memoria que requiere cada string ingresado.

Debemos tener cuidado con reasignar punteros dinámicos a constantes literales. Es un error grave hacer lo siguiente:
```c
char * s = malloc(20);
s = "Bowser"; // ¡ERROR!
```

Al ejecutar `s = "Bowser"`, el puntero `s` deja de apuntar a la memoria dinámica reservada en el Heap con `malloc` y pasa a apuntar a la dirección de la constante literal `"Bowser"` en el segmento de solo lectura. Esto provoca la pérdida irreversible del puntero a la memoria del Heap, generando una fuga de memoria (_memory leak_) e impidiendo hacer un posterior `free(s)` (lo cual abortaría la ejecución del programa).

Para copiar una cadena dentro de la memoria asignada dinámicamente, se debe utilizar siempre `strcpy` o `strncpy`:
```c
char * s = malloc(20);
if (s != NULL) {
    strcpy(s, "Bowser"); // Copia los caracteres dentro del espacio reservado en el Heap
}
```

## Bloques

Para obtener la **intersección de dos vectores** ordenados y sin repetidos, existen distintas estrategias para gestionar la asignación de memoria del resultado:
```c
int * interseccion(const int v1[], size_t dim1, const int v2[], size_t dim2) {
    int * resp = NULL;
    int i = 0, j = 0, k = 0;

    for (i = 0, j = 0, k = 0; i < dim1 && j < dim2; ) {
        if (v1[i] < v2[j]) {
            i++;
        } else if (v1[i] > v2[j]) {
            j++;
        } else {
            // Son iguales: forma parte de la intersección
            // ...
            i++;
            j++;
        }
    }
    return resp;
}
```

Para almacenar los elementos coincidentes en `resp`, se pueden evaluar distintas alternativas:
1. `realloc` por cada elemento: Ineficiente, ya que redimensiona y potencialmente traslada el bloque de memoria en cada inserción.
2. `malloc` inicial con el tamaño máximo posible (`MIN(dim1, dim2)`): Puede desperdiciar memoria si la intersección resulta ser mucho menor que el tamaño reservado.
3. Asignación por bloques: Es la estrategia óptima que **SIEMPRE** se debe utilizar cuando no se conoce de antemano la cantidad exacta de elementos a guardar.

La estrategia por **bloques** consiste en definir una cantidad fija de elementos por bloque (`BLOQUE`) e ir ampliando la memoria en el heap únicamente cuando se complete la capacidad actual.

Sabemos que un bloque se llenó cuando el índice de elementos guardados cumple `k % BLOQUE == 0`. Cada vez que ocurre esto, se invoca `realloc` para ampliar el vector en un bloque completo, solicitando un tamaño total de `(k + BLOQUE) * sizeof(int)`. Si todavía queda espacio disponible en el bloque actual, simplemente se guarda el elemento en `resp[k++]`.

Es importante inicializar el puntero `resp = NULL`, ya que el primer `realloc(NULL, ...)` actuará internamente como un `malloc`.

El código completo aplicando `realloc` por bloques y ajuste final queda estructurado de la siguiente forma:
```c
#define BLOQUE 10

int * interseccion(const int v1[], size_t dim1, const int v2[], size_t dim2, size_t * dimResp) {
    int * resp = NULL;
    int * aux;
    size_t i = 0, j = 0, k = 0;

    while (i < dim1 && j < dim2) {
        if (v1[i] < v2[j]) {
            i++;
        } else if (v1[i] > v2[j]) {
            j++;
        } else {
            // Se encontró un elemento en común
            if (k % BLOQUE == 0) {
                aux = realloc(resp, (k + BLOQUE) * sizeof(int));
                if (aux == NULL) {
                    free(resp);
                    *dimResp = 0;
                    return NULL;
                }
                resp = aux;
            }
            resp[k++] = v1[i];
            i++;
            j++;
        }
    }

    // Ajuste final: si sobró espacio en el último bloque, redimensionamos al tamaño exacto k
    if (k > 0) {
        aux = realloc(resp, k * sizeof(int));
        if (aux != NULL) {
            resp = aux;
        }
    }

    *dimResp = k;
    return resp;
}
```

No hace falta validar casos especiales si la intersección resulta vacía: si no se encuentra ninguna coincidencia, `resp` se mantiene en `NULL`, la función retorna `NULL` y `dimResp` se asigna en `0` de forma limpia y consistente.
