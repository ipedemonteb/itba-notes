## Definición

Ya terminamos con todos los temas propios del lenguaje C. Cuando desarrollamos un programa, tenemos que pensar que de la interfaz o *front-end* se va a encargar otra persona, mientras que nosotros nos ocupamos de la lógica y de hacer todas las validaciones necesarias. Por ejemplo, en un juego de ajedrez, otra persona se encargará de detectar dónde hace click el usuario y hacia dónde intenta mover, mientras que nosotros nos encargamos de validar que dicho movimiento sea efectivamente válido según las reglas del juego.

Siguiendo con el caso del ajedrez, la función `jugar()` junto con el resto de las validaciones estarían declaradas en el archivo de cabecera `chess.h`. En ese mismo encabezado podríamos llegar a incluir la definición de los `struct` de cada jugador, con su tablero, nombre, historial de jugadas, etc. Sin embargo, esto presenta un problema importante: al tener acceso directo a la estructura de datos, el *front-end* podría modificar sus campos arbitrariamente (por ejemplo, para hacer trampa o alterar el estado interno del juego). Esto resulta sumamente peligroso. La estructura interna de los datos debería permanecer oculta, de modo que la capa superior no tenga acceso a ella ni sepa cómo está implementada por dentro.

Para resolver esto se utilizan los **Tipos Abstractos de Datos (TAD)**, los cuales sirven para ocultar aquellos componentes internos que no deben ser manipulados directamente desde afuera. Si el *front* necesita consultar el estado de una pieza, no podrá recorrer el tablero accediendo a la estructura por su cuenta, sino que deberá invocar a una función pública de la interfaz que le retorne únicamente la información solicitada.

Dicho de forma más formal, el TAD es una técnica que fomenta la construcción de módulos con semántica clara (evitando que el cliente tenga que lidiar con los detalles de las estructuras de datos), buscando lograr alta cohesión y bajo acoplamiento. El uso de TADs representa el paso previo a la Programación Orientada a Objetos. Aunque el lenguaje C no ofrece construcciones sintácticas nativas para el control de acceso (como visibilidad `private` o palabras reservadas de clases), este concepto se implementa mediante el uso de estructuras opacas en los archivos `.h` y `.c`.

---
## Características

Una de las características fundamentales del TAD es el **ocultamiento de la información** (_hiding_). Esto significa que se ocultan los detalles de implementación de la entidad, tomando únicamente lo relevante para resolver el problema. Para lograrlo, se establece un contrato que define las únicas operaciones a través de las cuales el usuario podrá interactuar con el TAD, funcionando esencialmente como una caja negra.

Para ocultar la estructura interna al usuario utilizamos **punteros a `struct`**. Si definiéramos el `struct` directamente dentro de `chess.c`, al código del usuario no le compilaría porque no conocería la estructura. Si por el contrario lo pusiéramos completo en el archivo `.h`, el usuario podría acceder a sus campos directamente y modificar su contenido. La solución consiste en declarar en el `.h` un puntero a una estructura incompleta (`typedef struct dateCDT * dateADT;`) y postergar la definición real del `struct` para el archivo de implementación `.c`.

---
## Implementación

Tomemos como ejemplo un TAD para el manejo de fechas, el cual ofrecerá operaciones como crear una fecha, eliminarla, modificar un día o convertirla a texto:
- Nombre del TAD: `dateADT` (por _Abstract Data Type_)
- Archivos del TAD: `dateADT.h` (interfaz) y `dateADT.c` (implementación)
- Estructura subyacente en la interfaz (`.h`): Puntero a struct con sufijo CDT (`struct dateCDT * dateADT`)
- Estructura subyacente en la implementación (`.c`): Definición completa de `struct dateCDT { ... };`

Veamos cómo quedarían desarrollados los archivos:
```c
// dateADT.h
typedef struct dateCDT * dateADT;

dateADT newDate(unsigned char day, unsigned char month, unsigned int year);
void freeDate(dateADT date);
int setDay(dateADT date, int day);
void dateToString(const dateADT date, char s[]);
```

```c
// dateADT.c
#include <stdio.h>
#include <stdlib.h>
#include "dateADT.h"

struct dateCDT {
    unsigned char day;
    unsigned char month;
    unsigned int year;
};

dateADT newDate(unsigned char day, unsigned char month, unsigned int year) {
    if (/* parámetros inválidos */)
        return NULL;

    dateADT d = malloc(sizeof(struct dateCDT));
    if (d == NULL)
        return NULL;

    d->day = day;
    d->month = month;
    d->year = year;
    return d;
}
```

Cuando hacemos una función auxiliar como `isValid()` para validar los parámetros, la implementamos dentro de `dateADT.c` y la declaramos como `static int isValid(...)`. Usamos `static` porque es una función privada que el usuario no tiene por qué ver; además, `static` la oculta del enlazador (_linkeditor_), evitando conflictos si el usuario luego declara en su programa una función con el mismo nombre.

Seguimos desarrollando las funciones dentro de `dateADT.c`:
```c
void freeDate(dateADT date) {
    free(date);
}

int setDay(dateADT date, int day) {
    if (/* día no es válido */)
        return 0;

    date->day = day;
    return 1;
}
```

En funciones como `setDay` o `freeDate`, no hay que perder tiempo validando si el parámetro `date` es distinto de `NULL`. En el diseño de TADs se asume que el usuario pasa una instancia válida obtenida previamente mediante `newDate`.

Por último, para la representación en texto:
```c
void dateToString(const dateADT date, char s[]) {
    sprintf(s, "%02d/%02d/%d", date->day, date->month, date->year);
}
```

En este último caso, si el programa ya está en producción y lo utilizan otros desarrolladores, no se puede cambiar el prototipo de las funciones existentes. Si por ejemplo quisiéramos agregar el formato de EE. UU. (donde el mes va antes que el día), deberíamos agregar una función nueva en la interfaz en lugar de modificar los parámetros o alterar el comportamiento de la función original.

El `main` del usuario quedaría organizado de la siguiente manera:
```c
#include <stdio.h>
#include "dateADT.h"

int main(void) {
    dateADT f1, f2;

    f1 = newDate(10, 3, 2020);
    f2 = newDate(30, 2, 2020); // Retorna NULL porque el 30 de febrero es una fecha inválida

    setDay(f1, 15); // Retorna 1 (éxito)
    setDay(f1, 40); // Retorna 0 (falla por día inválido)

    return 0;
}
````
![[Pasted image 20260731112737.png|192]]
Si quisiéramos hacer dentro del `main` una asignación directa como `f1->dia = 40;`, el programa no va a compilar. Como la estructura `struct dateCDT` está oculta dentro del archivo `.c`, el compilador no conoce sus campos al procesar el programa del usuario. Por lo tanto, no queda otra alternativa para modificar `f1` o `f2` que utilizar las funciones declaradas en el `.h`. Esto nos obliga a diseñar una biblioteca completa, dado que el usuario no puede crear sus propias funciones para manipular la información interna de la fecha.

Veamos otro ejemplo: crear un Tipo Abstracto de Datos (TAD) para el manejo de una pila (_stack_) de enteros. Las operaciones principales que debemos considerar son:
- `newStack`: Crea e inicializa la pila.
- `freeStack`: Libera la memoria consumida por la pila.
- `isEmpty`: Indica si la pila está vacía.
- `push`: Inserta un elemento en el tope.
- `pop`: Devuelve el elemento del tope y lo remueve.
- `peek` (opcional): Devuelve el número de más arriba sin removerlo (equivale a hacer un `pop` seguido de un `push`).
- `isFull` (opcional): En pilas con tamaño fijo devuelve 1 al alcanzar la capacidad máxima. Al implementar un _stack_ dinámico sin límite, esta función no es necesaria.

Para este _stack_ sin límite, primero definimos los prototipos de las funciones que ofreceremos en la interfaz:
```c
stackADT newStack(void);
void freeStack(stackADT stack);
int isEmpty(const stackADT stack);
void push(stackADT stack, int value);
int pop(stackADT stack);
```

Ahora viene la parte más importante, que es elegir la estructura de datos adecuada. Podemos implementarlo mediante un vector dinámico o mediante una lista enlazada. Si usamos una lista, cada `push` inserta un nuevo nodo al principio. Si usamos un vector dinámico, agregamos los elementos al final.![[Pasted image 20260731113257.png|351]]

En el caso del vector, la estructura necesita almacenar el puntero al arreglo dinámico y su dimensión. Ambas opciones tienen sus ventajas y desventajas; con una lista tendríamos un `struct stackCDT` apuntando al primer nodo y un `struct node` por cada elemento. Vamos a implementarlo primero con un vector dinámico, que es una estructura con la que tenemos más práctica.

En el archivo de interfaz `.h`:
```c
typedef struct stackCDT * stackADT;
```

En el archivo de implementación `.c`:
```c
struct stackCDT {
    int * v;
    size_t dim;  // Cantidad de elementos actualmente almacenados
    size_t size; // Espacio total reservado en memoria
};
```

Declaramos el campo `size` para poder realizar la realocación de memoria (`realloc`) por bloques. El campo `dim` lleva la cuenta de cuántos elementos hay guardados y `size` registra la capacidad total disponible. Agregamos un nuevo bloque cuando `dim == size`, incrementando el valor de `size` según la cantidad de lugares que tenga el bloque. Definimos la constante del bloque al inicio del archivo:
```c
#define BLOQ 20
```

Programamos las funciones dentro del archivo `.c`:
```c
#include <stdlib.h>
#include "stackADT.h"

stackADT newStack(void) {
    return calloc(1, sizeof(struct stackCDT));
}

int isEmpty(const stackADT stack) {
    return stack->dim == 0;
}

void freeStack(stackADT stack) {
    free(stack->v);
    free(stack);
}

void push(stackADT stack, int value) {
    if (stack->dim == stack->size) { // Significa que el vector está lleno
        stack->v = realloc(stack->v, (stack->size + BLOQ) * sizeof(stack->v[0]));
        stack->size += BLOQ;
    }
    stack->v[stack->dim++] = value;
}

int pop(stackADT stack) {
    if (isEmpty(stack)) {
        exit(1);
    }
    return stack->v[--stack->dim];
}
```

En la función `push`, al usar `sizeof(stack->v[0])`, si más adelante se cambia el tipo del arreglo `v`, no hace falta modificar la invocación a `sizeof`. Además, al agrandar la memoria se debe actualizar el tamaño asignado sumando el bloque (`stack->size += BLOQ;`).

En la función `pop`, la expresión con pre-decremento `--stack->dim` le resta 1 a la dimensión antes de acceder al vector. De esta forma, decrementa el contador de elementos y accede directamente al índice correspondiente al tope de la pila.

¿Qué cambios podemos hacer en los archivos? En el `.h` podemos agregar prototipos de funciones públicas. En el `.c` (sin modificar el `.h`) podemos hacer cualquier cambio interno de implementación.

Ahora vamos a volver a implementar el TAD de stack, pero utilizando listas enlazadas en lugar de vectores dinámicos. Para esto definimos un `CDT` que contenga un puntero al primer nodo, y luego cada nodo apuntará al siguiente. La estructura de la lista se define dentro del `.c` para que el usuario no pueda verla ni acceder a sus campos:
```c
typedef struct node {
    int head;
    struct node * tail;
} node;

struct stackCDT {
    node * first;
};
````

La idea del programa es la siguiente:![[Pasted image 20260731113530.png|206]]

El campo `first` del CDT va a apuntar siempre al elemento superior del stack. Al hacer un `push`, insertamos el nuevo nodo al principio de la lista haciendo que apunte al que antes era el primero. De esta forma evitamos tener que recorrer toda la lista para encontrar el tope de la pila.

Desarrollamos las funciones en el `.c`:
```c
stackADT newStack(void) {
    return calloc(1, sizeof(struct stackCDT));
}
```

Usar `calloc` nos devuelve un puntero a la estructura con sus campos inicializados en cero, por lo que `first` queda automáticamente apuntando a `NULL`. Esto es mucho más limpio que pedir memoria con `malloc` e inicializar a mano los campos.

Seguimos con la función para verificar si la pila está vacía:
```c
int isEmpty(const stackADT stack) {
    return stack->first == NULL;
}
```

Para implementar `push`, no hace falta hacer un manejo especial según si la lista está vacía o no, ya que al insertar al principio el comportamiento es idéntico. En este caso utilizamos `malloc` directamente para pedir memoria para el nodo, dado que vamos a inicializar todos sus campos inmediatamente:
```c
void push(stackADT stack, int value) {
    node * aux = malloc(sizeof(node));
    if (aux == NULL) {
        return;
    }
    aux->head = value;
    aux->tail = stack->first;
    stack->first = aux;
}
```

Si quisiéramos agregar los elementos al final de la lista en lugar del principio, la operación resultaría ineficiente porque requeriría recorrer toda la estructura (o usar recursividad), lo cual es más propio de una cola.

Para la función `pop`, desreferenciamos el nodo del tope, guardamos el valor que contiene, avanzamos el puntero del CDT al siguiente nodo (`tail`) y liberamos la memoria del nodo removido:
```c
int pop(stackADT stack) {
    if (isEmpty(stack)) {
        exit(1);
    }
    int aux = stack->first->head;
    node * auxNode = stack->first;

    stack->first = stack->first->tail;
    free(auxNode);

    return aux;
}
```

Para destruir completamente el stack y liberar toda la memoria reservada por los nodos, lo hacemos de manera recursiva utilizando una función auxiliar `static` para que no sea accesible desde fuera del archivo `.c`:
```c
static void freeStackRec(node * list) {
    if (list == NULL) {
        return;
    }
    freeStackRec(list->tail);
    free(list);
}

void freeStack(stackADT stack) {
    freeStackRec(stack->first);
    free(stack);
}
```

Si queremos agregar funciones adicionales a la biblioteca, como por ejemplo obtener la cantidad de elementos en el stack, debemos incluir su prototipo en el `.h`. Una forma eficiente de resolver esto es agregar un campo `size_t dim;` dentro de la estructura `struct stackCDT`.

Al agregar `dim`, debemos actualizar `push` para que lo incremente (`stack->dim++`) y `pop` para que lo decremente (`stack->dim--`). La función `newStack` no requiere modificaciones porque `calloc` ya inicializa `dim` en 0. Con este cambio, consultar el tamaño se vuelve una operación directa:
```c
size_t size(const stackADT stack) {
    return stack->dim;
}
```

## Estructuras Genéricas

El ejemplo que vimos antes era para un stack de enteros. Si quisiéramos convertirlo en un stack genérico, podemos definir el tipo de dato mediante un `typedef`:
```c
typedef int elemType;
```

Si quisiéramos que el stack fuera de `double`, simplemente modificamos el `typedef` a `double` y recompilamos el programa. En la versión con lista enlazada (`stackADTList.c`), lo primero que debemos cambiar es la estructura del nodo para que el campo `head` sea de tipo `elemType` en lugar de `int`. En el caso de la función `pop`, también habría que tener en cuenta la liberación o copia de memoria si el tipo fuera una cadena de caracteres u otra estructura dinámica.

Si queremos implementar una función `belongs` para verificar si un elemento pertenece al stack implementado sobre un arreglo dinámico:
```c
int belongs(const stackADT stack, elemType elem) {
    for (int i = 0; i < stack->dim; i++) {
        // Para comparar elementos de tipo elemType no podemos usar el operador ==,
        // ya que elemType podría ser una estructura u otro tipo complejo.
    }
}
```

Por ejemplo, `elemType` podría estar definido como una estructura de coordenadas:
```c
typedef struct {
    double x;
    double y;
} elemType;
```

Como en C no se pueden comparar dos estructuras directamente con `==`, necesitamos una función de comparación. La responsabilidad de definirla es del usuario, ya que él conoce la estructura de los datos y el criterio de igualdad que desea aplicar.

Para guardar este criterio, agregamos un puntero a la función de comparación dentro de la estructura `struct stackCDT`:
```c
struct stackCDT {
    node * first;
    size_t dim;
    int (*compare)(elemType, elemType);
};
```

Luego, modificamos la función `newStack` para que reciba como argumento el puntero a la función de comparación y lo guarde dentro del CDT:
```c
stackADT newStack(int (*compare)(elemType, elemType)) {
    stackADT aux = calloc(1, sizeof(struct stackCDT));
    if (aux == NULL) {
        return NULL;
    }
    aux->compare = compare;
    return aux;
}
```

Con la función de comparación almacenada en la estructura, la función `belongs` para vectores dinámicos queda terminada de la siguiente forma:
```c
int belongs(const stackADT stack, elemType elem) {
    for (int i = 0; i < stack->dim; i++) {
        if (stack->compare(stack->v[i], elem)) {
            return 1;
        }
    }
    return 0;
}
```

Si queremos hacer la función `belongs` para la versión con listas enlazadas, no podemos hacer la llamada recursiva directamente sobre la función principal porque recibe el parámetro de tipo `stackADT` (el encabezado del TAD y no el nodo de la lista). Por este motivo, requerimos una función auxiliar recursiva declarada como `static`:
```c
static int belongsRec(node * list, elemType elem, int (*compare)(elemType, elemType)) {
    if (list == NULL) {
        return 0;
    }
    if (compare(list->head, elem)) {
        return 1;
    }
    return belongsRec(list->tail, elem, compare);
}

int belongs(const stackADT stack, elemType elem) {
    return belongsRec(stack->first, elem, stack->compare);
}
```

Finalmente, dentro del programa principal (`main.c`), el usuario debe implementar la función con el criterio de comparación. Para el caso de la estructura con coordenadas `x` e `y`:
```c
int cmpStruct(elemType e1, elemType e2) {
    return e1.x == e2.x && e1.y == e2.y;
}
```

Esta función retorna `1` si las coordenadas son idénticas y `0` en caso contrario, sirviendo para comparar las estructuras del tipo definido.

Ahora vamos a hacer un TAD para listas ordenadas. Primero armamos el archivo de interfaz `.h` de manera similar a como hicimos con el stack:
```c
// La función compare devuelve:
// < 0 si e1 debe estar antes que e2 (aka e1 < e2)
// > 0 si e1 debe estar después que e2 (aka e1 > e2)
// 0 si son iguales
typedef int (*compare)(elemType e1, elemType e2);

listADT newList(compare cmp);
void freeList(listADT list);
```

La función `addList` la podemos definir para que devuelva un `int`, retornando `1` si logró agregar el elemento o `0` si no pudo (por ejemplo, si ya existía en la lista o si falló la reserva de memoria). No hace falta volver a pasarle la función `compare` como parámetro a `addList`, ya que el criterio de comparación se guarda en el TAD al momento de llamar a `newList`; de lo contrario, se podría cambiar el criterio a mitad de camino y romper el orden de la lista:
```c
int addList(listADT list, elemType elem);
int sizeList(const listADT list);
int isEmptyList(const listADT list);
int belongsList(const listADT list, elemType elem);
```

Ahora podemos armar el archivo de implementación `listADT.c`. Lo primero que debemos definir es la estructura del nodo y la del CDT:
```c
typedef struct node {
    elemType head;
    struct node * tail;
} node;

typedef node * TList;

struct listCDT {
    TList first;
    size_t size;
    compare cmp;
};
```

Como detalle importante para las evaluaciones: en un examen nos pueden dar el `.h` y pedirnos que implementemos únicamente un par de funciones (por ejemplo, `add` y `delete`). Si nos piden eso, tal vez no usemos el campo `size` directamente dentro de esas dos funciones, pero es fundamental que el campo permanezca en la estructura del CDT para mantener la consistencia con el resto de la biblioteca.

Comenzamos a programar las funciones dentro de `listADT.c`:
```c
listADT newList(compare cmp) {
    listADT aux = malloc(sizeof(struct listCDT));
    if (aux == NULL) {
        return NULL;
    }
    aux->size = 0;
    aux->first = NULL;
    aux->cmp = cmp;
    return aux;
}

static void freeListRec(TList list) {
    if (list == NULL) {
        return;
    }
    freeListRec(list->tail);
    free(list);
}

void freeList(listADT list) {
    freeListRec(list->first);
    free(list);
}

int isEmptyList(const listADT list) {
    return list->first == NULL;
}

size_t sizeList(const listADT list) {
    return list->size;
}
```

Para implementar la función `belongsList` de forma iterativa, aprovechamos que la lista se encuentra ordenada. Iteramos mientras no lleguemos al final y el elemento del nodo actual sea menor o igual al buscado. Si el resultado del comparador es `0`, el elemento pertenece a la lista; si nos pasamos (resultado mayor a `0`), cortamos la búsqueda antes porque sabemos que no estará más adelante:
```c
int belongsList(const listADT list, elemType elem) {
    TList aux = list->first;
    int c;
    while (aux != NULL && (c = list->cmp(aux->head, elem)) <= 0) {
        if (c == 0) {
            return 1;
        }
        aux = aux->tail;
    }
    return 0;
}
```

Al guardar el resultado de `list->cmp` en la variable `c`, logramos ahorrar una llamada de comparación por cada iteración del ciclo.

Ahora implementamos la función `belongsList` de manera recursiva. Como la función de la interfaz recibe la estructura `listADT`, necesitamos una función auxiliar recursiva (`static`) que reciba el puntero al nodo (`TList`):
```c
static int belongsListRec(TList list, elemType elem, compare cmp) {
    if (list == NULL || cmp(list->head, elem) > 0) {
        return 0;
    }
    if (cmp(list->head, elem) == 0) {
        return 1;
    }
    return belongsListRec(list->tail, elem, cmp);
}

int belongsList(const listADT list, elemType elem) {
    return belongsListRec(list->first, elem, list->cmp);
}
```

En la función auxiliar `belongsListRec`, la condición `cmp(list->head, elem) > 0` evalúa si el elemento del nodo actual es mayor al buscado; si esto ocurre, cortamos la recursión devolviendo `0` dado que la lista está ordenada. Además, la llamada recursiva pasa el siguiente nodo (`list->tail`) invocando a `belongsListRec`.

Nuevamente podemos guardar el resultado de la comparación en una variable local `c` para evitar llamadas repetidas a la función `cmp`:
```c
static int belongsListRec(TList list, elemType elem, compare cmp) {
    int c;
    if (list == NULL || (c = cmp(list->head, elem)) > 0) {
        return 0;
    }
    if (c == 0) {
        return 1;
    }
    return belongsListRec(list->tail, elem, cmp);
}
```

Ahora seguimos con el desarrollo de la función `addList()`. No la podemos hacer directamente recursiva porque recibe la estructura `listADT`, por lo que necesitamos una función auxiliar recursiva que opere sobre los nodos (`TList`). Como el primer elemento de la lista puede cambiar (por ejemplo, al insertar un valor menor al actual primer elemento), asignamos el resultado de la llamada recursiva a `list->first`.

Para devolver `1` si el elemento se agregó o `0` si no se pudo agregar (o ya existía) e incrementar la dimensión `size`, realizamos la lógica dentro de `addList` y no dentro de la función recursiva. Usamos una variable local `flag` que le pasamos por referencia a la función auxiliar. Si logra insertar el elemento, la función recursiva asigna `*flag = 1`. Como solo se inserta un nodo por llamada, podemos actualizar la dimensión haciendo directamente `list->size += flag`:
```c
int addList(listADT list, elemType elem) {
    int flag = 0;
    list->first = addListRec(list->first, elem, list->cmp, &flag);
    list->size += flag;
    return flag;
}
```

La función auxiliar `addListRec` se encarga de recorrer recursivamente la lista e insertar el elemento en la posición ordenada que le corresponde:
```c
static TList addListRec(TList list, elemType elem, compare cmp, int * flag) {
    int c;
    if (list == NULL || (c = cmp(list->head, elem)) > 0) {
        TList aux = malloc(sizeof(struct node));
        if (aux == NULL) {
            return list;
        }
        aux->head = elem;
        aux->tail = list;
        *flag = 1;
        return aux;
    }
    if (c < 0) {
        list->tail = addListRec(list->tail, elem, cmp, flag);
    }
    return list;
}
```

Ahora programamos la función `get`, la cual permite consultar el elemento ubicado en un determinado índice del TAD. Lo primero que hacemos es validar que el parámetro `idx` pasado por el usuario no sea mayor o igual al tamaño actual de la lista (`size`):
```c
elemType get(const listADT list, size_t idx) {
    if (idx >= list->size) {
        exit(1);
    }
    return getRec(list->first, idx);
}

static elemType getRec(TList list, size_t idx) {
    if (idx == 0) {
        return list->head;
    }
    return getRec(list->tail, idx - 1);
}
```

## Iteradores

Si hiciéramos un ciclo para recorrer e imprimir toda la lista utilizando llamadas sucesivas a `get`, en cada iteración la función tendría que volver a recorrer la lista desde el primer nodo hasta llegar al elemento deseado. Esto resulta ineficiente, ya que se repite la caminata nodo por nodo en cada llamado. Para solucionarlo y recorrer la lista de manera eficiente sin exponer la estructura interna al usuario, utilizamos **iteradores**.

Para esto, la interfaz del TAD ofrece tres funciones específicas:
```c
// Le avisamos al TAD que vamos a empezar a recorrer la lista desde el principio
void toBegin(listADT list);

// Devuelve 1 (true) si queda algún elemento pendiente por recorrer o 0 (false) al llegar al final
int hasNext(const listADT list);

// Devuelve el elemento actual y avanza el puntero al siguiente
elemType next(listADT list);
```

El usuario utilizará el iterador dentro de su programa de la siguiente manera:
```c
printf("----\n");
toBegin(myList);
while (hasNext(myList)) {
    printf("%s\n", next(myList));
}
```

Esta alternativa es mucho más eficiente que usar `get`. Para poder soportarla, debemos modificar la estructura `struct listCDT` agregando un puntero `next` que guarde la dirección del nodo sobre el cual está parado el iterador:
```c
struct listCDT {
    TList first;
    size_t size;
    compare cmp;
    TList next;
};
```

Con la estructura actualizada, programamos las tres funciones del iterador en el archivo `.c`:
```c
void toBegin(listADT list) {
    list->next = list->first;
}

int hasNext(const listADT list) {
    return list->next != NULL;
}

elemType next(listADT list) {
    if (!hasNext(list)) {
        exit(1);
    }
    elemType aux = list->next->head;
    list->next = list->next->tail;
    return aux;
}
```

De tarea nos queda pendiente agregar la función `remove`.

A continuación, analizamos un ejercicio de la guía donde debemos implementar un `arrayADT` para representar un vector que en principio tiene dimensión "infinita" o ilimitada. Para diseñar la estructura del CDT, agregamos el vector de elementos (`values`), el tamaño reservado (`size`), la función de comparación (`cmp`) y un arreglo auxiliar de tipo `char *` (`used`) donde guardaremos un flag (`1` o `0`) para saber si cada posición del arreglo está realmente ocupada:
```c
struct arrayCDT {
    elemType * values;
    size_t size;
    compare cmp;
    char * used;
};
```

Utilizar un vector de `char` para registrar qué posiciones están en uso tiene sus ventajas y desventajas: nos permite saber de manera eficiente si un índice contiene un elemento válido sin depender de un valor centinela en `elemType`, pero requiere administrar y reasignar dos vectores dinámicos simultáneamente en memoria.
