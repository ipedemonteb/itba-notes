## Diseño de Interfaces

Tenemos que tener en claro la diferencia entre una interfaz usable y una "linda". Para la materia vamos a querer una interfaz usable, sin tanta componente de diseño.

En la materia vamos a usar CSS porque sigue siendo la principal herramienta de estilo. Los frameworks modernos lo utilizan como base de styling. Por otro lado, presentan cierta flexibilidad de uso:
- Se puede usar un grid system.
- Se puede usar un sistema más flexible.

Es importante saber usarlo porque es donde va a recaer todo. Si sabemos css, sabemos todo. Los superscripts mejoran aún más la experiencia. Es como un lenguaje por sobre un lenguaje (lo vamos a ver más al final).

Como vimos en HCI, funciona sobre un box system en cascada:
- De menos específico hasta más específico.
- Usamos `!important` para pisar estilo de libs.
- NUNCA usamos estilo en HTML salvo excepciones (como tailwind).

## UI Kit vs Framework

Todo lo que es el mundo Javascript, es muy dinámico y se cambia cada 15 días. Hay muchos frameworks que no nos van a servir porque no son compatibles con lo que vamos a usar. Por ejemplo, todo lo que trabaje sobre una Single Page Application, no nos va a servir para la primera parte. Sí vamos a tener compatibilidad con las componentes que nos dan el CSS y el HTML. Lo que se recomienda, es buscar componentes como por ejemplo botones.

## Java Server Pages

En Spring, todos los objetos que se agregan al front deben ser de formato `Bean`, un objeto de Java. Las condiciones son:
- Todas las propiedades son privadas (usar `getters`/`setters` con la convención estándar de nombres).
- Un constructor público sin argumentos.
- Implementa `Serializable`.

**Java Server Pages (JSP)** es una tecnología que permite combinar HTML estático con contenido dinámico. Las páginas JSP se traducen automáticamente a servlets que luego se compilan. Además, JSP establece una serie de primitivas básicas que permiten hacer operaciones como iteraciones.

La primitiva page define varias cosas de cómo se muestra el contenido. Permite definir el valor de ciertos headers e indicar si se utilizan sesiones.
```jsp
<%@ page contentType="text/html;charset=UTF-8" language="java" %>
```

La primitiva `include` permite insertar en una página código de otra página al momento de la traducción a servlet de la primera. Es similar al `include` de C y sirve para componentes estáticos.
```jsp
<%@ include file="URL relativa" %>
```

Para poder invocar componentes dinámicos creados con jsp, se utiliza el action `include`. 
```jsp
<jsp: include page="relativeURL | expression" />
```
Permite declarar parámetros para el componente
- `<jsp:param name="parametername" value="parametervalue | expression" />`
- Dentro del page, se accede mediante param.parametername

>[!INFO] Diferencia de Directiva y Action `include`
>La diferencia con la directiva `include` es que esta se ejecuta en momento de compilación, se inyecta tal cual está en el otro archivo. La action include permite definir parámetros.

**JSP Expression Language** es un lenguaje que simplifica la forma de acceder a los beans, se usa mediante `${expresion}`:
```html
<h3>Hola ${user.name}</h3>
<h3>Su horóscopo es ${horoscopes[user.birthMonth]}</h3>
<h4>Su muerte será en S{user.age t user.birthMonth} años</h4>
```

**JSP Standard Tag Library (JSTL)** define un conjunto de tags para resolver operaciones comunes. Evita que un archivo JSP contenga código Java y simplifica operaciones comunes. Define además un conjunto de tags estándar, agrupados en:
- core: control de flujo, variables y salida
- `<%@ taglib prefix = "c" uri = "http://java.sun.com/jsp/jstl/core" %>`
- i18n: internacionalización y formato
- functions: funciones para manipulación de colecciones y de strings

Veamos ahora en detalle. Mediante `c:out` podemos imprimir en la salida el resultado de una expresión, y permite **sanitizar** la entrada. Si usamos un `input` y luego imprimimos sin el `c:out`, se pega la entrada directamente, lo que es muy peligroso si por ejemplo se inyecta algo malicioso o simplemente un div que ocupe toda la pantalla.
```html
<hl>Bienvenido ${user.name}"</h1>

<h1>Bienvenido <:out value="${user.name}" />/h1>
```

Por otro lado, el `c:if` evalúa su contenido si la condición es verdadera:
```html
<c:if test="${users. size () > 0}">
	<! -- Show user list -->
</c: if>

<c: if test="$fusers. size () == 0}">
	<p>No se encontraron usuarios</p>
</c: if>
```

Para iteraciones sobre colecciones, podemos usar `forEach`:
```html
<c:if test="${users.size () > O}">
	<ul>
		<c: forEach var="message" items="$ {messages} ">
			<li><c: out value="$ {message}" /></li>
		</c: forEach>
	</ul>
</c: if>
```

Las `c:urls` funcionan para generar una URL, opcionalmente agregando parámetros. Es muy importante usarlo para que funcione cuando se deploye la aplicación. Se encarga de mirar si estamos parados en la posición relativa y no en cualquier lado:
```html
<link rel="stylesheet" href="<c:url value='/resources/css/navbar.css'/>">

<c:url value="/catalog">
    <c:param name="id" value="${book.id}"/>
</c:url>
```
