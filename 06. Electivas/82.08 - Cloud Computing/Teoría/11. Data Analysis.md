## Extract, Transform, Load (ETL)

Ya vimos servicios que nos permiten almacenar, consultar y manipular datos.
![[Pasted image 20260629171336.png|265]]
Ahora, ETL (Extract, Transform, Load) es un proceso batch que levantan datos, los transforman y los vuelven a guardar en otro lado. 

---
## AWS Glue

**AWS Glue** es un servicio serverless de ETL administrado por AWS. Permite preparar y mover datos entre diferentes orígenes y destinos sin necesidad de gestionar infraestructura. Es regional, porque no sabemos donde corre. Ayuda a automatizar la preparación y catalogación de datos. Sus componentes principales son: 
- **Glue Data Catalog**: Define cuál es el esquema de los datos que se tienen. Por ejemplo, en este S3, hay datos que tienen este esquema. Formalmente, Es un metastore centralizado donde se registran los metadatos de las fuentes de datos. Es compatible con Athena, Redshift Spectrum, EMR y Lake Formation. Permite que múltiples servicios accedan a datos en S3 u otras fuentes usando un esquema común.
- **Crawlers**: Analiza toda la data guardada en alguna fuente (S3, Dynamo, etc) y su esquema que después va a guardar en el catalog. Formalmente, son herramientas automáticas que exploran fuentes de datos (ej: S3, RDS, DynamoDB) y detectan esquemas y formatos, y actualizan el Glue Data Catalog automáticamente. Soporta formatos: JSON, Parquet, Avro, CSV, ORC, entre otros.
- **ETL Job**: Hacen las tareas y sincronizan los 3 procesos.
- **Glue Studio**
- **Glue DataBrew**
- **Glue Workflows & Triggers**

![[Pasted image 20260629171459.png|center|110]]

Algunos casos de uso son:
- Data Lake en S3: Ingestar datos crudos en S3, usar Glue Crawlers para catalogarlos, consultarlos con Athena y visualizarlos en QuickSight (interfaz web que permite armar dashboards para perfiles no técnicos).
- ETL hacia Redshift: Transformar datos de logs en S3 y cargarlos en Redshift para BI.
- Integración de múltiples fuentes: Combinar datos de RDS, DynamoDB y S3 en un solo Data catalog.
- Preparación para Machine Learning: Limpieza y normalización de datasets antes de entrenar modelos en SageMaker.

## AWS EMR (Elastic MapReduce)

**AWS EMR** es un servicio para correr map-reduce. Brinda un cluster de cómputo administrado (grupo de instancias EC2) donde se instalan automáticamente las herramientas necesarias para ejecutar cargas de trabajo de análisis de datos, machine learning o transformación masiva de datos. Aumenta o reduce el tamaño del cluster según la carga, pagando solo el cluster de EC2. Soporta múltiples frameworks de big data:
- Apache Spark → procesamiento en memoria, ideal para ETL, ML y análisis.
- Hadoop (MapReduce) → procesamiento batch de grandes datasets.
- Flink → procesamiento de streams en tiempo real.

Puede usar Amazon S3 como almacenamiento.También puede usar HDFS dentro del cluster.
![[Pasted image 20260629171614.png|center|109]]

Usamos EMR para:
- Controlar infraestructura, versiones, y configuración de frameworks como Spark, Hadoop, Hive, Presto, Flink, etc.
- Procesar datasets muy grandes (TBs o PBs) en clusters escalables.
- Ejecutar workloads intensivos en cómputo, batch o streaming, que requieren mucho poder de procesamiento.
- Tener flexibilidad para optimizar costo y rendimiento (elegir tipos de instancias EC2, almacenamiento, red, etc.).
- Correr algoritmos personalizados de machine learning o pipelines complejos que no entran bien en un esquema ETL puro.

## AWS Kinesis

**AWS Kinesis** es un servicio de AWS para ingestión y análisis de datos en tiempo real. Permite capturar, procesar y almacenar flujos de datos a gran escala. Algunos escenarios comunes: IoT, clickstreams de sitios web, logs de aplicaciones, métricas de sistemas, monitoreo en tiempo real. Está compuesto por cuatro modalidades principales.
![[Pasted image 20260629172216.png|center|114]]

La primera modalidad es **Kinesis Data Streams (KDS**), que consiste en un flujo de datos en tiempo real dividido en shards. Permite ingerir datos de miles de fuentes de manera simultánea. Los datos se almacenan temporalmente (por defecto 24 horas, hasta 7 días). Los consumidores (Lambda, EC2, ECS, etc.) pueden procesar los eventos en paralelo. Casos de uso:
- Procesar transacciones financieras en tiempo real.
- Analizar clics en un ecommerce.
- Monitorear logs de servidores.

La segunda es **Kinesis Data Firehose**, que es un servicio serverless fully managed para cargar datos en destinos finales. (Amazon S3, Redshift, OpenSearch, Splunk, Datadog, entre otros). Puede transformar datos en tránsito con Lambda (ej: convertir `JSON` → `Parquet`). Ideal para ETL simplificado en streaming. Casos de uso:
- Enviar logs de aplicaciones directamente a S3 para análisis posterior con Athena.
- Ingestar métricas de IoT en Redshift para visualización en QuickSight.

La tercera es **Kinesis Data Analytics**, que permite consultar y procesar flujos en tiempo real usando SQL o Apache Flink. Con SQL permite hacer consultas sobre streams (ej: detectar anomalías en métricas). Con Flink, soporta análisis avanzado, machine learning en tiempo real, y pipelines complejos. Casos de uso:
- Detectar fraude en transacciones en tiempo real.
- Generar dashboards con métricas de negocio en segundos.
- Alertas automáticas basadas en condiciones detectadas en los datos.

La cuarta es **Kinesis Video Streams**, que está diseñado para ingesta de audio y video en tiempo real. Brinda integración con Amazon Rekognition para análisis de video con inteligencia artificial (ej: detección de objetos, rostros, actividad sospechosa). Casos de uso:
- Monitoreo de cámaras de seguridad.
- Procesamiento de video en IoT (ej: dashcams, drones).
- Aplicaciones de videollamadas o streaming bajo demanda.

## AWS Simple Email Service (SES)

**AWS SES** es un servicio de correo electrónico que ofrece escalabilidad automática y seguridad built-in. Permite enviar, recibir y gestionar correos electrónicos de manera escalable y confiable. Ofrece analíticas y métricas, (seguimiento de entregas, aperturas, quejas). Algunos casos de uso son:
- Confirmaciones de compra
- Restablecimiento de contraseñas
- Campañas de marketing

![[Pasted image 20260629172603.png|center|96]]
Sus mayores ventajas son:
- Escalable y económico (modelo pay-as-you-go, se paga por correo enviado/recibido).
- Alta reputación de IPs → mejor tasa de entrega. El problema que soluciona es que al no recibir respuesta como por ejemplo en los mails de código de verificación, las casillas empiezan a mandar a spam los emails de esas IPs. 
- Flexibilidad (sirve para startups pequeñas y para corporaciones grandes).
- Se integra fácilmente con la infraestructura de AWS existente.

## AWS Redshift Spectrum 

**AWS Redshift Spectrum** es una extensión de Amazon Redshift que permite consultar directamente datos almacenados en S3, sin necesidad de cargarlos al clúster. Usa el mismo motor SQL de Redshift, pero procesa datos externos (en S3) combinados con los internos (en las tablas locales del clúster). Casos de uso:
- Data Lake + Data Warehouse: combinar datos históricos en S3 con datos transaccionales en Redshift.
- Consultas exploratorias: analizar datos crudos en S3 antes de decidir si cargarlos en Redshift.
- Archivos fríos o antiguos: mantener datos viejos en S3 (baratos) y datos recientes en Redshift.

Funciona de la siguiente manera:
1. Los datos crudos o semiestructurados se almacenan en Amazon S3 (por ejemplo, archivos Parquet, CSV o JSON).
2. Esos datos se catalogan en el AWS Glue Data Catalog (que funciona como el metastore).
3. Desde Redshift, se crean tablas externas que apuntan a esos datos en S3.
4. Las consultas SQL pueden combinar datos del almacenamiento interno de Redshift y del S3 externo.

Tomemos el siguiente caso:
```SQL
SELECT s.region, SUM(o.total) AS total_sales
FROM redshift_schema.orders o
JOIN spectrum_schema.sales_data s
    ON o.order_id = s.order_id
WHERE s.date >= '2025-01-01';
```

>[!INFO] Ubicaciones
>`orders` está en Redshift y `sales_data` en S3.
