## Network

Una red es un lugar donde podríamos llegar a instalar máquinas conectadas. En Amazon, se ofrece en formato VPC, que es un fragmento de red que se le ofrece al usuario para que tenga la libertad de levantar las VMs que necesite. Para que los recursos se interconecten, tienen que conocerse, lo que implica primero una presentación mediante IP. 
![[cloud-02-image001.png|center|460]]

>[!INFO] Recordar
>Los rangos de IP sirven para definir redes, o más específicamente subredes, ya que sabemos que la cantidad de direcciones es limitada. La separación se realiza en subredes públicas y privadas. La utilidad de estas subredes es separar responsabilidades.

Vemos en el siguiente caso donde tenemos dos subredes replicadas en zonas de disponibilidad. Vemos que tienen nombre A y B, pero Amazon no revela qué data zone es.
![[cloud-02-image002.png|center|430]]
Como vemos, se puede agregar una o más subredes en cada Zona de Disponibilidad. Las AZs proporcionan aislamiento de fallos, y las subredes se asignan como un subconjunto del rango CIDR de la VPC. 

Algunas recomendaciones:
- VPC /16 o menor de rangos de direcciones IPv4 privadas
- Subredes de al menos /24 (251 direcciones utilizables)
- Utilizar múltiples Zonas de Disponibilidad por VPC mediante múltiples subredes
- Se puede expandir la VPC con mas direcciones

## Subredes

Como dijimos, tenemos subredes públicas y privadas. El VPC se conecta a internet mediante el Internet Gateway, como se ve en la siguiente imagen:
![[02. Networking-1782740605072.png|center|452]]

Una **subred pública** es una subred cuyo tráfico se enruta a un Internet Gateway. Permite el uso de IPs Elásticas y direcciones IP públicas. Además, es útil como infraestructura DMZ para servidores web y ELBs de internet. Las instancias EC2 recibirán una IP privada y una IP pública que se mapea a la privada mediante un NAT.

Una **subred privada** es una subred que NO tiene ruta hacia el Internet Gateway. Puede enrutar indirectamente a Internet a través de una instancia NAT o gateway NAT. Estos dispositivos NAT residen en una subred pública. Esta subred es útil para servidores de aplicaciones y bases de datos. Las instancias EC2 recibirán solo IP privada en el rango de la subred

>[!TIP] Elastic IP
>Como las IPs son escasas, Amazon otorga una **IP elástica** para poder exponer los servicios del usuario, servicio que obviamente se cobra. Para que sea accesible, esa IP tiene que vivir en una subred que permita la conexión.

## Internet Gateway

El **Internet Gateway** es el componente que le da a una VPC la posibilidad de comunicarse con Internet. Se conecta directamente a la VPC y, para que una subred realmente tenga salida o entrada a Internet, además debe estar referenciado en su tabla de ruteo. Por eso una subred pública tiene una ruta hacia el Internet Gateway, mientras que una subred privada no la tiene.

Además, permite la traducción 1 a 1 entre la IP privada de una instancia y su IP pública o Elastic IP, de modo que una EC2 pública pueda ser alcanzada desde Internet y también pueda responder hacia afuera. Es un servicio administrado por AWS, altamente disponible y escalable, por lo que no hay que instalarlo ni mantenerlo como si fuera un servidor aparte.

## NAT Gateway

El **NAT Gateway** permite que las instancias que están en una subred privada puedan salir a Internet sin quedar expuestas para recibir conexiones entrantes desde afuera. Esto es útil, por ejemplo, cuando una máquina necesita descargar actualizaciones, instalar paquetes o consumir APIs públicas, pero no querés que sea accesible directamente desde Internet.

Funciona como un intermediario: la instancia privada envía el tráfico hacia el NAT Gateway, el NAT Gateway reemplaza la IP privada por una Elastic IP pública, y recién ahí el tráfico sale a Internet a través del Internet Gateway. Cuando vuelve la respuesta, el NAT Gateway la redirige correctamente a la instancia privada original. Por eso se dice que habilita solo la salida a Internet, manteniendo la subred privada protegida.
![[02. Networking-1782740944510.png|center|279x357]]

>[!INFO] Trabajo Práctico
>El problema de este mecanismo es que es muy caro de utilizar, entonces es importante en la práctica (TP) no dejarlo activado.

## VPC Endpoint

Un **VPC Endpoint** permite que una VPC se conecte de forma privada con otros servicios de AWS, sin necesidad de pasar por Internet. Eso significa que una instancia dentro de una subred privada puede, por ejemplo, acceder a S3 o a otros servicios compatibles sin usar Internet Gateway, NAT Gateway ni una VPN.

>[!TIP] Ventaja Principal
>La idea clave es que el tráfico permanece dentro de la red de AWS, lo que mejora la seguridad y simplifica la arquitectura. Así, los datos no salen a Internet pública, aunque el recurso esté consumiendo un servicio externo a la propia VPC.

Existen dos tipos. Un **Interface Endpoint** crea una interfaz de red con IP privada dentro de la VPC, y esa IP privada pasa a ser el punto de entrada al servicio. Se usa para conectarse de forma privada a muchos servicios de AWS o a servicios publicados mediante AWS PrivateLink, incluso entre proveedor y consumidor de servicios.

En cambio, un **Gateway Endpoint** no crea una IP privada ni una interfaz de red, sino que se agrega como destino en la tabla de ruteo de la VPC. Es más simple, pero solo sirve para algunos servicios específicos de AWS, principalmente S3 y DynamoDB.

## ACL de Red (NACL)

Las **NACLs** son listas de control de acceso, es decir maneras de agregar una capa de seguridad a nuestra subred. Si se define una regla, se aplica a todas las instancias dentro de la subred. Por defecto, prohíbe todo, y son stateless, por lo que debo definir reglas para inbound (lo que entra) y outbound (lo que sale). Están basados en puertos IP y TCP/UDP. 

Además, los NACLs permiten definir reglas tanto de permitir como de denegar, algo útil cuando queremos bloquear tráfico específico de manera explícita. Al final de la evaluación siempre existe una regla implícita que niega todo lo que no haya sido permitido antes.

## Security Groups

Los **grupos de seguridad** son una capa de seguridad a nivel de instancia o recurso, como una EC2 o una base de datos. Son stateful, así que si permitimos una conexión de entrada, la respuesta de salida se habilita automáticamente. Solo permiten definir reglas de permiso, no de denegación explícita, y todo lo que no esté permitido queda bloqueado por defecto. En la práctica, sirven para controlar con precisión qué tráfico puede llegar a cada recurso dentro de la VPC.

Podemos entonces establecer la siguiente comparación entre security groups y los NACLs:

| **Grupos de seguridad**                                | **ACL de red**                                                                             |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| • Seguridad a nivel de instancia                       | • Seguridad a nivel de subred                                                              |
| • PERMITIR solo reglas                                 | • Reglas de PERMITIR y DENEGAR                                                             |
| • Stateful                                             | • Stateless                                                                                |
| • Evaluar todas las reglas                             | • Evaluación secuencial de reglas                                                          |
| • Ámbito: instancia/grupo de instancias                | • Alcance: todos los recursos de AWS de la subred                                          |
| • Caso de uso: permitir una lista de fuentes conocidas | • Caso de uso: denegar explícitamente fuentes específicas, listas negras                   |
| • Caso de uso: grupo seguro de instancias              | • Caso de uso: denegación explícita del tráfico entre entornos, producto del desarrollador |
