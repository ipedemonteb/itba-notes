## Conceptos

Vamos a comenzar con algunos conceptos que serán útiles para el desarrollo de la materia. En primer lugar, debemos recordar todo lo que estudiamos en [[11. Transformers|transformers]]. Luego, podemos definir:
- **Generative Artificial Intelligence**: Uso de modelos de AI para crear contenido nuevo original (texto, imágenes, video, audio). Por lo general, es en respuesta a un “prompt”.
- **Prompt Engineering**: Proceso por el que se guía el modelo de GenAI para generar los resultados deseados. Se realiza a través de “instrucciones” o “indicaciones”.
- **Natural Language Processing**: Comprender, interpretar y generar texto y habla en lenguaje natural. Ej: “transduction tasks” (traducción automática, sumarización, transcripción), análisis de sentimientos, la generación de texto y la comprensión del lenguaje hablado.

Teniendo esto en cuenta, podemos definir como **Large Language Models** a los modelos de lenguaje entrenados con grandes cantidades de datos textuales (corpus) para comprender y generar texto en lenguaje natural. Ej: GPT, BERT, Llama, Claude, Gemini, Mistral.

Un **Coding Agent** es un agente capaz de interpretar el código y ejecutar acciones por línea de comando sobre el repositorio, según el contexto dado en el prompt o .md. Está basado en tools, skills y MCPs, y tiene mayor autonomía en el entorno. Ej: Claude Code, Codex CLI.

## Definición

Como sabemos, un **Transformer** es una red neuronal utilizada para transformar una secuencia en otra basada en un mecanismo de atención, que surge de un paper llamado ["Attention Is All You Need"](https://proceedings.neurips.cc/paper_files/paper/2017/file/3f5ee243547dee91fbd053c1c4a845aa-Paper.pdf). Si bien en SIA vimos un caso de traducción, el campo de aplicación de estas redes es mucho más amplio.
- Machine Translation
- Text Classification
- Speech Recognition
- Question Answering
- Image Generation
- Text Generation
- Forecasting
- Summarization
- Etc.

La arquitectura consta de un stack de encoders y decoders, con una cantidad $n$ de ellos que se puede variar según el estudio. Tienen una capa de self-attention y luego un MLP, que se conectan sucesivamente como se ve a continuación. El decoder tiene otra capa extra que se conoce como **Encoder-Decoder Attention** o **Cross Attention**, que permite la conexión con la parte del encoder para conocer los tokens pasados.
![[Pasted image 20260809194626.png|center|438]]

Hasta este punto habíamos llegado en SIA, pero en realidad el proceso es más complejo. La layer de self-attention que habíamos visto previamente es en realidad de **multihead attention**, lo que quiere decir que permite enfocarse en distintos puntos de la secuencia al mismo tiempo. En el decoder se agrega una máscara, porque recordemos que el encoder puede ver tokens "tanto adelante como hacia atrás", pero el decoder no puede ver el futuro. Entonces, se enmascara todos los siguientes tokens que podrían venir después para poder realizar una inferencia. 

Otro componente que se agrega es una capa de **Add & Norm** sobre todas las layers. Por un lado, la parte de **Add** contiene conexiones residuales (o _skip connections_) que toman la entrada previa a la capa y se la suman a la salida de esta, lo cual sirve para mitigar el problema de _vanishing gradient_ (que los gradientes se vuelvan tan pequeños durante el entrenamiento que los pesos no cambien). Por otro lado, la parte de **Norm** (_Layer Normalization_) toma ese resultado y normaliza los valores para que tengan una media de $0$ y una varianza de $1$ dentro de cada vector de características; esto estabiliza el flujo de datos y las activaciones, evitando que los valores explosionen o se descalibren a medida que la red se hace más profunda, permitiendo un entrenamiento más rápido.
![[Pasted image 20260809195504.png|center|468]]

## Encoder

La cadena se divide en tokens que luego son representados en vectores de números reales de dimensión 512 (según el paper). A esto se lo llama **embedding**. El primer encoder recibe como input el embedding. Brinda la capacidad semántica para representar la palabra y convertirla en un vector de números con el que luego podemos hacer cuentas. 
![[Pasted image 20260809195605.png|center|414]]

Ahora, necesitamos otorgar un sentido de orden a los tokens. Para esto, utilizamos **positional encoding**. A cada embedding se le agrega un vector p de posición que sigue un patrón que el modelo aprende para determinar la distancia entre tokens.
![[Pasted image 20260809195641.png|center|525]]

Este vector de posiciones se calcula (en el paper) en base a senos y cosenos.
$$
\begin{aligned}
PE(\text{pos}, 2i) &= \text{sen}(\text{pos} / 10000^{2i/d}) \\[2ex]
PE(\text{pos}, 2i+1) &= \cos(\text{pos} / 10000^{2i/d})
\end{aligned}
$$
Donde:
- $\text{pos}$ es la posición del token en la secuencia
- $i$ es el índice del vector de posición
- $d$ es la dimensión de un embedding, la misma del vector de posición $p_i$

Notemos que se utiliza el seno para las posiciones pares y el coseno para las impares. Existen otras formas de realizar este procedimiento.
![[Pasted image 20260809200003.png|center|366]]

Para entender el **mecanismo de atención**, debemos primero entender tres conceptos en el contexto de LLMs:
- **query**: representación del token que se está analizando en ese momento.
- **key**: representa los tokens a los que hay que prestarle atención.
- **value**: Información de los tokens que después se usa para construir el contexto.

Otra forma de verlo es como si se tuviera una base de datos. Lo podemos pensar como “imitar” la obtención de un value a partir de una query basándose en una key de una BD.

El procedimiento del mecanismo es el siguiente. Por cada embedding $x_i$, se calculan 3 vectores llamados query, key y value, multiplicando los embeddings por 3 **matrices de pesos (Attention Weights)** $WQ$, $WK$ y $WV$.
![[Pasted image 20260809200115.png|center|212]]

Luego, se calcula un **score** por cada embedding que determina cuánta atención se le pone al mismo mientras se está procesando otro. Se hace el producto escalar (interno) entre $q$ y el vector $k$ de cada embedding (medida de similitud). Vemos a continuación que para saber cuánta atención prestarle al token, se multiplica el $q_0$ por el $k_0$ y luego el $q_0$ por ahora $k_1$. Todo esto para el primer token. 
![[Pasted image 20260809200257.png|center|328]]

El siguiente paso es dividir los scores por la raíz de la dimensión de vector $k$ ($d_k$), que se conoce como **scaled dot product**. Luego, usando $\text{SoftMax}$ para los scores se obtienen probabilidades ($p_i$).
![[Pasted image 20260809200356.png|center|346]]
$$
\text{SoftMax}(s_0 / \sqrt{d_k}) = p_0 \quad\quad \text{SoftMax}(s_1 / \sqrt{d_k}) = p_1
$$

Como siguiente paso, se multiplica cada vector $v$ por lo obtenido en la función de $\text{SoftMax}$. Posteriormente, se suman los vectores ponderados $v’$ obteniendo el output de la capa de Self-Attention para cada token (en este ejemplo, para el primero).
![[Pasted image 20260809200626.png|center|487]]

En la práctica, esto se realiza de forma matricial por eficiencia, no vectorialmente como lo vimos acá. Podemos resumir la cuenta para obtener la matriz de atención como:
$$
\text{Attention}(K, Q, V) = \text{SoftMax}\left(\frac{QK'}{\sqrt{d_k}}\right) V = Z
$$

## Decoder

En la fase de decoding, el output debe depender únicamente de outputs previos, no futuros. Entonces, como ya vimos, ahora vamos a tener una **máscara de self-attention**. La ecuación que vimos antes se reemplaza por lo siguiente:
$$
\text{MaskedAttention}(K, Q, V) = \text{SoftMax}\left(\frac{QK' + \text{Mask}}{\sqrt{d_k}}\right) V = Z
$$
Donde $M$ es una matriz triangular inferior con $0$ y $-\text{inf}$. Esto es así porque luego, cuando aplicamos $\text{SoftMax}$ el resultado será cero.
![[Pasted image 20260809201445.png|center|465]]

Una vez que los tokens atraviesan todo el proceso de encoding y decoding, vamos a obtener nuestro output como una salida numérica. Entonces, ¿cómo hacemos ahora para pasar de número a texto así como antes pasamos de texto  embedding? 

Antes, debemos ver que la salida del decoder es autoregresiva. Esto significa que el modelo reutiliza secuencialmente cada token que genera como parte de la entrada para predecir el siguiente. Podemos observar este proceso en el siguiente [enlace](https://jalammar.github.io/images/t/transformer_decoding_2.gif). Básicamente, luego de obtener el primer token (supongamos "I" o "yo") y el siguiente en el output (supongamos "am"), la nueva entrada del decoder será la combinación de ambos (es decir, "I am"). Vemos cómo la red se va autoalimentando progresivamente con su propia salida.

Para poder hacer la traducción de valor numérico a texto, se agrega una proyección sobre una **capa lineal**, que es una red fully-connected que proyecta el output del último decoder en un vector más grande llamado **logits**. Este vector asigna un puntaje a cada uno de los tokens que luego se pasa a probabilidades mediante una función de $\text{SoftMax}$. Entonces, el output es una distribución de probabilidad sobre las posibles clases de salida (palabras).
$$\sigma(\vec{z})_i = \frac{e^{z_i}}{\sum_{j=1}^{K} e^{z_j}}$$
![[Pasted image 20260809201818.png|center|272]]

En este caso, se utiliza la proyección de la función lineal para evaluar todas las palabras del diccionario en uso, ya que estamos frente a un ejemplo de traducción y no de predicción, y luego se obtiene la probabilidad para cada palabra. Pero vamos a ver más adelante otras arquitecturas para diferentes casos de uso de estos modelos.

## Entrenamiento

Supongamos que se tiene un vocabulario de salida $v = (\text{a}, \text{am}, \text{i}, \text{thanks}, \text{student}, \text{<eof>})$ y se desea traducir "gracias" a "thanks". El objetivo de la red es maximizar la probabilidad de la palabra que realmente es y minimizar las de todo el resto. 
![[Pasted image 20260809202103.png|center|518]]

Los pesos se inicializan de forma aleatoria, entonces el modelo sin entrenar devuelve una distribución de probabilidades con valores arbitrarios para cada token. Se pueden comparar las probabilidades y por backpropagation nos vamos a ir acercando al output deseado.

Todo este proceso es muy costoso, ya que como podemos ver en el paper donde se buscaba traducir de inglés a alemán, se tardó tres días y medio con 8 GPUs para poder realizarlo. Son modelos muy grandes y complejos.

## Tipos

La arquitectura de Transformers que vimos hasta ahora se conoce como **Encoder-Decoder**, pero podemos hacer variaciones para obtener nuevos tipos de ellos. Otra opción es tomar un **Decoder-Only Transformer**, en el cual se elimina por completo toda la parte de encoding (como es el caso de GPT - Generative Pretrained Transformer).
![[Pasted image 20260809202417.png|center|459]]

También podríamos eliminar por completo el decoder y adoptar un **Encoder-Only Transformer**, donde el output será un embedding. Un ejemplo es Bert (Bidirectional Encoder Representations from Transformer), que procesa el texto basándose en el contexto previo y el futuro.
![[Pasted image 20260809202506.png|center|446]]
