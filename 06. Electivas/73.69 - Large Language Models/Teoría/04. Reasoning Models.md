## Definición

Los **Reasoning Models** son aquellos modelos que generan tokens adicionales para resolver un problema. Dichos tokens adicionales se corresponden con la generación de pasos intermedios (verificación, planeamiento, etc.) que ayudan a resolver problemas de mayor complejidad. Es otro tipo de Fine-Tuning que se le hace a los modelos. 
![[Pasted image 20260826191004.png|center|center|446]]
>[!INFO] Detalle
>No es la chain-of-thought lo que se muestra al usuario, sino que se mantiene oculta porque es la lógica de negocios propia del modelo y de la empresa que lo desarrolló.

Lo que tiene de particular el razonamiento es que puede aparecer implementado desde el punto de vista del entrenamiento o desde el punto de vista de la inferencia. El **tiempo de inferencia** es el lapso que tarda un modelo en procesar un dato de entrada y generar un resultado o predicción.

En el caso más simple de este último, en lugar de pedir la resolución directa del problema, se le establecen una serie de pasos para llegar a ella, lo que se conoce como **Chain-of-Thought Prompting**.
![[Pasted image 20260829120014.png|center|457]]

Entonces, el modelo cuando tiene que resolver otro problema lo hace siguiendo esa serie de pasos. Esta capacidad del modelo se conoce como **Few-Shot Learning**. A un modelo que fue entrenado más para la parte de lenguaje, se le da algunos ejemplos de una tarea y en base a ellos, aprende a resolver casos similares. 

Desde el entrenamiento, se puede aplicar **Reinforcement Learning from Verifiable Rewards (RLVR)**, que es una variante de RLHF. En lugar de obtener una recompensa de otro modelo, se obtiene una recompensa verificable. Por ejemplo, resuelve un problema matemático para el cuál tiene la respuesta, ya que puede verificar que su resultado sea correcto. Además, se le otorga otra recompensa si el formateo es correcto. 
![[Pasted image 20260829121245.png|center|329]]

## Inference Time Scaling

**Inference Time Scaling** es un paradigma en Deep Learning donde se incrementa la cantidad de cómputo y tiempo dedicada durante la generación de la respuesta para mejorar la precisión y calidad del modelo, en lugar de depender únicamente de hacerlo más grande durante el entrenamiento. Sebastian Raschka, dice: "La idea es sencilla. Si estamos dispuestos a gastar un poco más de cómputo y más tiempo durante la inferencia (cuando usamos el modelo para generar texto), podemos lograr que el modelo produzca mejores respuestas".

La técnica de CoT Prompting sirve cuando la escala del modelo aumenta, como podemos ver a continuación. En las siguientes imágenes, se pueden comparar una técnica de prompting estándar con la CoT y la aplicación de aprendizaje supervisado con el dataset.
![[Pasted image 20260829122408.png|center|633]]

Vemos que recién a partir de cierta escala, CoT comienza a ser beneficioso. El paper que lo propuso habla también de despertar cierta capacidad en el modelo que ya existía.

Otra estrategia utilizada se conoce como **Self-Consistency** o **Sampling** y consiste en samplear distintas respuestas del modelo y analizar cuál es la más consistente. Notemos que se están generando varias respuestas para la misma entrada, por lo que no sería recomendado utilizarlo en problemas que tengan soluciones muy cortas, con dominio muy acotado o que se puedan encontrar en todo internet.  En cambio, sí es una buena idea para dominios donde importa que la respuesta sea la correcta, como es el caso del ámbito médico. 
![[Pasted image 20260829122724.png|center|584]]

Una tercera estrategia es el **Self-Refine**, donde modelo genera una respuesta y recibe feedback del mismo u otro modelo para así juntar el diálogo con el feedback y refinar la respuesta.
![[Pasted image 20260829123246.png|center|521]]

Por último, **Agentic Tool Use (Model Scaffolding)** es una estrategia que consiste en darle acceso al modelo a un montón de tools durante el momento de inferencia para resolver ciertas partes del problema de forma más robusta que si lo tuviera que hacer por sí mismo. Un ejemplo sería ejecutar un script para calcular una operación matemática.
![[Pasted image 20260829123450.png|305]]

## Training Time

Como sabemos, tenemos técnicas como RLHF para lograr alinear nuestro modelo, y así acotar ciertas respuesta que no queremos que otorgue a los usuarios, usando un mecanismo basado en recompensas. Esta estrategia es muy costosa, porque recordemos que teníamos el propio LLM, el Reward Model (suele ser un Transformer que se debe tener en memoria), el advantage que es la diferencia entre lo que dice este último modelo y lo que estima otro más (también en memoria), y el modelo original para calcular la diferencia KL. Vemos que los requerimientos de cómputo son altísimos.
![[Pasted image 20260829124718.png|center|417]]

Si ahora introducimos la técnica de **Reinforcement Learning from Verifiable Rewards (RLVR)** que definimos previamente, notemos que logramos eliminar dos de los modelos anteriores y así bajamos nuestra necesidad de cómputo. No necesitamos un modelo de recompensas porque únicamente verificamos que la respuesta esté bien o mal. Además, en lugar de tener un modelo crítico, se utiliza Group Relative Policy Optimization (GRPO), que lo que hace es intentar armar un baseline, que se calcula a partir de un promedio de las recompensas obtenidas.
![[Pasted image 20260829124804.png|center|456]]

Con esto, se observó un importante aumento en la accuracy de los modelos en problemas de matemática:
![[Pasted image 20260829125227.png|center|452]]

Además, se observó un fenómeno curioso con las apariciones de palabras de reflexión durante los procesos de entrenamiento, como se puede ver en el primer gráfico, y particularmente el caso de la palabra "wait", que podría indicar una auto corrección del modelo.

La accuracy de estos modelos en respuestas para problemas complejos se correlaciona de manera muy fuerte con la longitud de las respuestas. El modelo en el esquema de Reinforcement Learning empieza a generar secuencias cada vez más largas para mejorar esta métrica.

## Problemas

Pensemos ahora, ¿qué problemas podría traer entrenar "razonamiento" de esta forma? Notemos que no nos estamos fijando en nada de lo que pasa en el medio, solamente vemos si está bien o mal. Un posible problema sería tomar caminos demasiado largos para hallar la solución, pero lo importante, es que no existe un control sobre cómo se forma esa cadena de pensamientos, lo que puede traer problemas de seguridad. 
![[Pasted image 20260829130317.png|center|502]]

Vemos en la imagen anterior que se tiene un modelo base, se le aplica Reinforcement Learning y se obtiene el modelo de razonamiento. El proceso es en realidad mucho más largo y con muchas más rondas, donde podemos tomar como ejemplo el siguiente pipeline:
![[Pasted image 20260829130534.png|center|557]]

Los componentes que podemos observar en el esquema anterior son:
- **Modelo base**: Corpus, Self-Supervised Learning, Scaling Laws.
- **Asistente**: Supervised Fine Tuning.
- **Seguridad**: RL or SFT (principalmente RL) como estrategias de fine tuning (RLHF, DPO). Generalmente todas las técnicas se suelen aplicar post modelo base.  
- **Razonamiento**: RL como estrategia de fine tuning y prompting como estrategia de test-time inference.
