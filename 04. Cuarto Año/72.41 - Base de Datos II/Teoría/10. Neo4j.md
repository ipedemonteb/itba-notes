## Introducción

**Neo4j** es un software libre de base de datos orientada a grafos, implementada en Java. Los desarrolladores la describen como un motor de persistencia embebido, basado en disco, completamente transaccional, que almacena datos estructurados en grafos en lugar de en tablas. Vamos a ver que para esta BD, la clasificación dentro del teorema CAP va a ser más complejo que en otros casos anteriores.

Esta base de datos está enfocada también en la extracción de **valor de la información** (es el concepto perfecto en el que se engloban las cuatro famosas V de los grandes datos: volumen, velocidad, variedad y veracidad), lo que es muy importante para el enfoque de Big Data. No le importa tanto el volumen como a Cassandra pero sí encontrar las relaciones entre todos los datos.

---
## Características

Neo4j usa **grafos** para representar datos y las relaciones entre ellos. Un grafo se define como cualquier representación gráfica formada por vértices y aristas. Dentro de estas representaciones gráficas, tenemos varios tipos de grafos:
- **Grafos no dirigidos**: los nodos y las relaciones son intercambiables, su relación se puede interpretar en cualquier sentido. Las relaciones de amistad en la red social Facebook, por ejemplo, son de este tipo.
- **Grafos dirigidos**: los nodos y la relaciones no son bidireccionales por defecto. Las relaciones en Twitter son de este tipo. Un usuario puede seguir a determinados perfiles en esta red social sin que ellos le sigan a él.
- **Grafos con peso**: en este tipo de grafos las relaciones entre nodos tienen algún tipo de valoración numérica. Eso permite luego hacer operaciones.
- **Grafos con etiquetas**: estos gratos llevan incorporadas etiquetas que pueden definir los distintos vértices y también las relaciones entre ellos. En facebook podríamos tener nodos definidos por términos como 'amigo' o 'compañero de trabajo' y la relaciones como 'amigo de' o 'socio de'.
- **Grafos de propiedad**: es un grafo con peso, con etiquetas y donde se puede asignar propiedades tanto a nodos como relaciones (por ejemplo, cuestiones como nombre, edad, país de residencia, nacimiento). Es el más complejo.

Neo4j utiliza grafos de propiedad para extraer valor añadido de los datos de cualquier empresa con gran rendimiento empresa con gran rendimiento de una forma ágil, flexible y escalable. 

Las bases de datos orientadas a grafos como Neo4j tienen mejor rendimiento que las relacionales (SQL) y las no relacionales (NoSQL). La clave es que, aunque las consultas de datos aumenten exponencialmente, el rendimiento de Neo4j no desciende, frente a lo que sí sucede con las BD relacionales como MySQL. Las BDOG responden a las consultas actualizando el nodo y la relaciones de esa búsqueda y no todo el grafo completo. Eso optimiza mucho el proceso.

>[!INFO] Capacidad Máxima
>La agilidad es, como dijimos, una de sus principales ventajas. Si nosotros quisiéramos llevar al límite sus capacidades, tendríamos que superar un volumen total de 34.000 millones de nodos (datos), 34.000 millones de relaciones entre esos datos, 68.000 millones de propiedades y 32.000 tipos de relaciones.

Cuando los desarrolladores de una empresa trabajan con grandes datos, buscan flexibilidad y escalabilidad. Las bases de datos orientadas a grafos aportan mucho en este sentido porque cuando aumentan las necesidades, las posibilidades de añadir más nodos y relaciones a un grafo ya existente son enormes.

>[!TIP] Casos de Uso
>Las bases de datos de grafos son perfectas para datos no estructurados, en muchos sentidos incluso más que las bases de datos de documentos. Neo4j no solo es sin tipos ni esquema, sino que no impone restricciones sobre cómo se relacionan los datos. 

Las distribuciones de Neo4j proporcionan varias herramientas para búsquedas rápidas con Lucene, el lenguaje de consultas **Cypher** y la interfaz REST. Más allá de la facilidad de uso, Neo4j es rápido. A diferencia de las operaciones de join en bases de datos relacionales o de las operaciones de map-reduce en otras bases, los recorridos de grafos son de tiempo constante. Los datos relacionados están a un solo paso de nodo, en lugar de unir valores en bloque y filtrar los resultados deseados, que es como operan la mayoría de las bases de datos que hemos visto. No importa cuán grande se vuelva el grafo; moverse del nodo A al nodo B siempre es un paso si comparten una relación. Por último, la edición Enterprise permite sitios de alta disponibilidad y alto tráfico de lectura mediante Neo4j HA.

Neo4j tiene algunas desventajas. Encontramos que su elección de nomenclatura (nodo en lugar de vértice y relación en lugar de arista) añade complejidad a la hora de comunicarse. Aunque HA es excelente para la replicación, sólo puede replicar un grafo completo a otros servidores. Actualmente no puede fragmentar subgrafos (sharding), lo que aún impone un límite al tamaño del grafo (aunque, siendo justos, ese límite se mide en decenas de miles de millones). Por último, si buscas una licencia de código abierto amigable para negocios (como MIT), puede que Neo4j no sea para ti. Aunque la edición Community (todo lo que usamos en los dos primeros días) es GPL, probablemente tendrás que comprar una licencia si quieres ejecutar un entorno de producción usando las herramientas Enterprise (que incluyen HA y copias de seguridad).

## Cypher

El principal lenguaje de consultas para Neo4j se llama **Cypher**, y una de sus principales características es que tiene elementos visuales que ayudan a entender el sentido del grafo por ejemplo.
![[Pasted image 20260810090221.png|center|339]]
```cypher
(a)-[:LIKES]->(b)
```

Ahora, podemos comenzar con el modelado de nodos. Tomemos el siguiente caso. 
```cypher
MATCH (node:Label) RETURN node.property

MATCH (node1:Label1)-->(node2:Label2)
WHERE node1.propertyA = {value}
RETURN node2.propertyA, node2.propertyB
````

La primera sentencia chequea la igualdad de dos etiquetas y retorna la propiedad del nodo:
- **`MATCH`**: Busca en el grafo todos los nodos que tengan la etiqueta `Label`.
- **`(node:Label)`**: Define un patrón donde `node` es una variable que representa un nodo, y `Label` es el tipo o clase del nodo.
- **`RETURN node.property`**: Devuelve el valor de una propiedad específica del nodo (por ejemplo, `node.name` o `node.age`).

La segunda sentencia busca un patrón de relación dirigida, es decir nodos `Label1` conectados a nodos `Label2`.

Veamos ahora el siguiente caso:
```cypher
MATCH (n1:Label1)-[rel:TYPE]->(n2:Label2)
WHERE rel.property > {value}
RETURN rel.property, type(rel)
```
Ahora, se está filtrando aún más en la relación dirigida, buscando por un nombre en la relación. Luego se aplica un filtro, para que el valor `property` sea mayor a un valor particular.

Tomemos otro:
```cypher
MATCH (you:Person {name:"You"})
FOREACH (name in ["Johan","Rajesh","Anna","Julia","Andrew"] |
  CREATE (you)-[:FRIEND]->(:Person {name:name}))
```
En este caso, se busca en el grafo un nodo de tipo `Person` cuyo atributo name sea `"You"`.  Luego, se itera sobre una lista de valores (en este caso, nombres de personas). Por cada nombre de la lista se crea un nuevo nodo de tipo `Person` con una propiedad `name` igual a ese valor y se crea una relación dirigida `:FRIEND` que va desde el nodo you hacia el nuevo nodo `Person`.

Supongamos ahora que tenemos el siguiente grafo, y queremos encontrar a alguien que nos ayude a aprender Neo4j. Vemos que cada tipo de entidad tiene un color diferente.
![[Pasted image 20260810090412.png|center|328]]

La solución en código es la siguiente:
```cypher
MATCH (you {name:"You"})
MATCH (expert)-[:WORKED_WITH]->(db:Database {name:"Neo4j"})
MATCH path = shortestPath( (you)-[:FRIEND*..5]-(expert) )
RETURN db,expert,path
```

El segundo `MATCH` busca nodos `expert` que tengan una relación `WORKED_WITH` con un nodo `db` de tipo `Database` cuyo nombre sea `"Neo4j"`. El tercero usa la función `shortestPath()` para encontrar el camino más corto de amistad entre nosotros (`you`) y el experto (`expert`):
- **`[:FRIEND*..5]`**: Significa "a través de relaciones `FRIEND` de longitud entre 1 y 5".
- **El doble guión `-(expert)`**: Permite que las relaciones sean en cualquier dirección (vos $\rightarrow$ amigo $\rightarrow$ amigo $\rightarrow$ experto, etc.).
    
Para el `MATCH`, tenemos tres situaciones posibles:
- **Objeto con nombre:** Busca un nodo específico (tipo `Person`, con propiedad `name="Ana"`).
```cypher
    MATCH (p:Person {name:"Ana"})
```
- **Objeto anónimo:** Busca cualquier nodo del tipo `Person`, pero no lo guarda en una variable. Sirve si solo nos importa su existencia, no su contenido.
```cypher
    MATCH (:Person)
```
- **Variable:** Busca nodos de tipo `Person` y los guarda en `p` para poder usarlos luego (en `WHERE`, `RETURN`, etc.).
```cypher
    MATCH (p:Person)
```

Veamos el siguiente caso:
```cypher
MATCH (:Person { name:"Dan" }) -[:LOVES]-> ( whom ) RETURN whom
```
- **`:Person`**: Label (Etiqueta).
- **`{ name:"Dan" }`**: Property (Propiedad).
- **`whom`**: Variable.

Vemos que el `whom` es una variable, porque queremos saber a quién ama Dan. El hecho de que sea una variable hace que se deba instanciar.

Supongamos que queremos borrar la relación entre dos nodos. Entonces, usamos:
```cypher
MATCH ()-[r:reported_on]->() DELETE r
```
Si queremos empezar de cero, borrando todos los nodos y los ejes, se debería ejecutar:
```cypher
MATCH (n) OPTIONAL MATCH (n)-[r]-() DELETE n, r
```
O sino:
```cypher
MATCH (n) DETACH DELETE n;
```

Esto puede llegar a demorar mucho si son grafos muy grandes. Otra opción es borrar el directorio donde está la base de datos, que puede ser por ejemplo el directorio: `C:\Users\<username>\Documents\Neo4j\default.graphdb`.

Es importante notar que si creamos un nodo y una relación, todos los siguientes nodos creados **NO** van a tener esta misma relación, se debería establecer a mano.

## Restricciones, Índices y Esquemas

En Neo4j, la sintaxis para estas funcionalidades es muy similar a Postgres. Para crear y eliminar un índice:
```cypher
// Para crear un índice sobre el atributo name de todos los nodos de tipo Wine
CREATE INDEX FOR (w:Wine) ON (w.name);

:schema // Para ver los índices y las restricciones (constraints)

// Para eliminar el índice
DROP INDEX index_name [IF EXISTS]
````

Para crear y eliminar restricciones, veamos el siguiente caso. Si creo esta restricción:
```cypher
CREATE CONSTRAINT FOR (p:Person) REQUIRE p.name IS UNIQUE;
```
E intento crear un nodo duplicado:
```cypher
CREATE (p:Person {name: "Tom"});
```
Devuelve error: `Neo.ClientError.Schema.ConstraintValidationFailed: Node(40) already exists with label 'Person' and property 'name' = 'Tom'`. No voy a poder tener dos nodos con el mismo nombre.

Si queremos borrar la restricción:
```cypher
:schema // Miramos el nombre de la restricción que queremos borrar
DROP CONSTRAINT constraint_df66ae8
```

Neo4j no permite aplicar esquemas rígidos como lo hacen las bases de datos relacionales, pero sí permite aportar cierta estructura a los nodos de los grafos creando índices y restricciones para etiquetas específicas. Para acceder al esquema, tenemos que ejecutar la siguiente sentencia:
```cypher
:schema
```

## Propiedades

Neo4j es compatible con ACID con almacenamiento y procesamiento de grafos nativos. Además es “small & big”, es decir que es lo suficientemente pequeño como para incrustarse en casi cualquier aplicación, y puede ejecutarse en grandes clústeres de servidores usando replicación maestro-esclavo y almacenar decenas de miles de millones de nodos y la misma cantidad de relaciones. En otras palabras, Neo4j puede manejar prácticamente cualquier tamaño de problema que le plantees.

## Acceso Por REST

Neo4j nos provee una API para poder acceder y utilizar la base de datos. Podemos ejecutar el siguiente comando desde la terminal:
```bash
$ curl http://localhost:7474/db/data/
````

```json
{
  "errors" : [ {
    "code" : "Neo.ClientError.Security.Unauthorized",
    "message" : "No authentication header supplied."
  } ]
}
```

Modificar el archivo `/conf/neo4j.conf`:
```Properties
# dbms.security.auth_enabled=false
```

Si queremos crear un nodo:
```Bash
$ curl -i -XPOST http://localhost:7474/db/data/node -H "Content-Type: application/json" -d '{ "name": "P.G. Wodehouse", "genre": "British Humour" }'
```

Observar el resultado del `curl`, para determinar el `"id"` que se le asignó a este nodo.

Esto no lo vamos a usar mucho.

## Disponibilidad y Replicación

Neo4j funciona con un sistema de replicación de un nodo primario y varios secundarios (master y slaves). Delega la coordinación a un mecanismo externo, es decir que quien va a controlar quién es master y quién slave es el zookeeper, que es una herramienta externa. Si el master se cae, este elige entre los slaves cuál es el más apropiado para ser el nuevo master.
![[Pasted image 20260810091620.png|center|420]]

En cuanto al teorema CAP, tenemos distintas situaciones posibles:
- En general, si se trabaja de manera distribuida con particiones, Neo4j es CP. 
- Si se trabaja con una única instancia, es decir con un único nodo, es CA, se comporta transaccional como una base de datos SQL.
- Si se trabaja en un contexto de alta disponibilidad, configurando el modo HA (high availability), entonces se encuentra en el vértice de AP.
