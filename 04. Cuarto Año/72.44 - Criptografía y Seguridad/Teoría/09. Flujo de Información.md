## Confinamiento

Una política de seguridad dice: un empleado no puede ver los sueldos de otros empleados. El control de acceso no impide copiar la información a otro lugar. Esto es un problema de flujo de información porque no queremos controlar el acceso a ella sino cómo entendemos la forma en la que la información fluye. 

El control de acceso limita acceso a operaciones sobre objetos que contiene información, pero la información no es estática, sino que es actualizada y puede copiarse. Las políticas, por lo general restringen el flujo de información y no el acceso a objetos. No es lo mismo evitar que un empleado sepa el sueldo de otro que evitar que un empleado acceda a la base de datos de sueldos. Los controles de acceso sirven, pero por lo general son mecanismos abiertos. Deben ser complementados.

Si se pudiera confinar el flujo de información dentro de un ambiente controlado, no habría riesgos de confidencialidad o integridad. El modelo Bell-Lapadula define un modelo de seguridad para asegurar el confinamiento.

El **problema del confinamiento (de acceso)** se refiere a la dificultad de asegurar que un programa o proceso (denominado "sujeto") no transmita información a otra entidad (denominada "objeto") a la que no está autorizado a acceder, ya sea de manera directa o indirecta.

El modelo ideal de confinamiento se conoce como de **aislación total**. Los requisitos que tienen son:
- Un proceso no puede comunicarse con otros procesos.
- Un proceso no puede ser observado.
Como consecuencia, el proceso no revela información. Notemos que estos requisitos le quitan utilidad al sistema, ya que no podemos ni conectarlo ni comunicarlo. En la práctica, los procesos usan recursos observables:
- Memoria: Ciclos de CPU
- Espacio en disco 
- Ancho de banda

## Covert Channel

Un **canal encubierto (covert channel)** es un método de comunicación utilizado para transferir información de manera oculta, aprovechando vías no diseñadas para la transmisión de datos. En el contexto de la seguridad de la información, los canales encubiertos son utilizados para evitar los controles de seguridad y transmitir datos sin detección, por lo que representan un gran problema.

Hay distintos tipos de canales encubiertos:
- **Canales de Temporización (Timing Channels)**: Estos canales utilizan la temporización del sistema para transmitir información. La idea es codificar datos en la variación del tiempo entre eventos.
	- Latencia de Red
	- Carga de CPU
	- Tiempos de Respuesta de Aplicaciones
- **Canales de Almacenamiento (Storage Channels)**: Estos canales utilizan el almacenamiento de información en áreas no convencionales o no reguladas del sistema para transmitir datos.
	- Espacio en Archivo: Utilizar bits no utilizados en los archivos (por ejemplo, en el espacio de relleno de un archivo) para almacenar y luego leer información secreta.
	- Atributos de Archivos: Modificar atributos de archivos como la fecha de creación, modificación o acceso. Bits no Usados en Estructuras de Datos.

Un **Ataque de Canal Lateral (Side Channel Attack)** explota las emisiones físicas y temporales de un sistema para extraer información sensible. No se basa en vulnerabilidades clásicas del software o errores de autenticación, sino en la observación de efectos colaterales del hardware durante su funcionamiento. Es especialmente relevante en criptografía, donde un atacante podría medir tiempos de ejecución, consumo de energía, radiación electromagnética o incluso ruido acústico para inferir claves de cifrado u otra información crítica.

Algunos ejemplos de estos ataques son:
- Los atacantes miden el tiempo que toma para ejecutar operaciones criptográficas y utilizan esta información para inferir claves secretas.
- Analizan el consumo de energía de un dispositivo durante las operaciones criptográficas para obtener información secreta.
- Utilizan emisiones de radiación electromagnética para obtener información sobre la operación interna de un dispositivo, incluyendo sus claves secretas.

>[!WARNING] Diferencia
>Un **canal encubierto** se centra en evadir controles de seguridad para transmitir información dentro y fuera de un sistema de manera oculta. Un **ataque de canal lateral** se enfoca en recolectar información sensitiva mediante la observación del comportamiento físico del hardware durante su operación.

Para intentar mitigar estos problemas, existen los controles de flujo:
- Tiempo de compilación (compile-time enforcement): Analiza propagación de información directamente en el código fuente. Es costoso y complejo, y está limitado a componentes muy sensibles.
- Tiempo de ejecución (run-time enforcement): Se aplica control dinámico (sandboxing) y aislación (virtualization). Son los métodos más utilizados.

## Control de Flujo en Tiempo de Compilación

El concepto del **control en tiempo de compilación** se basa en cuantificar la información asociada a cada variable, para evaluar cómo cambia la información asociada en cada sentencia. Se debe comparar el valor inicial y final de cada variable, y los cambios indican transferencia (flujo) de información. Si hay transferencia que no debiera ocurrir, fallar.

Para medir la información, se introdujo el concepto de **entropía**, que permite reducir en un sólo número la cantidad de información que puede circular por un canal. 
>[!TIP] Entropía
>Sea $X$ una variable aleatoria discreta que toma valores $x_1,…, x_n$.
>$$H(X)=-\sum_{i=1}^{n}p(x_i)\log_2 p(x_i)$$
>- El **valor mínimo** será cero cuando la probabilidad de alguno de ambos valores es cero. Entonces $p(x_i)=1$, $p(x_j)=0$ para $j\neq i$. Este es el caso de un canal donde sabemos exactamente lo que se transmite.
>- El **valor máximo** se alcanza cuando todos los valores son iguales, $p(x_i)=1/n$.  Si todas las probabilidades son iguales, entonces tenemos una distribución uniforme, lo que quiere decir que de los n valores, todos son equiprobables.

Intuitivamente, más que medir la cantidad de información que viaja por el canal, mide la cantidad de información que deberíamos conocer para poder explicar completamente el contenido de ese canal. Por esto se dice que mide la incertidumbre a la hora de determinar el valor de una variable.

Para analizar los flujos de información, debemos analizar cómo cambia la entropía. Para esto, se utiliza el concepto de **entropía condicional**, que es similar al de probabilidad condicional.
>[!TIP] Entropía Condicional
>Sea $X$ una VAD que toma valores $x_1,…,x_n$, e $Y$ otra VAD que toma valores $y_1,…,y_m$.
>$$H(X|Y=y)=-\sum_{i=1}^{n}p(x_i|y)\log_2 p(x_i|y)$$
>$$H(X|Y)=\sum_{j=1}^{m}p(y_i)H(X|Y=y_j)$$

Entonces, ahora podemos formalizar la existencia de **flujo de información**. Sea $s$ el estado de un sistema, $t$ el estado del sistema luego de ejecutar comandos $c_1,…, c_n$. Sean $x_s, y_s$ valores de objetos en el estado $s$ y sea $y_t$ valor de $y$ en el estado $t$. Hay flujo de información de $x$ a $y$ si:
- $H(x_s|y_t)<H(x_s|y_s)$, si $y$ existe en el estado $s$.
- $H(x_s|y_t)<H(x_s)$, si $y$ no existe en el estado $s$.

Existen técnicas formales de análisis de flujo de información en programas. En programas, por ejemplo imperativos, el flujo de información existe siempre, e incluso es necesario para el funcionamiento. A veces interesa verificar casos puntuales, como por ejemplo en una variable que tiene una clave criptográfica. 

El **flujo directo** se produce de la siguiente manera. Consideremos el comando $y=x+z$, donde $0\le x\le 7$, con igual probabilidad:
$$Z={p(z=1)=0.5,p(z=2)=0.25, p(z=3)=0.25}$$
Entonces:
$$H(x)=-8\sum(\frac{1}{8} \log_2 (\frac{1}{8}))=3$$
Conociendo $y$ luego del comando $x$ puede tener solo 3 valores $(y-1, y-2, y-3)$. Luego:
$$H(x|y)= –(\frac{1}{2})\log_2(\frac{1}{2})–2(\frac{1}{4})\log_2(\frac{1}{4}) = 1.5$$
Vemos que hay traspaso de información de $x$ a $y$.

Para entender el **flujo indirecto**, tomemos el siguiente caso:
```c
if (x == 0) y = 1 else y = 0
```
Vemos que $x$ e $y$ no aparecen en la misma asignación. Podemos considerar $x$ como ${0,1}$ con $p(x=0)=0.5$. Luego:
- $H(x)=1$
- $H(x | y) =0$
Por lo tanto, hay traspaso de información.

En este tipo de flujo, la información puede fluir también por comportamiento, como en el caso de `while (x = 0) {}`. No existe ninguna asignación, pero consideremos $x$ como ${0,1}$ con $p(x=0) = 0.5$ y definimos $y = 0$ si el programa termina. Entonces:
- $H(x)=1$
- $H(x | y) =0$
Hay traspaso de información.

Estas técnicas comparten los límites de la verificación formal: No es computable verificar todo programa. Además, cuando hay interactividad los casos explotan en cantidad de forma exponencial. Los ciclos son también un problema.

## Control de Flujo en Tiempo de Ejecución

Para realizar este control, los sistemas **aíslan** procesos de dos maneras:
- Ambiente de ejecución sintético separado del real, y aislado por definición (*virtualización*).
- Control y modificación de las interacciones del sistema con su entorno (*sandboxing*).

Las **máquinas virtuales (VMs)** usan *hipervisores* para emular hardware y gestionar diferentes sistemas operativos en un solo host físico. Los hipervisores pueden ser de tipo: Bare-metal, como KVM, VMware ESXi o Hyper-V, Hosted, como VirtualBox o VMware Workstation. Las VMs tienen su propio kernel, lo que proporciona un fuerte aislamiento entre ellas.

El **sandboxing** se basa en analizar las interacciones de un proceso con su ambiente y las modifica para aislarlo. A diferencia del caso anterior, ahora se comparten muchas cosas, como por ejemplo la memoria y el CPU con el resto de los procesos. 
![[09. Flujo de Información-1782137832948.png|center|398]]

Al nivel sistema operativo:
- **Linux**: los *namespaces* permiten aislar procesos y recursos. Esto permite aislar procesos, usuarios, red, filesystem, y más. Los cgroups controlan y limitan el uso de recursos como CPU, memoria y red para diferentes procesos.
- **Windows**: El User Mode Scheduling es similar a namespaces en Linux. Los Job Objects permiten gestionar grupos de procesos como una unidad. Esto se utiliza para asignar límites de recursos y prioridades a estos grupos.

Los **contenedores** aprovechan tecnologías como namespaces y cgroups en Linux (Docker es un ejemplo popular) para aislar aplicaciones, permitiendo que múltiples contenedores compartan el mismo kernel del SO anfitrión pero manteniendo la separación lógica en términos de red, procesos y sistema de archivos. Windows soporta contenedores nativos que usan características de windows o Hyper-V.

## Malware

**Malicious Software (Malware)** es el término con el que se identifica a cualquier programa diseñado para causar daño, atravesar un control o extraer información. Un ataque usualmente usa múltiples tipos de malware para ejecutar cada parte del ciclo del ataque. El malware suele aprovechar vulnerabilidades del software para lograr su cometido.

Un **Virus/Worm** posee la característica de infectar una máquina y usar los medios disponibles para propagarse entre máquinas ocupando recursos. Puede infectar directamente una máquina por medio de una explotación de una vulnerabilidad remota o infectar algún recurso compartido (archivos). 

Un virus tiene dos componentes, uno de replicación y otro de ejecución. En función a este último puede reclasificarse en otros tipos. Worm, se especializa en la infección por medio de la red, propagándose inclusive por email (Melissa 1999). SQL Slammer infectó 75000 computadoras en 10 minutos gracias a las bases de datos SQL expuestas a internet. 

Un **Troyano** es un malware oculto dentro de otro software que parece benigno y de interés para la víctima. Se utiliza para establecer al atacante dentro del equipo infectado. PC-Write (1986), fue uno de los primeros sharewares que ofrecía un editor de texto, y contenía un troyano que borraba todos los archivos de la máquina.

Vemos que hasta ahora no hablamos de qué hace el atacante luego de infiltrarse en el sistema, lo que se conoce como payload, sino que vimos otras características para definir a los malwares que se pueden combinar.

Un **Rootkit** es un software diseñado para ocultar malware dentro de la máquina infectada. Un virus tradicional es un programa ejecutable, que se puede propagar modificando otros ejecutables. Un rootkit va un paso más allá y busca aplicar contramedidas activas para esconderse. Utiliza técnicas de ofuscación, encripción, reescritura y reemplazo de herramientas del sistema para quedar oculto a los administradores y antivirus. Pueden operar a nivel de kernel o de usuario. NTRootkit (1999) fue el primer rootkit para Windows NT, y Stuxnet (2010) utilizó rootkit para recolectar por meses información antes lanzar el ataque que afectó las plantas nucleares de Irán.

Un **Spyware** es un software diseñado para recolectar información del usuario infectado. Se especializa en el ocultamiento de información dentro del activo infectado y usualmente establece alguna forma de covert channel (túnel). Algunas empresas desarrollan este software a pedido de los gobiernos para hacer vigilancia digital o espionaje. Acá ya comenzamos a analizar también los payloads, como dijimos antes.

Un **Ransomware** es un software diseñado para bloquear el acceso de los usuarios a su información, pidiendo dinero para volver a restaurar el acceso. CryptoLocker (2013), enviado vía mail, infectaba a los usuarios al abrir el correo. Se estima que se robaron cerca de U\$D 3M en ese año. Wannacry (2017), aprovechando una vulnerabilidad de Windows conocida fue uno de los primeros ransomwares en distribuirse en la red local. Se estima que la infección fue de más de 200K máquinas, y tuvo un costo de U\$D 4B.

Los **Botnets** consisten en software diseñado para desplegar bots o agentes multiuso que permanecen a la escucha de instrucciones. Las máquinas infectadas se usan para disparar ataques distribuidos, minería de cripto, accesos anónimos, distribuir spam, entre otros usos maliciosos. Srizbi BotNet (2008) se considera la botnet más grande que existió. Se estima que fue responsable por el envío de la mitad del spam mundial (60B mails por días).

El **ciclo de un ataque con malware** es el siguiente:
![[09. Flujo de Información-1782138280065.png|center|581]]
1. **Reconocimiento Inicial**: Se identifica a la víctima y se recopila información. Se explora toda la información interna, responsables, puntos débiles. Se exploran intereses y afinidades de los responsables en las posiciones claves.
2. **Compromiso Inicial**: El malware se “weaponiza” y se empaqueta de forma que pueda ser ejecutado por la víctima. Usando alguna forma de ataque dirigido, se comprometen una o más máquinas. Este proceso puede durar varios días hasta lograr la primera infección.
3. **Establecimiento**: El malware trata de establecer comunicación hacia su comando y control (C&C), asegurarse la persistencia y almacenamiento seguro. Se bajan y componen las nuevas herramientas que se van a utilizar en las etapas posteriores. Esta etapa suele durar minutos después de la infección inicial.
4. **Escalamiento de Privilegios**: El malware trata de elevar los privilegios inicialmente obtenidos. Puede utilizar vulnerabilidades locales o remotas. Este proceso suele durar minutos.
5. **Reconocimiento Interno**: El malware hace análisis de comunicaciones y va mapeando otras posibles máquinas o usuarios de interés. Se prueba comunicación y visibilidad desde las máquinas infectadas. Del descubrimiento se bajan y componen nuevos malwares.
6. **Movimiento Lateral**: El malware realiza explotación remota de vulnerabilidades y busca incrementar la base infectada.
7. **Mantener la Persistencia**: El malware se asegura persistir en las nuevas máquinas infectadas.
8. **Completar la Misión**: Cuando el atacante ya tiene acceso a los datos de interés, va extrayendo la información o la acumula internamente hasta enviarla hacia afuera en horarios con menor monitoreo. En el caso del ransomware, se infectan la mayor cantidad de máquinas posible antes de activar el bloqueo a los datos.

## Ataques

**SQL Injection (SQLi)**: Sucede cuando se inserta código SQL dentro de otro código SQL para alterar su funcionamiento normal y hacer que se ejecute maliciosamente el código invasor en la base de datos. Mediante un ataque de este tipo, el invasor puede obtener datos de acceso restringido o ejecutar comandos en el servidor de bases de datos.

**Cross Site Scripting (XSS)**: Está basado en la explotación de vulnerabilidades del sistema de validación de HTML incrustado. El Cross-Site-Scripting es una vulnerabilidad que aprovecha la falta de mecanismos de filtrado en los campos de entrada y permiten el ingreso y envió de datos sin validación alguna, aceptando el envió de scripts completos, pudiendo generar secuencias de comandos maliciosas que impacten directamente en el sitio o en el equipo de un usuario. Las formas mas comunes de realizar dicha agresión es por medio de correos electrónicos, vínculos falsos o ataques directos a sitios no preparados para este tipo de ataque.

**Cross-Site Request Forgery (CSRF)**: Es un tipo de exploit malicioso de un sitio web en el que comandos no autorizados son transmitidos por un usuario en el cual el sitio web confía. Al contrario que en los ataques XSS, los cuales explotan la confianza que un usuario tiene en un sitio particular, el cross site request forgery explota la confianza que un sitio tiene en un usuario en particular.

**Unrestricted Upload of File with Dangerous Type**: El software permite que el atacante suba o transfiera archivos peligrosos, por ejemplo un archivo que es interpretado y ejecutado como código por el receptor (ejemplo: una imagen que en vez de tener extensión gif tiene extensión .php).

**Information Exposure Through an Error Message**: El software genera mensajes de error que incluyen información sobre entorno, usuarios, o datos asociados. La información sensible puede ser valiosa en sí misma o ser útil para obtener otra.

**Open Redirect - URL Redirection to Untrusted Site)**: Una aplicación web acepta una entrada controlada por el usuario que especifica un link a un sitio externo, y usa ese link para un redireccionamiento.

**Race Condition**: Una condición de carrera describe el error que se produce en programas cuando no han sido diseñados adecuadamente para su ejecución simultánea con otros. Por ejemplo cuando dos procesos están esperando a que el otro realice una acción. Como los dos están esperando, ninguno llega a realizar la acción que el otro espera.

**Buffer Overflow**: El programa copia una cantidad de datos sobre un área que no es lo suficientemente grande para contenerlos, sobreescribiendo otras zonas de memoria. La consecuencia de escribir en una zona de memoria imprevista puede resultar impredecible, pudiendo en algún caso alterar el flujo normal del programa. Los compiladores de c suelen tener actualmente protección contra buffer overflow.

**Path Traversal**: La finalidad de este ataque es ordenar a la aplicación a acceder a un archivo al que no debería poder acceder o no debería ser accesible. Este ataque se basa en la falta de seguridad en el código. También es conocido como el "ataque punto punto barra", escalado de directorios у backtracking.

**Integer Overflow (o Wraparound)**: El software hace un cálculo que produce un integer overflow o wraparound cuando la lógica asume que el valor será mayor que el original (Ejemplo: en una variable `unsigned char`, si sumo 255 + 1 da 0, cuando uno podría esperar que dé 256).

**Allocation of Resources Without Limits or Throttling**: El software reserva un recurso reusable o un grupo de recursos en nombre de un actor sin imponer restricciones sobre cuántos recursos pueden ser reservados.
